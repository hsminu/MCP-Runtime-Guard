# C · Cisco Scanner 남은 작업

2026-10-13 사용자가 Scanner LLM을 **Luna low**로 선택했다. `.env`·공유 템플릿과 설정 문서에 반영했고, 임시 요청 보정 코드의 실제 API 두 건은 성공했다. [현재 모델 설정](c-openai-scanner-setup.md), [none 확장 평가](c-luna-scanner-evaluation.md)를 따른다. 모델 선택은 제품 Scanner·Registry 구현 완료나 API 계약 합의를 뜻하지 않는다.

같은 날 사용자의 후속 구현 지시로 [전체 도구 정의 입력·분석기 호출 부분](c-cisco-metadata-implementation.md)을 제품 소스에 반영하고 23개 테스트를 통과했다. 당시 모델 요청 보정·ScanReport 집계·Registry는 남아 있었다.

후속 "연결해 b scanreport는 연결하지마" 지시로 [Luna low 제품 연결](c-cisco-luna-connection.md)을 구현했다. 현재 62개 오프라인 테스트·정적 검사와 low 실제 API 28건을 확인했다. 공격 16/16 탐지·정상 오탐 1/12다. **현재 작업에서 B ScanReport 연결은 제외하며**, Registry·Guard·실제 MCP 연결도 남아 있다.

이후 사용자가 **LLM 기본·위험 발견 시 경고만 표시**를 결정하고, **검사 실패·미완료도 경고 후 사용 계속**하는 1안을 선택했다. 위험도·실패 상태·고정 오류 코드는 보존하고 이 Scanner 결과만으로 자동 등록 차단·실행 중단하지 않는다. 이전 위험/검사 실패의 PENDING 강제 규칙보다 이 사용자 결정이 우선한다. [결정 범위](../contracts.md#scanner-정책-사용자-결정)를 따른다. 현재는 문서 반영이며 경고 UI·Registry 정책 구현은 남아 있다.

후속 "함께 돌리자" 결정으로 **LLM 기본 + YARA 보조 병행**을 사용한다. 두 분석기에 동일한 전체 정의를 전달하고 위험·실패 경고 정책을 적용한다. 한쪽 실패는 다른 검사를 생략하는 근거가 아니며 완료·실패와 Finding 출처를 따로 보존한다. 병행 실행·집계 코드는 아직 미구현이다.

이후 사용자 요청으로 [실제 MCP metadata 조사](c-real-mcp-metadata-survey.md)를 수행했다. 공개 서버 6종·설정 7개에서 실제 stdio·원격 HTTP `tools/list` 189건을 수집했고 현재 입력 어댑터의 전체 보존을 확인했다. 최대 정의는 8,360바이트, 최대 페이지 result는 259,485바이트다. 이 정의의 LLM/YARA 검사·A 제품 transport·Registry·Guard 연결은 미실행이다.

후속 "너 추천대로 해 다음 설명" 결정으로 **도구당 기본 64KiB·설정 가능**을 확정했다. 전체 Tool JSON의 UTF-8 바이트 수로 계산하고 초과하면 자르지 않으며 `SCAN_METADATA_TOO_LARGE`·검사 미완료 경고 후 사용을 계속한다. [결정 범위](../contracts.md#scanner-입력-크기-사용자-결정)를 따른다. 현재는 문서 반영이며 제품 기본값·설정·경고 연결은 미구현이다.

후속 "ㅇㅇ 그렇게 해 다음 정할거" 결정으로 **목록 페이지당 기본 1MiB·설정 가능**을 확정했다. A transport가 JSON 파싱 전에 받는 도중 제한하고 초과 응답은 수신 중단·목록 수집 미완료 경고로 처리한다. 잘린 목록을 수집 완료로 취급하지 않는다. [응답 메시지 기준과 구현 범위](../contracts.md#mcp-목록-수신-크기-사용자-결정)를 따른다. 현재는 문서 반영이며 A 제품 수신 제한과 C의 초과 응답 검증·UI 연결은 남아 있다.

후속 "그렇게 하자" 결정으로 **서버별 전체 목록 조회당 누적 기본 8MiB·설정 가능**을 확정했다. 같은 조회의 모든 페이지를 합산하고 초과하면 추가 수집을 중단하며 전체 목록 수집 미완료 경고를 남긴다. [누적 기준과 구현 범위](../contracts.md#mcp-목록-누적-수신량-사용자-결정)를 따른다. 현재는 문서 반영이며 제품 계수·설정·수집 중단과 C 검증은 미구현이다. 다음 미확정 항목은 서버별 도구 수 상한이다.

후속 "이런 자잘한 거 다 추천하는 거 적어봐" 요청으로 [운영 설정 일괄 추천안 v1](c-scanner-operating-proposal.md)을 작성했다. 도구 수·페이지 수·깊이·시간·동시성·재시도·취소·경고·캐시·재검사 동작을 모았다. 기존 결정과 현재 구현값을 구분했으며 새 추천값은 미확정이다. 문서 작성 요청을 일괄 승인이나 구현 완료로 기록하지 않는다.

후속 "검증 ㄱㄱ" 요청으로 [운영 추천안 검증](c-scanner-operating-validation.md)을 수행했다. 62개 회귀·정적 검사, 공개 서버 재수집과 실제 정의 144개의 Luna low/YARA 검사, stdio/HTTP 경계 관찰 22개·YARA timeout 실험을 확인했다. 실제 API 144건 모두 HTTP 200·분석 완료, 실험 배치 69.764초다. A 수신 상한·제품 병행 runner·UI·Registry·Guard 인수는 남아 있으며 새 추천값을 자동 확정하지 않았다.

## 어댑터에 반영할 확인된 사항

- `MCP_SCANNER_LLM_REASONING_EFFORT`는 프로젝트 변수다. Scanner 4.8.6 CLI의 기본 설정 로더는 읽지 않는다. C 제품 연결은 설정을 읽고 직접 low를 전달한다.
- C 제품 Luna 요청은 `max_completion_tokens`를 사용하고 temperature를 생략한다. 기존 이름만 교체하는 upstream 경로는 실제 HTTP 400을 재현했다.
- C-CISCO-01: 분석 실패를 완료·safe로 표시하는 정적 검사 경로를 피하고 C가 실행 결과를 직접 집계한다.
- C-CISCO-02: 원문 예외·Finding의 raw_response/evidence·인증정보를 기본 로그/화면으로 전달하지 않는다.
- C-CISCO-03: 루트 schema·annotations·중첩 인자·추가 정의 필드를 보존하는 입력 어댑터를 제품 소스에 반영했다. 설치 SDK의 프롬프트·실제 YARA 규칙을 회귀 검증했다. B 리뷰·지문 계약·실제 MCP/Registry 연결은 남아 있다.
- JSON 객체가 파싱된 것과 필수 결과 스키마가 유효한 것을 구분한다. 필수 필드 누락·잘못된 severity·도구 지문 불일치는 완료로 처리하지 않는다.

관련 불변식은 I6·I7·I9·I10, 등록·검사 인수는 T17·T10이며 원문 비노출은 T19·S04와 연결한다. 실제 tools/call 인수는 I1–I3·I8 및 C6 계수 검증으로 연결한다. 이 목록은 아직 테스트 전체 통과 기록이 아니다.

## 추가 분석기의 순서

현재 사용자 결정은 Luna low LLM을 기본으로, YARA를 보조로 함께 사용하고 위험과 검사 실패·미완료 모두 경고로 표시하면서 사용을 계속하는 것이다. Registry 활성화 절차는 별도로 정한다. 이전 오프라인 필수/LLM 선택 제안을 현재 확정 정책으로 취급하지 않는다.

Readiness·Prompt Defense는 운영 준비·방어 문구를 보는 보조 검사로 후순위에 둔다. 정상 정의에도 HIGH를 반환한 사례가 있어 보안 finding과 같은 활성화 기준을 무조건 적용하지 않는다. Behavioral은 MCP 소스가 있을 때, Vulnerable Package는 의존성 검사가 필요할 때 검토한다. Cisco API·VirusTotal은 별도 키와 외부 호출이 필요하다. Meta는 finding을 제거하는 기능이므로 필수 검사 결과를 완화하는 용도로 기본 활성화하지 않는다. 항목별 범위는 [검사 항목](c-cisco-scan-items.md)을 따른다.

모델 추가 비교는 현재 필수 선행 작업이 아니다. 남은 핵심은 실제 어댑터·MCP 정의 수집·실패 의미·등록과 집행 연결이며, 정확도 우위는 별도 비교 결과가 있을 때만 보고한다.

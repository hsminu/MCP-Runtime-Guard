T21에서 A는 **새 Task**를 모델 대화/프롬프트 사본/제공자 핸들/캐시 키의 유일한 초기화 경로로 제안한다. 이전 Task의 키를 재사용하거나 Task 이름만 바꾸고 보안 등급만 초기화하는 API는 두지 않는다. B의 Task ID는 신뢰 실행 맥락에서 받고 모델 응답 필드는 그 출처가 아니다. 새 Task의 모델 요청에 이전 Task의 합성 표지가 없는지, 캐시 hit/대화 핸들이 격리됐는지는 C의 T21 통합 시험에서 확인해야 한다. 제공자 측 캐시를 Task별로 나눌 수 없다면 비활성화/해당 모드 거부 여부를 E6/E8에서 정한다.

T22에서 A가 요청하는 시작 차단은 **민감 시나리오 시작 전에** 승인 환경 상태를 신뢰 설정에서 읽고, 승인되지 않았거나 확인할 수 없으면 시작을 거부하는 계약이다. 승인 주체, 범위, 갱신/철회, 시작 시점과 Task 진행 중 변경의 의미는 E7에서 B·C·운영 측과 정해야 한다. 단위 대역의 통과, 환경변수 존재, 모델 응답, UI 선택은 승인 증거가 아니다. 시연 입력은 합성 자료로 제한하고 실제 문서·인증정보·전체 인자를 모델 제공자에게 넘기는 시험은 계획하지 않는다.

## lock과 검증 순서

1. A07/A08은 C의 격리 합성 fixture/harness에서 **클라이언트와 서버가 같은 MCP SDK 버전**인 stdio READ·HTTP SEND 왕복, 수명·계수·redirect/retry 조건을 기록한다. 현재 A02의 `pip check`는 이 단계를 대체하지 않는다.
2. A17은 AGT의 판정 전용 연결과 MCP SDK 충돌을 조사한다. C는 Scanner 고정 버전·필수 오프라인 분석기·동일/별도 환경 결정을 실제 설치와 결과 계약으로 제공한다. 각 결과는 [연동 기록](../integration-notes.md)에 버전·방법·성공/실패·한계를 남긴다.
3. E2/E3의 편집 담당과 리뷰어가 정해진 뒤 위 조합만 공통 `pyproject.toml`/lock에 반영한다. B 단독 lock이나 A 로컬 설치 목록을 곧바로 전체 제품 lock으로 복사하지 않는다.
4. A41에서 새 가상환경에 lock으로 설치해 동일 stdio/HTTP 왕복을 재현하고, AGT·Scanner 모드/환경을 명시하며 C CI의 정적·보안 검사 결과를 별도로 기록한다. 실패·미실행은 통과로 표시하지 않는다.

# A · 최신 B 동기화 기록

기준: A `281cbae`, B `3bf414cded1c7262f744dd4f282c0abe93109f4f`.
사용자의 최신화 요청으로 B 이력을 A에 병합했다. 공동 계약에 대한 동의나 C 독립 인수 기록은 아니다.

## 반영 범위

- B `29025e0`의 Guard 접근 검사 추적·동시 상한·취소 정리와 승인 ID·관계·마지막 만료 검사를 반영했다.
  B 소유 소스와 단위 테스트는 B 원본을 사용한다. A Runner의 expected_epoch 전달,
  AGT 대기열·worker 교체, HTTP/stdio와 Qt 한국어 표시를 유지했다.
- B `3bf414c`의 공동 검토 요청·B6·스키마 연결안·인수 문서를 가져왔다.
  B6-01–06, AGT-01–03, SCHEMA-01, ENV-01은 검토 대기이며 동의 표를 채우지 않았다.
- domain·ports는 두 기준에서 동일하다. SQLite·Registry·실제 모델의 제품 연결은 추가하지 않았다.
- 미추적 사용자 QA 보고서와 재현 폴더는 이번 커밋에 포함하지 않는다.

## 실행 환경과 B 검사 설정

ENV-01 합의 전까지 A `pyproject.toml`·`uv.lock`의 실행 조합(jsonschema 4.25.1)을 유지한다.
B `requirements.lock`은 B 코어 검사 조합(jsonschema 4.26.0·mypy·types-jsonschema 포함)으로
원본 보존한다. A 환경에 덮어 설치하지 않는다. Scanner 포함 공통 제품 환경은 미확정이다.

2026-10-14 `chore/integrate-a-b`가 ENV-01 제안으로 두 환경과 검사 설정을 루트 `pyproject.toml`·`uv.lock`으로 합쳤다([A+B 통합](../integration-a-b.md)). 아래 별도 환경·설정과 명령은 당시 기록이다.

B의 Ruff·strict mypy 설정을 별도 검사 설정 `config/b-core/pyproject.toml`에 보존했다.
저장소 루트에서 B 소유 파일을 명시해서 사용한다. A 앱 전체에 B 전용 설정을 적용한 결과로
오해하지 않도록 검사 대상은 해당 B 커밋의 파일 목록에서 얻는다.

```powershell
uv sync --locked
uv run pytest -q

uv venv .cache/b-core-lock-check
uv pip sync --python .cache/b-core-lock-check/Scripts/python.exe requirements.lock
$bFiles = git ls-tree -r --name-only 3bf414c -- src tests |
    Where-Object { $_ -like '*.py' }
$bSources = $bFiles | Where-Object { $_ -like 'src/*' }
$bTests = $bFiles | Where-Object { $_ -like 'tests/*' -and $_ -notlike '*/__init__.py' }
& .cache/b-core-lock-check/Scripts/python.exe -m ruff check --config config/b-core/pyproject.toml @bFiles
& .cache/b-core-lock-check/Scripts/python.exe -m ruff format --check --config config/b-core/pyproject.toml @bFiles
& .cache/b-core-lock-check/Scripts/python.exe -m mypy --config-file config/b-core/pyproject.toml @bSources
& .cache/b-core-lock-check/Scripts/python.exe -m pytest -q @bTests
```

## 검증 범위

- A AGT 단위 검증에 실제 SDK를 공유하는 Guard 동시 슬롯 검사를 추가했다.
  4개 Task는 adapter 대기열을 통해 허용되고, 슬롯 포화 중 5번째는 AGT_ERROR·transport 호출 0이다.
  최종 대역 transport 호출은 허용된 4개만이며 소비·실제 wire 검증으로 대체하지 않는다(I2/I6, T20).
- 전체 검사 초기 실행에서 첫 실제 SDK import가 5초를 넘겨 시작 실패했고, 다음 실행에서는
  시작 제한 이후 1초 종료 확인도 실패했다. 집중 75개 검사는 통과했다.
  규칙 의미 검사에만 시작 여유를 30초로 지정했다. 제품의 기본 시작 5초·종료 1초와
  제어된 생성 지연/시간초과·종료 미확인 테스트는 유지한다. 느린 환경의 제품 시작 제한은 남는 운영 조건이다.
- 최종 실행 결과는 아래에 기록한다. 기존 B 971개/A 1,298개 기록과 구분한다.
- 후속 전체 검사에서 기존 transport 테스트의 정상 후속 호출도 10ms 제한에 걸렸다.
  첫 호출은 미해제 이벤트로 확실히 멈추므로 테스트 제한을 250ms로 조정하고,
  TimeoutError·worker 생존·총 호출 2회(재시도 없음) 검증을 유지했다. 제품 제한은 바꾸지 않았다.

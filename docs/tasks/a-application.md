# A · 애플리케이션 작업 지침과 체크리스트

작업 브랜치는 `feat/a-application`이다. **Guard의 판정이 실제 MCP 호출과 사람의 제어에 연결되는 실행 경로**를 맡는다. 초기 준비 뒤 개발환경 조사·HTML 시안에 이어, 사용자의 B 브랜치 활용 결정에 따라 A transport·AGT mock·모델/Runner·Qt 읽기 화면·bridge 커널과 단위 테스트를 현재 트리에 추가했다. 로컬 등록 초안, 승인 일반 텍스트 상세, 읽기 전용 Task 상태 화면도 추가했다. **실제 MCP 왕복·C 저장소/fixture·사람 제어 UI 연결은 아직 없다.** [현재 작업 현황](a-progress.md)에 각 작업의 증거와 재개 조건을 기록한다. 아래 체크리스트는 전체 인수 조건이며 부분 단위 구현을 전체 완료로 표시하지 않는다.

## 담당 범위

제품 경로는 향후 `src/guard_app/` 기준이다.

| 파일 / 영역 | 구현 책임 | 리뷰 |
| --- | --- | --- |
| `adapters/mcp_transport.py` | stdio·Streamable HTTP, 서버별 세션 소유 worker, 명령 future·원시 결과 | B |
| `adapters/agt.py` | AGT 연결과 `ResolvedRequest`·`AccessResult` 번역 | B |
| `adapters/model_client.py`, `services/runner.py` | 모델 호출, 제안 변환, 공개된 결과만 대화에 전달 | B |
| `services/bridge.py`, `ui/*`, `__main__.py` | 스레드·큐·이벤트, GUI, 시작·종료 | C |
| 담당 모듈 단위 테스트, UI T18 | 자기 모듈 검증 | 해당 모듈 리뷰 담당 |
| `docs/integration-notes.md` | SDK·AGT·모델·Qt 호환 검증 기록 | B·C |

B의 정책·Catalog·Guard·승인·응답 게이트, C의 SQLite·보안 유틸·Registry·fixture를 별도로 구현하지 않는다. `domain/*`·`ports.py`는 B가 정의하며 변경은 세 사람이 합의한다.

## 먼저 읽을 설계

개발문서 0.4·0.5·2장, 6.5절(Task 격리), 7–8장(실행·승인), 9장(transport), 10.1·10.3·10.4절(등록·AGT·모델), 12장(GUI), 부록 A를 읽는다.

## 작업 순서

### A1 · 계약과 호환성 확인

- [ ] B의 Transport·AccessChecker·ModelClient·Guard 결과 타입·UI 명령/이벤트 초안을 검토한다.
- [ ] C와 서버 등록 레코드, 도구 지문 검증 알림, host dispatch 계수·fixture 사용법을 맞춘다.
- [ ] Python 3.12에서 같은 SDK로 stdio READ와 HTTP SEND를 실제 왕복한다. 환경·정확한 버전·API 시그니처·결과를 `docs/integration-notes.md`에 기록한다.
- [ ] AGT를 판정만 받는 형태로 쓸 수 있는지와 의존성 충돌을 확인한다. 불가능하면 설계 10.3절의 모의 연동 경로를 선택하고 근거를 기록한다.
- [ ] redirect·retry·로그 콜백·stderr 격리의 실제 SDK 지원을 확인한다. 지원 여부를 추측하지 않는다.

### A2 · MCP transport

- [ ] 서버마다 장수 task 하나가 세션의 진입·사용·종료를 소유한다. 외부 호출은 명령 큐로만 전달한다.
- [ ] 매 명령 future를 성공 또는 예외로 반드시 확정한다. 변환 실패·McpError 등 명령 하나의 실패가 worker 전체를 종료시키지 않는다.
- [ ] 시간초과·연결 끊김·예상하지 못한 예외를 계약된 원시 결과 또는 예외로 전달한다. Task 최종 상태는 B의 Guard가 결정한다.
- [ ] 쓰기 자동 retry·redirect를 끈다. 재연결 중 진행 SEND는 결과 불명으로 알린다. C가 wire·수신 계수로 확인할 수 있게 한다.
- [ ] 등록된 실행 파일·인자·최소 환경만 사용한다. C의 launcher 검증 규칙을 적용하고 부모 환경 전체를 상속하지 않는다.
- [ ] 서버 stderr·logging·progress·알림은 격리 경로로 보낸다. 출처 확인 전 UI·모델·기본 로그에 공개하지 않는다.
- [ ] 연결 시 도구 지문을 확인하고 불일치는 C의 Registry 경로로 전달한다. transport가 직접 ACTIVE를 선언하지 않는다.

### A3 · AGT·모델·Runner

- [ ] AGT 오류·시간초과·형식 불명은 `AccessResult.error=True`로 반환한다. 판정 합성은 B에 맡긴다.
- [ ] 실제 연동과 mock 모드를 설정·UI·감사에서 구분한다. AGT 자체 실행이나 승인 기능으로 Guard를 우회하지 않는다.
- [ ] 모델에는 ACTIVE 등록 도구의 네임스페이스 이름과 고정 스키마만 제공한다. 승인·취소·정책 제어 API를 모델 도구로 노출하지 않는다.
- [ ] 모델의 도구 호출을 신뢰하지 않는 `ProposedCall`로 변환한다. task_id·label 등 추가 필드는 검증 실패로 처리한다.
- [ ] Runner의 도구 실행은 Guard를 통해서만 한다. `Released` 결과만 대화에 넣고 Pending·Denied에는 합의된 짧은 고정 문구를 쓴다.
- [ ] 새 Task마다 대화 이력·제공자 핸들·캐시 키·클라이언트의 Task 관련 세션 상태를 새로 만든다.
- [ ] 합성 자료와 승인된 모델 환경만 시연에 사용한다. T22의 환경 선택·검증 계약을 B·C와 확정한다.

### A4 · bridge·GUI·종료

- [ ] Qt 메인 스레드와 asyncio 백엔드 스레드를 분리한다. UI가 네트워크 future를 동기 대기하지 않게 한다.
- [ ] 실행 큐와 사람 전용 제어 큐를 분리한다. 승인 대기 중 취소·긴급 차단을 처리할 수 있게 한다.
- [ ] 불변 명령·이벤트로만 스레드를 연결한다. UI가 DB나 transport를 직접 사용하지 않는다.
- [ ] 작업 실행, 요청·승인, 서버·검사, 기록·정책 화면을 백엔드 확정 상태에서 갱신한다.
- [ ] DENY에는 승인 버튼을 만들지 않는다. ASK 첫 클릭에서 승인 버튼을 비활성화하고 중복 이벤트는 백엔드의 원자성으로 처리한다.
- [ ] 승인 대상 전체 수신처·인자를 동일 메모리 사본에서 일반 텍스트로 표시한다. HTML·링크·원격 이미지 자동 요청, 말줄임을 사용하지 않는다.
- [ ] 비가시·bidi·혼동 문자를 시각화하고 표시용 변환이 해시·실제 전송 바이트를 변경하지 않게 한다.
- [ ] 취소·긴급 차단은 요청됨과 적용됨을 구분한다. UNKNOWN_OUTCOME은 수신측 확인이 필요한 상태로 표시한다.
- [ ] 시작 실패·종료 시 worker·세션·백엔드 큐·DB 소유 스레드의 종료 순서를 C와 확인한다.

- [ ] C에게 계수 관측 위치, 오류 주입 지점, mock 설정, 재현 방법을 전달한다.

## A 작업 착수·완료 게이트

이 절은 A 브랜치에서 후속 구현 요청을 받을 때마다 적용한다. 위 체크리스트의 완료 표시는 아래 근거가 실제로 확보된 경우에만 바꾼다.

1. **착수 전:** 현재 브랜치와 작업 트리를 확인하고, 변경할 파일의 소유권·리뷰 담당, 관련 설계 절·불변식(I)·검증 ID(T/S)를 적는다. B 소유 `domain/*`·`ports.py` 계약이 필요한 작업은 `docs/contracts.md`의 합의 기록과 실제 코드를 확인한다. 미확정 계약을 임의의 API로 확정하지 않고, 독립적으로 가능한 호환성 조사와 A 소유 작업부터 진행한다.
2. **구현 중:** MCP 호출은 Guard가 예약한 요청만 transport로 보낸다(I1). 원시 결과와 서버 로그는 커밋 전 모델·UI·일반 로그에 노출하지 않는다(I5·I9). SEND의 전송 여부가 불명확하면 재시도하지 않고 결과 불명으로 전달한다(I8). 승인·취소는 사람 전용 제어 경로로만 받고, UI는 백엔드 확정 상태만 표시한다(I3·I7).
3. **완료 전:** 변경 파일을 소유권 표와 대조하고, 관련 단위 테스트 및 가능한 계약·통합 검증의 실제 실행 결과를 기록한다. 전송 차단이나 중복 방지는 화면 문구가 아니라 `host_dispatch`·`wire_post`(`wire_tools_call`)·`receiver_effect` 계수로 확인한다. 측정할 수 없는 항목과 미실행 항목은 각각 `검증 불가`, `미실행`으로 남긴다.
4. **인수 기록:** 변경 사항, I/T/S 연결, 계약 변경 여부와 합의 근거, 정확한 SDK·AGT·모델·Qt 버전 및 재현 결과, mock/실제 연동 구분, B·C에 전달할 의존성을 작업 보고에 포함한다. 외부 API 시그니처는 문서의 코드 골격이 아니라 설치된 코드 또는 공식 자료로 확인하고 `docs/integration-notes.md`에 남긴다.

2026-10-12 기준 상태: B 초안을 가져와 A의 transport·Runner·bridge·일부 Qt 화면과 단위 테스트를 구현했다. `docs/contracts.md`의 합의 표는 비어 있고 C 실행 소스·fixture는 아직 없다. 실제 MCP 왕복, 외부 연동, 전송 계수 인수는 완료로 표시하지 않는다. 작업별 증거와 남은 조건은 [A 진행 현황](a-progress.md)을 따른다.

## 세분화된 후속 실행 프롬프트

2026-10-12에 확인한 로컬 환경·HTML 시안 작업을 출발점으로, A 전체 범위를 [42개 실행 프롬프트](a-prompts/README.md)로 나눴다. 각 작업에는 선행 조건, 수정 범위, 완료 기준, 실제 검증 방법이 있다. B·C에게 전달할 계약 요청 초안도 포함한다. 프롬프트 작성 자체는 작업 완료나 계약 합의를 뜻하지 않으며, 개별 진행 판정은 [A 진행 현황](a-progress.md)에 기록한다.

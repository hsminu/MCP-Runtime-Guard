# A83 · 미연결 조회·세션 시작 가능 여부·제품 실행 옵션 정리

2026-10-18. B·C 없이 할 수 있는 A UI·실행 경로 정리다. B·C 소유 파일과 공통 계약은 바꾸지 않았다.

## 한 일

- **승인 목록이 "불러오는 중"에서 멈추던 문제.** 제품에는 승인 목록 조회를 처리하는 곳이 없다(B6-02 대기).
  - 이제 창은 승인 목록을 "조회 미연결"로 시작한다. 새로고침·탭·검색·정렬을 비활성화하고 "승인 목록 조회가 아직 연결되지 않았어"를 보인다. 요청 신호는 0건 나간다.
  - 조회를 처리하는 조립 루트만 `set_approval_query_connected(True)`로 연다.
  - 다른 조회 화면의 미연결 문구는 "조회 연결 대기"에서 "조회 기능 미연결"로 바꿨다. 기다리면 연결될 것처럼 읽히지 않게 하려는 것이다.
- **세션 시작 가능 여부를 미리 표시.**
  - `SessionRuntime.creation_blocker()`가 생성 순서대로 이미 알고 있는 거부 사유를 돌려준다: 종료됨, 정리 미확인, 준비 기능 없음, 이전 준비 실패, 세션 factory 없음.
  - bridge가 이 값을 READY 직전과 생성 시도 뒤마다 `session_capability_changed`로 알린다. `create_session`이 아예 없으면 `SESSION_CREATION_UNAVAILABLE`이다.
  - 화면은 사유가 있으면 "세션 시작"을 처음부터 비활성화하고 클릭 전 시제로 안내한다. 사유가 없어도 L2·Task별 검사는 생성할 때 따로 돈다.
- **모델 이름 상수.** `gpt-6.1-sol` 하드코딩 6곳을 `bridge.CODEX_MODEL_ID` 하나로 모았다. 테스트로 C의 `config/codex/codex.lock.json`의 `allowed_models`와 같음을 묶었다.
- **승인 대기 표시.** "30분 이상 대기"는 승인 유효 시간(기본 300초, Profile `approval_ttl_seconds`)과 관계없는 값이었다. 유효 시간이 지난 대기 행에 "승인 유효 시간 지남 · 상태 다시 확인(참고)"를 붙이도록 바꿨다. 화면에 TTL을 주입하는 `set_approval_ttl_seconds`를 두었다.
- **화면 정리.** 창 제목의 "모델 새 세션"을 없앴다. 새 세션 초안에서 바로 덮어써져 보이지 않던 초기 문구도 지웠다.
- **실행 옵션(`__main__`).**
  - 제품 모드에서 시연 전용 옵션(`--scenario`·`--mcp-transport`·`--store`·`--agt-*`)을 주면 조용히 무시하지 않고 거부한다(exit 2).
  - `examples`가 없는 설치판에서 `--demo`를 쓰면 traceback 대신 "소스 checkout에서만"이라는 안내로 끝난다.

`examples/http_spike_server.py`의 `mcp_transport` 비공개 이름 import는 테스트용 서버가 같은 로그 격리를 재사용하는 A 내부 사용이라 그대로 두었다.

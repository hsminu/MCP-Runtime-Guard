# A58 · JSON-RPC 클라이언트의 전송 마감·종료 교착·종료 사유 보정

A50·A55 JSON-RPC 클라이언트를 다시 손본 작업이다. 기존 기록은 고치지 않는다. QA 검토에서 재현된 결함을 고쳤다.

## 한 일

- **전송이 영원히 막히는 경로**
  - 결함: `request()`의 전송이 시간 상한 밖에 있었다. 그래서 상대가 읽기를 멈추면 시간초과도 `close()`도 요청을 풀지 못했다.
  - 이제 요청 하나에 마감 시각 하나를 두고, 전송과 응답 대기를 함께 묶는다.
  - 전송은 마감이나 종료 신호가 오면 취소된다. 프레임 일부가 이미 나갔을 수 있으므로 전송 시간초과나 채널 오류가 나면 클라이언트 전체를 `SEND_TIMEOUT`·`CHANNEL_FAILED`로 닫는다.
  - 전송 잠금을 기다리다 마감이 지나면 아직 아무것도 보내지 않았으므로 `REQUEST_TIMEOUT`만 낸다.
  - `notify`와 서버 요청 응답에도 같은 마감을 적용했다.
- **처리기 안에서 `close()`**: 서버 요청 처리기가 자기 task 안에서 `close()`를 부르면 자기 자신을 기다리며 교착하던 결함을 고쳤다.
- **종료 사유 구분**
  - 동시 서버 요청이 상한을 넘으면 `TOO_MANY_SERVER_REQUESTS`다. 전에는 `PROTOCOL_ERROR`였다.
  - 알림 처리기가 `InvalidMessageError`를 던져도 `HANDLER_FAILED`다.

## 실제 검증

- `tests/unit/test_jsonrpc_client.py` 31개 통과. 새 테스트는 네 가지다.
  - 막힌 전송이 마감으로 끝남
  - close가 막힌 전송 중인 요청을 풂
  - 처리기 안 close의 교착 없음
  - 상한 초과·처리기 형식 오류의 사유 구분
- 새 테스트 4개는 수정 전 코드에서 각각 실패함을 확인했다. 교착 가능성이 있어 외부 60초 제한을 걸고 돌렸다.
- `PytestUnraisableExceptionWarning`을 오류로 올려 돌려도 이 파일은 통과했다.
- `ruff check`·`ruff format --check`·`mypy` 통과.

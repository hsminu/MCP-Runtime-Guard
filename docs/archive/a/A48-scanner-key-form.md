# A48 · Scanner API 키 입력 화면

## 한 일

- `src/guard_app/ui/scanner_key.py`의 `ScannerKeyForm`. contracts 2026-10-15 "Scanner LLM API 키는 사용자가 각자 준비하고 Windows 자격증명 관리자에 저장" 결정의 입력 화면이다.
  - 가려진 입력칸이다. 비밀번호 표시 방식이라 Qt가 복사·잘라내기를 막는다. 컨텍스트 메뉴와 입력기(IME)는 끈다.
  - 안내문은 세 가지를 알린다: 앱 전용 OpenAI 프로젝트 키와 사용 한도를 권장한다, 자격증명 관리자에만 저장한다, 우리 서버로 보내지 않는다.
  - 저장은 주입받은 `KeySaver = Callable[[str], bool]`로만 한다. 저장 결과가 정확히 `True`일 때만 성공으로 본다. 그 밖의 값은 고정 문구의 실패로 처리하고, 오류 원문은 받지 않는다.
  - 저장을 시도하면 성공·실패와 관계없이 입력칸을 먼저 비운다. 화면에 숨길 때도 비운다. 성공하면 끝 4자리만 남긴다. 4자 이하 키는 전체가 드러나므로 끝자리를 표시하지 않는다.
  - 키를 Signal·로그·라벨·repr로 내보내지 않는다. `key_saved` Signal에는 값이 없다.
- 실제 저장은 연결하지 않았다. 저장 함수가 없으면 저장 버튼이 꺼지고 "아직 저장 기능이 연결되지 않아 키를 저장할 수 없어."라고 표시한다. 연결 지점은 C2.10(`security/secrets.py` 자격증명 관리자 저장 API)이다.

## 실제 검증

- `tests/unit/test_ui_scanner_key.py` 10개 통과.
  - 가림, 컨텍스트 메뉴와 IME 꺼짐
  - 저장 함수 없을 때 저장 불가와 입력 비움
  - 성공 시 앞뒤 공백을 제거한 키를 1회만 전달, 끝 4자리 표시
  - 라벨·입력칸·repr·로그에 키와 표지 문자열이 없음
  - 실패나 애매한 반환값(False, None, "yes", 1)이면 고정 문구와 입력 비움
  - 공백 입력 거부, 짧은 키, 숨길 때 비움
- `uv sync --locked` 환경에서 `ruff check`·`ruff format --check`·`mypy` 통과, `pytest -q` 2353 통과(경고 5, subtest 20).

## 남은 한계

- 막힘: C2.10 저장 API. C 오류를 `False`로 바꾸는 연결 코드는 bridge 쪽에서 만든다.
- 화면 배치(어느 탭·대화상자에 둘지)는 화면 명령·이벤트 계약(B1.5) 뒤에 정한다.
- Python 문자열과 Qt 버퍼는 안전 삭제를 보장하지 않는다. 화면 사본만 비운다.

# A104 · 정책 저장 뒤 적용 실패·거부 때 재시작까지 Guard 닫기

2026-10-26. #33 B 답변 4번(저장 성공·적용 실패)을 A에 반영했다.

## 한 일

- `services/session_runtime.py` `change_server_access`: 설정 문서를 저장한 뒤 `apply_policy_change`가 `PolicyChangeError`를 내면 다음을 한다.
  - `guard.aclose()`로 Guard를 닫는다.
    - 새 도구 호출은 바로 거부된다. 대기 중 승인은 B 종료 규칙대로 정리된다.
    - transport는 닫지 않는다. 이미 보낸 호출은 결과를 커밋한다.
  - 새 세션을 막는다. `creation_blocker`와 생성 중 확인이 모두 `POLICY_APPLY_FAILED`를 낸다.
  - 다음 정책 변경은 저장하기 전에 거부한다. 다시 저장하면 파일과 Guard가 어긋나 있다는 사실이 가려진다.
  - `POLICY_APPLY_FAILED`를 낸다. 정책 화면은 기존 문구("설정은 저장했지만 적용을 확정하지 못해 Guard를 정지했어. 앱을 다시 시작해.")를 보여 준다.
- 두 경우를 같게 처리한다.
  - **적용 전 거부**(기준 버전 불일치·입력 오류·이미 정지): 전에는 Guard가 옛 규칙으로 계속 돌았다. 사용자가 deny를 추가해 저장했어도 실제로는 옛 허용이 적용됐다.
  - **적용 중 실패:** B Guard가 이미 전역 정지한다. 다만 전에는 새 세션과 재저장이 막히지 않았다.
- `ui/presentation.py`: 세션 시작 차단 문구에 `POLICY_APPLY_FAILED`를 넣었다.

- 이미 실행 중인 세션은 닫지 않는다. 도구 호출은 모두 거부되지만 모델과의 대화는 이어질 수 있다.

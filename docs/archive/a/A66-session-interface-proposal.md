# A66 · 세션 관리자 인터페이스 제안 v1

2026-10-18. 최신 main `a41f1d8`을 A 브랜치에 병합하고 [#20에 제안 v1](https://github.com/hsminu/MCP-Runtime-Guard/issues/20#issuecomment-6246972714)을 게시했다. 제안 원문은 이슈에 두며 이 기록은 완료 범위만 남긴다.

- 현재 A65의 주입형 연결부와 실제로 필요한 공통 계약을 구분했다. `ModelClient` 제거·DTO/포트 정의는 B, 세션 관리자·JSON-RPC·Guard 중계·L3는 A, launcher·L1/L2·경로·종료/정리는 C라는 기존 경계를 유지한다.
- L2 증거와 실행 구성의 결박, 새 Task/thread 매핑, NOTIFY-01의 유실 없는 대기와 중복 응답 방지, STOP-01의 시스템 정지와 UNKNOWN_OUTCOME 보존, Task별 FIFO·동시 실행, 검토된 설명·원문 처리·로그 정리를 제안했다. 최종 타입·메서드와 C 제공물의 형식은 B·C 검토 대상으로 남겼다.
- `runner.py`·`session_runtime.py`의 설명만 보정해 C가 완성된 세션 관리자/Guard 중계까지 구현한다는 오해를 없앴다. A가 C의 안전 연산을 조합하는 factory이며 동작 변경은 없다.

검증: 별도 에이전트가 최신 결정·현재 A/B 인터페이스·소유권과 제안의 차이를 검토했다. 게시 후 댓글 본문을 로컬 초안과 대조했다. 최종 Ruff 전체 검사·포맷 137파일·mypy 63소스가 통과했다. 이번 제안 때문에 실제 Codex 호출·프로세스 실행·공통 포트 변경을 하지 않았고 새 실행 검증을 완료했다고 보고하지 않는다. 함께 수행한 A54 검사 결과는 별도 A54 기록에 있다.

남은 일: B의 NOTIFY-01/STOP-01/DESC-01 및 공통 타입 초안·ModelClient 제거, C의 #21 launcher/L2/경로/정리 API, A·B·C 합의와 실제 JSON-RPC/Guard 중계 연결. T21·T22·T39–T46은 제안의 인수 기준이며 실제 프로세스 인수 완료가 아니다. 공통 문서는 원격 병합분만 반영했고 B·C 소유 구현은 변경하지 않았다. PR은 생성하지 않았으며 사용자 요청으로 A 브랜치에 커밋·푸시한다.

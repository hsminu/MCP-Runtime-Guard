# A63 · 세션 중심 A 시안을 실제 Qt 앱에 반영

## 한 일

- 대화를 기본 화면으로 바꾸고 세션 목록·검색·상태·메시지 입력·결과/실행 활동 왕복을 연결했다. 같은 세션 위젯을 유지해 입력 초안·선택·커서·스크롤·입력 포커스를 보존한다.
- 기존 현황, MCP 서버 목록/필터/상세/검사, 등록 초안, 승인 목록/사본 검토, 호출 로그/상세/CSV, 취소·긴급 차단을 유지했다. 독립 폼이던 폴더 등급과 Scanner 키 입력에도 관리 화면 진입점을 제공한다.
- 흰색·연보라색, 선형 아이콘, 버튼·카드·입력창 스타일을 통일했다. 작은 화면에서는 메뉴와 입력/작업 버튼을 재배치한다.
- 사용자 메시지는 bridge를 통해 기존 Runner로 전달한다. Task·epoch·실행 상태·입력 가능 상태를 검사하고 화면 projection과 실제 Runner의 식별자가 일치해야 접수한다. 승인 대기·결과 불명·이전 epoch는 새 입력으로 실행을 재개할 수 없다.
- 대화 이벤트는 메모리 전용이며 일반 텍스트로 표시한다. 다른 세션으로 자동 이동하지 않고, 종료 시 UI와 Runner의 원문을 폐기한다. 종료 뒤 늦은 이벤트와 과거 상태로 원문을 다시 표시하지 않는다.
- 세션을 바꾸면 승인 검토 사본을 폐기한다. 연결된 Task로 돌아와 정확한 사본을 다시 확인해야 승인할 수 있다. 초안에서 기존 Task의 실행·승인·취소를 제어할 수 없다.

## 실제 검증

- Windows, Python 3.12.15, PySide6 6.12.0, `QT_QPA_PLATFORM=offscreen`에서 검증했다. 사용자 데스크톱에 창을 띄우지 않았다.
- `uv sync --locked`, CI와 같은 `uv export --locked --all-groups --no-emit-project -o requirements.lock` 후 lock 내용 변경 없음.
- `pytest -q`: 2,445개 및 subtest 20개 통과, SDK 경고 5개, 134.04초. `mypy`: 62개 소스 파일 통과.
- `ruff check src tests examples`, `ruff format --check src tests examples` 통과. 디렉터리 전체 검사는 기존 미추적 `docs/tasks/` 실험 스크립트에서 실패했으며, 해당 커밋 제외 경로만 제외한 전체 Ruff·format 검사는 통과했다. 기존 실험 파일은 변경하지 않았다.
- 새 회귀는 세션 전환·초안 보존·일반 텍스트·늦은 이벤트 폐기·기능 진입점, 실제 Runner의 메시지 수락/거부와 epoch 불일치를 확인한다. 기존 Overview 검사는 기본 진입 화면 변경에 맞춰 현황으로 명시적으로 이동한다.
- 독립 GUI QA 107개 관측·27장 캡처. 1280×800, 1024×768, 390×780, 320×680에서 대화·결과 화면과 관리 화면을 검사했고 27개 가로폭 검사 모두 넘침 0이었다.
- 실제 합성 mock+stdio에서 ASK 전 수신 부작용 0, 사본 검토 후 중복 승인 시 부작용 1/dispatch 2(READ+SEND), 후속 메시지 뒤 부작용 증가 없음. 취소 후 UI/Runner 원문 폐기, 별도 긴급 차단 후 HALTED/부작용 0을 확인했다.
- 상세 왕복의 초안·커서·스크롤·포커스 보존, 검색, Scanner 키 화면을 숨길 때 입력 폐기도 확인했다. 재현 스크립트와 캡처는 Git 제외 경로 `.test-artifacts/`에 있다.

## 한계와 리뷰

- 현재 실행 백엔드는 기존 단일 합성 Runner다. 새 세션은 미연결 초안이며 실제 다중 Task 생성/동시 실행은 구현하지 않았다. 대화·초안은 디스크에 저장하지 않는다.
- 모델 API·CLI 선택, Scanner 키의 Windows 자격증명 관리자 저장, 폴더 등급 실제 적용, 제품 Registry/감사 조회는 기존 미연결 상태를 명시한다. 기능을 활성화된 것처럼 표시하지 않는다.
- 기존 AGT 제거와 실제 모델/저장소 연결의 타 담당 의존성은 남아 있다. 도구 호출을 Guard 밖으로 우회하지 않는다.
- A 소유 UI·bridge·Runner와 단위 테스트 변경. domain/ports 계약 변경 없음. 관련 I1·I3·I5·I7·I8·I9, T18·T21의 UI/합성 범위이며 실제 모델 세션 격리 인수 완료를 뜻하지 않는다. C 독립 인수는 별도다.
- PR 미생성. 사용자 요청에 따라 `feat/a-application`에 커밋·푸시하며 main 병합은 하지 않는다.

# A168 · A151 MSIX 경로 L2 재확인: 패키지 앱에서 띄울 때만 실패

2026-10-29 · `wip/next`(A167 커밋 `3cc7cc7` 위). PR: 아직 없음(로컬 커밋).
관련: A151, A161, I6·I11, T22. C 코드·제품 코드 변경 없음.

## 왜 다시 봤나

A161은 Codex 데스크톱에서 띄운 제품의 기본 시작이 L2에서 실패하는 것을 재현했다. 앱 폴더가 MSIX 가상 경로(`Packages/…/LocalCache/Local/MCPRuntimeGuard`)로 풀리고, C `codex_l2`가 논리 경로와 Codex가 보고한 물리 경로를 다른 파일로 보았다.

사용자 결정으로 C의 경로 비교 수정은 보류 중이다. 그래서 이번에는 수정 없이 다음만 봤다.

- Codex가 아닌 다른 패키지 앱에서도 같은가
- 패키지 밖 프로세스에서는 어떤가

## 방법

- 제품 시작과 같은 `CodexProcessPreparation`으로 `claim`과 `prepare_startup`을 실행했다.
  - 고정 codex.exe 0.162.1과 C `run_l2`를 썼다. 모델은 C의 127.0.0.1 가짜 모델이다.
  - 로그인과 인증정보는 쓰지 않았다.
- 앱 루트는 시험용 `%LOCALAPPDATA%\MCPRuntimeGuard-a151-probe`다.
  - 기본 `app_root()`와 부모 폴더가 같다. 사용자의 실제 앱 폴더를 건드리지 않으려고 이름만 바꿨다.
  - 논리 경로로 한 번, `resolve()`한 경로로 한 번 넘겼다. 끝나면 폴더를 지웠다.
- 두 환경에서 돌렸다.
  1. Claude 데스크톱 앱(MSIX)이 띄운 셸. 이 프로세스에는 패키지 ID가 없다. 그래도 `%LOCALAPPDATA%` 아래 새 폴더가 `Packages/Claude_…/LocalCache/Local/…`로 풀린다.
  2. WMI `Win32_Process.Create`로 띄운 패키지 밖 프로세스. 경로가 그대로 풀린다.
- 기록한 값은 고정 실패 코드, bool, 초뿐이다([근거 JSON](../evidence/A168-msix-l2-probe.json)).

## 결과

| 환경 | 경로 | L2 | 실패 코드 | 초 |
| --- | --- | --- | --- | ---: |
| Claude 데스크톱이 띄운 셸 | 논리 | 실패 | `L2_CONFIG_LAYERS_UNEXPECTED`, `L2_CONFIG_MISMATCH` | 1.266 |
| Claude 데스크톱이 띄운 셸 | resolve | 통과 | — | 1.193 |
| 패키지 밖(WMI) | 논리 | 통과 | — | 1.175 |
| 패키지 밖(WMI) | resolve | 통과 | — | 1.191 |

- A161과 같은 두 코드다. Codex 데스크톱만의 문제가 아니다. 파일 시스템을 가상화하는 MSIX 앱 아래에서 제품을 띄우면 생긴다.
- 패키지 밖 프로세스에서는 논리 경로로도 통과한다. 예를 들어 탐색기나 패키지가 아닌 터미널에서 띄우는 경우다. 그런 환경의 기본 제품 시작은 이 문제에 걸리지 않을 것으로 본다. 다만 실제 기본 앱 폴더로 `main()`을 돌린 것은 아니다.
- 초는 `prepare_startup` 전체(codex.exe 지문 확인 포함)다. A161의 L2 시간과 측정 구간이 달라 비교하지 않는다.

## 남은 것

- A151 "기본 제품 MSIX 경로의 L2 성공 재확인·C 인수"는 그대로 열려 있다. MSIX 앱 아래의 기본 시작이 통과하려면 C의 경로 비교 수정이 필요하다. 보류는 사용자 결정이라 A가 바꾸지 않았다.
- 판단 재료로 남긴다. 실제 사용자가 제품을 MSIX 앱 안에서 띄울 일이 없다면 이 실패는 개발 환경에서만 보인다. 사용자가 Codex·Claude 데스크톱에서 개발·확인할 때는 계속 보인다.
- 확인하지 않은 것
  - Windows Terminal(자체가 MSIX 앱)에서 띄운 셸이 가상화를 받는지
  - 설치판(C6.20 패키징)이 자체 패키지로 실행될 때
- 실제 기본 앱 폴더와 로그인 상태의 시작·Task 시작은 이번 확인에 없다. 사용자 앱 데이터를 건드리지 않으려고 시험 폴더만 썼다.

# A50 · Codex app-server용 JSON-RPC 클라이언트 뼈대

## 한 일

- `src/guard_app/adapters/jsonrpc_client.py`를 새로 만들었다. 후속 Codex 세션 관리자(A19–A22)가 쓸 JSON-RPC 2.0 클라이언트이며, 특정 전송 방식에 묶이지 않는다.
  - 주입받은 `FrameChannel`(완성된 메시지 하나씩 `receive`·`send`)만 다룬다. 프로세스는 띄우지 않는다. codex.exe 실행은 `security.launcher`(C2.6)가 하고, 그 stream 위에 채널을 만든다.
  - 프레이밍과 Codex 메서드 스키마는 고정 버전이 정해지지 않았다(GitHub #21 1번). 그래서 프레이밍은 채널 쪽에 두고 `MessageCodec`은 바꿀 수 있게 했다. 기본 `JsonCodec`은 UTF-8 JSON 객체만 받고, 중복 키·NaN·Infinity를 거부한다. Codex 고유 메서드는 구현하지 않았다.
  - 할 수 있는 일:
    - 정수 id로 요청과 응답 짝 맞추기(순서가 바뀌어도 됨)
    - 알림을 도착 순서대로 동기 전달
    - 서버가 보낸 요청은 요청마다 별도 task에서 처리하고 결과를 응답한다. 처리기를 기다리는 동안에도 읽기는 계속된다. 승인 대기 중 L3 감시가 가능하게 하려는 것이다. 처리기가 없으면 -32601로 답한다.
    - 요청별 시간 상한. 시간초과 뒤 늦게 온 응답은 버린다.
    - 송수신 프레임 크기 상한, 동시 미결 요청 상한
  - fail-closed: 형식이 틀린 프레임, 크기 초과, EOF, 채널 오류, 처리기 예외가 나면 클라이언트를 닫는다. 남은 요청은 고정 reason(`PROTOCOL_ERROR`, `FRAME_TOO_LARGE`, `EOF`, `CHANNEL_FAILED`, `HANDLER_FAILED`, `CLOSED`)으로 실패시킨다.
  - 원격 오류는 정수 code만 남기고 원격 message는 버린다. 메시지 본문·파라미터·원문을 로그나 예외 메시지에 넣지 않는다.

## 실제 검증

- `tests/unit/test_jsonrpc_client.py` 25개 통과. 가짜 채널만 썼고 프로세스·네트워크는 없다.
  - 순서가 바뀐 응답의 짝 맞추기, 원격 오류의 code만 보존·원문 비노출(로그 포함)
  - 시간초과와 늦은 응답 무시, 알림 순서와 무응답
  - 처리기 대기 중에도 읽기 계속, 처리기 없음 -32601, 처리기 예외로 닫힘
  - 잘못된 프레임 11종으로 닫힘, 송수신 크기 상한, EOF
  - 미결 요청 상한, 시작 전·중복 시작·닫힌 뒤 요청 거부, 잘못된 설정 거부, 코덱 왕복
- `PytestUnraisableExceptionWarning`을 오류로 올려 돌려도 통과했다. 처리되지 않은 task 예외 경고가 없다.
- `uv sync --locked` 환경에서 `ruff check`·`ruff format --check`·`mypy` 통과, `pytest -q` 2413 통과(경고 5, subtest 20).

## 남은 한계

- 프레이밍(줄 단위 등)과 Codex 메서드는 고정 버전 설치본에서 스키마를 확인한 뒤 붙인다. 로컬 설치본은 0.159.0, C 기록은 0.162.1이라 아직 확인하지 않았다.
- 크기 상한은 채널이 넘겨준 프레임에 적용된다. 채널 자체도 읽기 단계에서 크기를 제한해야 한다(채널 구현 때).
- 서버 요청 순서와 허용 메서드(L3 허용 목록)는 세션 관리자가 정한다. 이 클라이언트는 판단하지 않는다.
- 처리기 예외 원문은 버린다. 그 사유를 감사에 기록하는 방식은 B의 시스템 Task 정지 입구(GitHub #20 2번)가 정해진 뒤 연결한다.

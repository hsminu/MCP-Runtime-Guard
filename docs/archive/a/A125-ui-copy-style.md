# A125 · 앱 문구를 하세요체·음슴체로 통일

2026-10-28. 사용자 결정: 앱 화면의 안내·오류·상태 설명에 반말(해체)을 쓰지 않는다. 사용자가 할 일은 하세요체(예: "확인하세요"), 상태·사실·결과는 음슴체(예: "정지함", "없음")로 쓴다. 범위는 앱 화면 문구와 그 문구를 단언하는 테스트다.

## 한 일

- `src/guard_app/ui/` 17개 파일의 문구 약 230개를 바꿨다. `presentation.py`의 실행·제어·수명주기·Codex 실패 문구표가 가장 많다.
- 1차로 문장 끝 어미를 규칙으로 바꾸고, 바뀐 줄을 모두 읽어 사실/지시를 다시 골랐다. 예를 들어:
  - "원문을 지워"는 앱이 하는 일이라 "원문을 지움"으로 바꿨다. 지시("지우세요")가 아니다.
  - "직접 저장해"는 Codex가 하는 일이라 "저장함"으로 바꿨다.
  - "넣지 마"는 "넣지 마세요"로 바꿨다.
- 시점이 다른 두 문구는 구분해 남겼다. 시작을 시도했다가 거절된 경우는 "세션을 시작하지 않았음", 시작 전에 이미 막힌 경우는 "새 세션을 시작하지 않음"이다. 테스트가 이 차이를 검사한다.
- 문체 때문에 길어진 문구 6줄은 100자 제한에 맞게 나눴다.
- `ui` 밖의 모듈에는 화면에 보이는 해체 문구가 없었다. 독스트링·주석은 바꾸지 않았다.
- 테스트 10개 파일의 옛 문구도 새 문구로 바꿨다. `not in` 단언은 옛 문구가 남으면 무조건 통과해서 검사가 무의미해지므로, 같이 바꿨다.

## 검증

- 바꾼 뒤 `ui` 파일에서 문장 끝이 해체 어미인 문자열을 다시 찾았고, 남은 것이 없었다. 남은 후보는 명사로 끝나는 라벨뿐이었다.
- 전체 테스트(`QT_QPA_PLATFORM=offscreen`, `tests` 전체): 4,874 통과, 4 skip, subtest 20. 실패 1개는 C 소유 `test_paths.py::test_app_root_is_under_local_app_data`이고 이 변경 전부터 실패했다. ruff check·format, mypy(strict)는 통과했다.
- 별도로 B 소유 `test_access_rules.py::test_decision_and_normalization_are_deterministic`(Hypothesis 속성 테스트)가 전체 실행 3번 중 2번 실패했다. 단독 4번, 앞쪽 파일 순서대로 일부만 실행, 전체를 모은 뒤 그 테스트만 실행했을 때는 모두 통과했다. 이 변경은 그 파일과 대상 코드에 닿지 않는다. 원인은 확인하지 못했다.

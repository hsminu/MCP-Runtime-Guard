# A148·A149 · 실제 키와 틀린 키의 첫 요청

2026-10-29 · A · 관련 I6·I8·I9, 개발문서 10.4·12절, T19·S04의 로그인 안내 보조 확인.

## 실제 실행 결과

- 사용자가 실제 제품 데스크톱 창의 Codex API 키 입력란에 기존 키를 직접 입력했다. 저장 직후 가린 입력란은 비워졌고 끝 4자리와 `첫 요청에서 키를 확인함` 안내가 표시됐다.
- 도구가 없는 새 Task에서 합성 요청 `도구를 호출하지 말고 OK만 답해.`를 보냈다. 실제 고정 Codex 0.162.1·gpt-6.1-sol이 `OK`를 답했다. 첫 요청 성공과 계정의 API_KEY 저장 상태를 구분했다.
- Task를 취소·정리하고 실제 로그아웃한 뒤, 비밀이 아닌 잘못된 키를 입력했다. 이 경우에도 첫 요청 전에는 같은 미검증 안내가 표시됐다.
- 틀린 키의 첫 요청은 실제 HTTP 401이었다. 처음에는 일반 세션 실패 안내가 나오는 A 결함을 발견했다. [A160](A160-codex-http-auth-error.md)에서 수정하고 새 프로세스로 재실행해 기존 A149의 키 확인·로그아웃·재로그인 안내를 확인했다. Task는 HALTED이고 원문 대화가 제거되며 추가 전송이 비활성화됐다.
- 키 원문과 전체 RPC·원문 오류는 근거 파일에 넣지 않았다. HTTP 오류의 태그·정수 상태 코드, 프로세스 종료 확인만 관찰했다.

## 한계

- 기본 시작은 C L2의 Windows 가상 경로 비교에서 실패했다. 첫 요청 시험에는 같은 실제 폴더의 정규 경로를 기존 테스트 설정으로 넘겼고 L2 자체는 통과했다. 기본 제품 시작 실패는 별도 미해결 항목이다.
- 등록된 합성 서버는 PENDING·Profile 미선택이었다. 실제 API 검증은 도구 없는 대화였고 Guard 도구 실행·외부 SEND 검증이 아니다.
- 잘못된 키의 모델 요청을 자동 재시도하는 로직은 추가하지 않았다. 재현·수정 확인은 각각 사용자가 요청한 검증의 새 Task에서 수행했다.

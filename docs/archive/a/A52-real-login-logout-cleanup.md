# A52 · 실제 API 키·ChatGPT 로그인과 로그아웃 정리

2026-10-29 · A · 관련 I9·I11, 개발문서 10.4·11.4·12절, T43의 계정 정리 부분 관찰. 계약·C 구현 변경 없음.

## 실제 검증

실제 데스크톱 제품 창과 고정 Codex 0.162.1로 유효 API 키 로그인·첫 모델 요청, 잘못된 키 시나리오, 브라우저 로그인·재시작 유지 후 로그아웃을 실행했다. 키와 브라우저 인증은 사용자가 직접 입력·진행했다. 비밀 원문 대신 암호문 파일 이름, 자격증명 존재 bool, Task 폴더 목록, 고정 계정 상태, PID 종료 확인을 기록했다.

| 관찰 | 유효 API 키 로그아웃 | ChatGPT 로그아웃 |
| --- | --- | --- |
| `account/logout` | 성공 | 성공 |
| 계정 Codex 프로세스 | 종료 확인 True, returncode 0 | 종료 확인 True, returncode 0 |
| 정리 함수 시작 시 Task 폴더 | 0개 | 0개 |
| `codex_auth.age` | 존재→없음 | 존재→없음 |
| primary Windows 자격증명 | 존재→없음 | 존재→없음 |
| Scanner 자격증명 | 유지 | 유지 |
| 로그아웃 시작→정리 완료 | 8.990540초 | 6.064340초 |

- 두 경로에서 실제 순서는 logout RPC 성공→계정 프로세스 종료 확인→계정 폴더 제거→C 자격증명 정리 함수였다. 함수 반환만으로 폴더 삭제를 추정하지 않고 `tasks=[]`를 읽었다.
- ChatGPT 로그아웃 뒤 새 계정 프로세스를 열어 SIGNED_OUT을 재조회했고, 앱 종료 때 이 새 프로세스도 확인 종료했다. 최종 암호문 0개·primary 없음·Task 폴더 0개·Scanner 유지다.
- 일반 앱 종료는 로그인 정보를 유지하고 Task 폴더만 정리하는 것도 확인했다. 로그아웃 뒤 다시 로그인한 실행의 마지막 자격증명 존재를 삭제 실패로 해석하지 않는다.
- C 관점의 독립 하위 에이전트가 소스와 안전한 관찰 JSON을 읽기 전용 검토했다. 관찰된 순서에 모순은 없다는 결과이며, C 소유자의 인수 승인으로 대체하지 않는다.

## 근거와 남은 한계

- [완료된 관찰 JSON](../evidence/A109-A151-A52-real-login.json). `canonical-api-key-1`의 첫 logout 구간, `canonical-invalid-key-fixed`의 API_KEY→SIGNED_OUT→CHATGPT 전환, 두 ChatGPT 후속 실행을 구분해서 본다.
- [A161](A161-msix-l2-path-observation.md)의 기본 MSIX 경로 문제는 사용자 결정대로 미수정이다. 이번 실제 실행은 같은 물리 앱 폴더의 정규 경로를 기존 설정으로 주입했다.
- Gateway 자격증명은 모든 관찰에서 처음부터 없었다. 이미 존재하는 Gateway 항목의 실제 삭제는 입증하지 않았다.
- **T43 전체 완료는 아니다.** 표지 도구 결과 주입 후 앱 폴더 전체·Codex 로그 DB의 표지 잔류 검사를 수행하지 않았다. 앞서 제품 `guard.log`에서 실제 Scanner 키·잘못된 시험 키의 일치 0건을 본 한정 검사도 이를 대체하지 않는다.
- Profile에는 시험 서버를 선택하지 않았고 실제 수신 계수는 호출 0·부작용 0이었다. 이 계수로 Guard wire 차단이나 도구 실행 경로를 검증했다고 보고하지 않는다.
- 최종 제품은 로그아웃·종료 상태다. Scanner 키와 PENDING 시험 서버 등록은 유지했다.

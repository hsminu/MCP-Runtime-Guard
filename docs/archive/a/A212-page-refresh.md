# A212 · 로그·승인 화면으로 이동할 때마다 Store 다시 읽기

2026-10-30 · `wip/next` · PR #110. 출처: 사용자 요청("화면 이동시 sqli 불러오기(새로고침) 현재 채팅에서 로그로 이동시 로그가 최신화 안되는 버그 있음").
관련: A33·A34(승인 목록 Store 조회), A35(호출 로그 Store 조회), A172(`StoreQueryLink`).

## 문제

- `StoreQueryLink`는 Store 조회 출처가 연결될 때만 호출 로그·승인 목록을 읽었다.
- `GuardWindow.navigate`는 화면만 바꿨다. 채팅에서 도구를 부른 뒤 로그 화면으로 가도 연결 때 읽은 목록이 그대로 보였다.

## 한 일

- `navigate("logs")`·`navigate("approvals")`는 그 화면의 `refresh()`를 부른다. 지금 보고 있는 쪽 번호로 다시 읽는다. 같은 화면으로 다시 이동해도 읽는다.
- 이동 대상(호출 ID·승인 ID)이 있으면 지금처럼 바로 선택을 시도하고, 그 화면의 현재 조회 토큰과 같은 응답이 오면 한 번 더 선택한다.
  - 이전 조회의 늦은 응답, 다른 목록의 응답, 실패 응답으로는 선택하지 않는다.
  - 다른 화면으로 떠나면 대기 중인 선택을 버린다.
- 조회만 보낸다. 승인·거부 같은 제어 명령은 보내지 않는다. 조회 출처가 연결되지 않았으면 아무것도 보내지 않는다.
- 다른 화면(개요, 감사, 서버, 실행, 결과)은 이동해도 조회하지 않는다.
- 구현은 Codex(`gpt-6-astra`, high)가 했다.

## 한계

- 화면에 머무는 동안에는 자동으로 다시 읽지 않는다. 이동할 때와 기존 새로고침 동작 때만 읽는다.
- 다시 읽은 뒤 이동 대상이 없는 목록에서는 선택이 비워질 수 있다.
- 실제 앱에서 채팅 → 로그 이동으로 확인하지 않았다.

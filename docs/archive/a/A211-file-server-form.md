# A211 · 로컬 파일 서버 등록을 공유 폴더와 등급 선택으로 줄이기

2026-10-30 · `wip/next` · PR #110. 출처: 사용자 요청("로컬 파일 서버 등록 화면을 '폴더를 고르고 등급을 고르는' 두 동작만으로 줄여 주십시오. 보안 규칙은 그대로 두고 ...").
관련: A49(폴더 선택 등록), A128·A105(설정 기록 복원), A156(목적지 표시), C의 폴더 등록 검증.

## 문제

- 로컬 파일 서버를 고르면 서버 ID·신뢰 경계·최대 수신 등급을 사용자가 직접 골라야 했다. 로컬 파일 서버는 답이 정해져 있는 값이다.
- "루트 목록(list_root)" 등급을 따로 골라야 했고, 하위 폴더 등급은 루트보다 낮게도 고를 수 있었다. 겹친 하위 폴더도 등록 단계에서야 거절됐다.
- 화면 용어가 "루트"였고 등급 이름이 "공개·내부·기밀"이라 신뢰 경계 "내부"와 겹쳤다.

## 한 일

- 로컬 파일 서버를 고르면
  - 서버 ID를 `local-files`로 채운다. 이미 있는 ID(대소문자·전각 접기 기준)면 `local-files-2`, `-3` …로 넘긴다. ID 목록이 바뀔 때마다 다시 고른다.
  - 신뢰 경계는 `internal`("내부"), 최대 수신 등급은 `CONFIDENTIAL`("민감")로 고정한다.
  - 세 칸은 제목·입력·오류까지 숨긴다. 숨긴 칸의 오류(ID 형식 등)는 폴더 영역 오류 줄에 보인다.
  - 표시 이름을 고쳐도 ID가 따라 바뀌지 않는다.
  - 다른 방식으로 돌아가면 사람이 직접 쓴 ID만 되돌리고 경계 두 칸은 비운다.
- "루트 목록" 등급 칸을 없앴다. 요청의 `list_root_label`에는 공유 폴더 등급을 그대로 싣는다. 계약 필드는 그대로다.
- 하위 폴더
  - 등급 목록은 공유 폴더 등급과 같거나 높은 등급만 보인다. 공유 폴더 등급을 올려 기존 선택이 목록에서 빠지면 선택을 비운다.
  - 폴더 선택 대화상자는 공유 폴더에서 시작한다. 공유 폴더 자체·바깥 폴더, 이미 고른 하위 폴더와 안팎으로 겹치는 폴더는 고를 수 없고 그 줄에 오류를 보인다.
  - 화면에는 "└ a/b"처럼 공유 폴더 기준 상대 경로를 보이고, 요청에는 고른 절대 경로를 그대로 싣는다.
  - 공유 폴더를 바꾸면 하위 폴더 줄을 모두 지운다. 공유 폴더를 고르기 전에는 "하위 폴더 추가"가 꺼져 있다.
  - 안내는 "공유 폴더를 고르고 등급을 정하세요. 더 높은 등급이 필요한 하위 폴더만 따로 추가하세요." 한 줄로 줄였다.
- 용어: 화면의 "루트"를 "공유 폴더"로 바꿨다. 등급 이름은 `PUBLIC`·`INTERNAL`·`CONFIDENTIAL` = "공개·개인·민감"이다(`presentation.LABELS`, 거절 사유 문구 포함). 신뢰 경계 "내부"는 그대로다.
- 기존 시험 기대값을 새 용어에 맞췄다: `test_ui_policy`, `test_ui_sessions`, `test_ui_chat`, `test_server_add`, `test_a156_destinations`, `test_a49_registration`(없어진 `list_root` 참조 제거, 요청 기대값 갱신).
- 구현은 Codex(`gpt-6-astra`, high)가 했다.

## 리뷰에서 고친 것

- 복원(A128·A105)도 고정 경계를 보내고 있었다. 예전에 다른 경계로 등록한 로컬 파일 서버는 항상 `REG_RESTORE_BOUNDARY_DIFFERS`로 거절되고, 안내는 "서버 목록에 보이는 값으로 고르세요"인데 칸이 숨겨져 있어 고를 수 없었다.
  - 복원 중에는 Registry 행의 신뢰 경계·최대 수신 등급을 그대로 보낸다. 로컬 모드를 드나들어도 그 값을 지우지 않는다.
  - Registry 행에 경계가 없을 때만 고정값을 보낸다. 다르면 지금처럼 백엔드가 거절한다.
  - 명세의 "복원도 고정값을 보내고 거절되게 둔다"를 리뷰에서 바꿨다. 값은 앱이 가진 Registry 행에서 오며 모델·도구 출력이 아니다.
- 등록할 내용 미리보기에 남아 있던 `list_root_label` 줄을 지웠다. 공유 폴더 등급과 같은 값이라 중복이었다.
- 되돌림 검사에서 살아남은 두 경로에 시험을 더했다(아래 표 M10, A212 기록의 N5).

## 한계

- 하위 폴더의 바깥·겹침 판정은 경로 글자 비교다(Windows는 대소문자 무시). 심볼릭 링크·정션·실제 존재 여부는 지금처럼 C의 등록 검증이 판정한다.
- 같은 등급의 하위 폴더도 고를 수 있다. 요청이 "같거나 높은 등급"이었다.
- Registry 행에 경계가 없는 복원은 고정값을 보내고, 다르면 거절된다. 이때는 칸이 숨겨져 있어 화면에서 고칠 수 없고 서버 삭제(A208) 뒤 다시 등록해야 한다.
- 실제 앱에서 폴더 선택 대화상자로 확인하지 않았다.

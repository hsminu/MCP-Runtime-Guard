# A48 · 실제 Windows 키 저장과 재시작 표시

2026-10-29 · A · 관련 I9, T19·S04의 자격증명 화면 보조 확인.

## 한 일과 실제 검증

- 실제 Windows 데스크톱에서 제품 `main()`을 실행했다. 사용자가 Scanner 입력창에 기존 키를 직접 입력하고 저장했다. 원문을 채팅이나 검증 파일에 옮기지 않았다.
- 저장 전 C `scanner_key_tail()`의 결과가 None이었고, 저장 뒤 실제 자격증명 관리자 항목이 존재했다. 화면의 저장 성공·끝 4자리와 빈 입력창을 확인했다.
- 앱을 정상 종료한 뒤 새 프로세스로 실행했다. 설정 화면에 `저장된 키 · 끝 4자리 …`가 표시됐고 저장 직후와 일치했다. 재시작 시 키를 다시 입력하기 전의 화면을 확인했다.
- Codex 계정의 실제 로그아웃 정리 뒤에도 별도 Scanner 항목은 유지됐다. 두 저장 영역은 별개다.

## 한계

- Scanner 외부 API 호출·키 유효성 검증은 이 항목의 범위가 아니다. 검증한 것은 저장·재로딩·가림·끝자리 표시다.
- Codex 데스크톱 아래에서 기본 앱 경로가 패키지 LocalCache로 가상화됐다. 재시작 때 L2 경로 비교는 별도로 실패했으나 설정 화면과 Scanner 재로딩은 동작했다. 이를 하네스 통과로 세지 않았다.
- C 독립 인수와 T19·S04 전체 검증을 대체하지 않는다. 화면 근거는 이 작업의 Computer Use 관찰이며, 인증값·화면 캡처 파일은 저장하지 않았다.

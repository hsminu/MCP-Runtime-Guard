- 접근 규칙 표: 등록 도구와 허용·거부 쌍의 합집합을 서버·도구 순으로 보인다. 거부가 허용을 이기고, 둘 다 없으면 "규칙 없음 · 거부"(기본 거부), OTHER 종류는 "실행 불가 종류"다. 허용·거부는 모양과 글자가 있는 알약이다. 서버·상태(허용·거부·규칙 없음) 필터와 "n개 표시 · 전체 m개"를 둔다. "도구 허용 설정" 메뉴로 기존 `open_allow_dialog`에 들어간다(`server_buttons` 유지). 표시 이름은 `untrusted_display_text`를 거친다.
- 목적지 표: ID(mono), 신뢰 경계, 최대 수신 등급 태그, 사용 알약, 변경·삭제. 정책 미연결·목록 비어 있음(다음 동작 안내)·조회 실패를 서로 다른 상태로 보인다.
- 저장 상태: 요청 종류와 대상을 기억해 "목적지 X 저장·적용 중"처럼 진행을 보이고, 진행 중에는 다른 변경을 막는다. 결과는 기존 `CHANGE_RESULTS` 고정 문구와 알약(저장·적용됨 / 저장 안 됨 / 결과 미확인)으로 보인다. "변경됨" 표시는 성공 결과와 새 정책을 둘 다 받은 뒤에만 바뀐 행에 붙이고, 실패·미확인이면 붙이지 않는다. 정책 → 결과, 결과 → 정책 순서를 모두 처리한다.
- 목적지 대화상자(`ui/destinations.py`): 등급을 "공개 · PUBLIC"처럼 보이고(보내는 값은 그대로), 필수 입력 안내를 저장 버튼 옆 보조색 한 줄로 보인다.
- 검수에서 고친 점: 요약이 기본 거부 행을 "거부"에 합쳐 세던 것을 "허용 a · 거부 d · 규칙 없음 m"으로 나눴다. Codex가 `style.py` 끝에 `_SHEET +=`로 붙인 정책 글자 규칙을 스타일 표 안으로 옮겼다. 목적지 대화상자의 저장 줄을 위젯보다 먼저 붙였다(A178). 같은 검사에서 걸린 A185 `SectionCard`·A189 `SettingsPage`는 앞 커밋 `f4a26ad`에서 고쳤다.

## 한계

- 실제 프로필로 정책·목적지를 바꾸지 않았다. 차단·dispatch 계수는 이 화면 시험의 범위 밖이다.
- 표는 모든 행을 보인다. 행이 아주 많으면 페이지가 길어진다(가상화 없음). 긴 ID는 자르지 않아 좁은 창에서 표 가로 스크롤이 생길 수 있다.
- 삭제에 성공한 목적지는 행이 사라져 "변경됨" 표시를 붙일 곳이 없다. 결과 알약과 바뀐 목록으로만 보인다.
- 필터는 화면이 받은 정책 전체에 적용된다(정책은 한 번에 다 받음).

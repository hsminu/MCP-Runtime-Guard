# A135 · 실행 컨트롤 안내의 내부 코드를 접힌 줄로 내림(#52 C 리뷰 UI 3)

2026-10-28. C가 [#52 리뷰](https://github.com/hsminu/MCP-Runtime-Guard/pull/52#issuecomment-6463307897)에서 UI 제안 세 가지를 냈다.

- 1(옆 패널 승인 사본 폭)과 2(사본의 `\n` 표시)는 A131에서 처리했다. 승인 사본을 한 필드 한 줄로 나누고, 구분 줄바꿈을 실제 줄바꿈으로 잇는다.
- 이 기록은 3번이다. 실행 컨트롤의 모든 안내 문구 아래에 "내부 코드: …"가 붙어 있었다. 시연·평가에는 코드가 필요하니, 지우지 말고 접는 상세 영역으로 내리자는 제안이었다.

## 한 일

- `ui/runtime.py`의 실행 컨트롤 안내(`RuntimePanel.message`)에는 이제 문구만 보인다.
- 코드는 그 아래 "내부 코드 ▸" 링크 버튼으로 접어 둔다.
  - 누르면 "내부 코드: READY" 같은 줄이 펼쳐지고 버튼은 "내부 코드 ▾"가 된다.
  - 등록 화면의 접는 절(`add_section`)과 같은 모양이고, 접근성 이름도 같은 방식(펼치기·접기)이다.
  - 코드가 없는 안내("실행 요청됨 · 백엔드 결과 대기" 등)에서는 버튼도 숨긴다.
  - 한 번 펼치면 다음 안내에서도 펼친 채로 둔다. 시연 중에 매번 다시 누르지 않아도 된다.
- 세션마다 마지막 안내를 (문구, 코드) 쌍으로 기억한다. 다른 세션을 골랐다가 돌아오면 그 세션의 문구와 코드가 함께 돌아온다.
- 키보드
  - 탭 순서는 실행 버튼 → 내부 코드 → 승인 버튼들이다. 화면 위치와 같다.
  - Enter 기본 버튼이 되지 않는다.
  - 포커스가 있는 버튼이 숨겨질 때는 포커스를 읽기 전용 사본 상자로 옮긴다. 그냥 숨기면 Qt가 다음 버튼으로 포커스를 넘긴다. 그 버튼은 "작업 취소"일 수 있다(QA Q06과 같은 이유).
- 코드 값과 안내 문구는 바꾸지 않았다. bridge가 보내는 고정 코드만 보이고, 원문·예외 문구는 여전히 없다.

## 검증

- `tests/unit/test_runtime.py`
  - 기존 테스트 8곳: 안내 문구에 코드가 없고, 코드는 `internal_code`에 같은 값으로 있다. 시작 실패의 `RAW_MARKER`는 여전히 문구에 없다.
  - 새 테스트 `test_internal_code_is_folded_under_the_message_and_follows_the_session`
    - 처음에는 버튼과 코드가 모두 숨어 있다. READY를 받으면 버튼만 보이고 코드는 접혀 있다.
    - 누르면 코드가 보이고 글자·접근성 이름이 바뀐다. 다음 거절 안내(`NOT_READY`)에서도 펼친 채다.
    - 버튼에 포커스가 있을 때 코드 없는 안내("메시지 요청됨")가 뜨면, "작업 취소"가 켜져 있어도 포커스는 사본 상자로 간다.
    - 안내가 없는 세션에서는 버튼이 숨고, 원래 세션으로 돌아오면 그 세션의 문구와 코드가 돌아온다.
  - 포커스 옮기기를 뺀 변형으로 돌리면 새 테스트가 실패한다. 포커스가 버튼으로 넘어간다.
- `tests/unit/test_ui_sessions.py`: 다른 세션의 거절 코드는 선택한 세션의 코드 줄에 나오지 않는다. 그 세션을 고르면 코드 줄에 나온다.
- 오프스크린 캡처(376px, 라이트·다크)로 접힘·펼침을 눈으로 확인했다.
- 전체(`QT_QPA_PLATFORM=offscreen`, Windows, 로컬 `.venv`)
  - 단위 5,203개 통과, 4개 skip, subtest 20개, 실패 없음(경고 1개는 A02·A06 기록의 서드파티 경고와 같다)
  - contract 42개 통과
  - ruff check·ruff format --check(238개 파일)·mypy(102개 소스 파일) 통과

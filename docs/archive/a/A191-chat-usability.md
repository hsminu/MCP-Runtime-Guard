## 한 일

- 입력(`ui/composer.py` `MessageDraft`): Enter·Ctrl+Enter는 보낼 수 있을 때만 전송, Shift+Enter는 줄바꿈, IME 조합 중(preedit가 있는 동안) Enter는 입력기에 넘김, 길게 누른 Enter 반복은 무시. 입력칸은 2–8줄까지 자라고 그 뒤로는 안에서 스크롤한다. 평문만 붙여 넣고, 파일·URL만 끌어다 놓으면 "파일 첨부는 지원하지 않음…"을 알린다. 세션별 초안은 기존처럼 메모리에만 있다.
- 답변 블록(`ui/answer_blocks.py` 파서, `ui/answer_widgets.py` 위젯): 문단·제목·목록·인용·코드(닫히지 않은 울타리 포함)·표 모양·구분선을 나눠 PlainText 위젯으로만 그린다. HTML·Markdown 엔진·링크 실행·원격 자원은 쓰지 않고, 짝이 맞는 `**`·`__`만 지운다. 코드 블록은 언어 이름·복사 버튼·읽기 전용 고정폭 칸(20줄 넘으면 안에서 스크롤)이다. 스트리밍 중에는 바뀌지 않은 앞 블록을 다시 쓴다.
- 복사: 사용자 메시지·답변·코드 블록마다 복사 버튼, 1.5초 "복사함" 표시. 복사는 화면에 보인 글자만 넘긴다.
- 스크롤: 위쪽을 읽는 중에는 새 답변이 와도 끌어내리지 않고 "최신 메시지로 이동" 버튼(새 내용 표시)을 띄운다.
- 입력 상태 알약(`session_projection.py`): 입력 가능·응답 중·승인 필요·연결 필요·종료됨 등을 백엔드 상태와 명령 결과로만 정한다.
- 중지: 메시지·실행 명령이 처리 중일 때만 전송 버튼 자리에 "작업 중지"를 보인다(`RuntimePanel.turn_scopes`). 확인 창은 "Task가 정지되어 더 보낼 수 없음", "이미 전송된 쓰기와 외부 작업은 취소되지 않음", "모델 답변만 멈추는 기능은 아직 없음"을 알린다. A188의 `stop_task`로 그 Task·epoch에 CANCEL만 보내고, 게시된 상태가 종료일 때만 "작업 정지를 확인함"을, 아니면 "확인하지 못함"을 보인다.
- 모델 표시(`session_model.py`): 시작 뒤에는 Task가 알려 준 `model_id`를 보이고, 없으면 "모델 확인 전"이다. 요청한 모델과 적용된 모델이 다르면 툴팁에 둘 다 적는다.
- 승인 카드: 승인 대기 띠에 도구·서버·수신처·사유·만료 시각과 현재 Task 등급 태그를 보인다. 요약은 `StoreQueryLink.lookup_session_approval`이 음수 토큰으로 승인 목록을 조회해 승인 ID가 정확히 같은 행만 쓰며, 실패하면 "요청 요약을 불러오지 못함"을 보인다. 승인은 기존 "승인 사본 확인" 검토 흐름으로만 한다.
- 단축키(`window.py`): Ctrl+N 새 세션, Ctrl+K 세션 검색(좁은 창은 메뉴의 검색), Ctrl+L 입력칸.
- 검수에서 고친 점: 입력 상태 줄 레이아웃을 위젯보다 먼저 붙였다(A178, `test_a178_qt_ownership.py` 2건 실패 → 통과).

## 백엔드 미지원으로 넣지 않은 것

- 파일 첨부와 끌어다 놓기 첨부: 메시지 명령에 첨부 필드가 없다. 넣는다면 B의 메시지 명령에 첨부 참조와 등급 판정 경로가, C의 경로 검사가 필요하다.
- 응답 다시 만들기: 같은 턴을 다시 돌리는 명령이 없다. 보내기·쓰기 도구를 몰래 다시 부르지 않도록 B의 재실행 계약(도구 재호출 금지 또는 승인 재요구)이 먼저 필요하다.
- 모델 답변만 멈추기: 턴 단위 중단 명령이 없어 Task CANCEL만 쓴다. B·A의 턴 중단 명령이 있으면 Task를 살린 채 멈출 수 있다.

## 한계

- 실제 Windows 한글 IME와 물리 키보드로는 확인하지 않았다. preedit·commit 합성 이벤트만 썼다.
- 실제 모델 스트리밍의 긴 답변 성능은 재지 않았다. 스트리밍 중 바뀌는 꼬리 블록은 다시 만들어져 그 블록의 선택·가로 스크롤이 처음으로 돌아갈 수 있다.
- 승인 요약은 승인 목록의 접두 검색으로 찾는다. 대기 승인이 아주 많으면 첫 5행 안에 없을 수 있고, 그때는 요약 없이 검토 버튼만 남는다.
- 숨은 문자는 기존 `untrusted_display_text` 표기(`‮` 꼴)를 따른다. 설계 예시의 `⟦U+…⟧` 표기와는 다르다.

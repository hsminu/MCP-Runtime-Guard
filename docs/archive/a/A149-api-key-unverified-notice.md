## 한 일

- `presentation.py`의 `CODEX_LOGIN_TEXT["api_key_saved"]`를 “API 키를 저장함. 첫 요청에서 키를 확인함.”으로 정의하고 `model_settings.py`의 API_KEY 상태에서 사용한다. 새로 입력한 키의 끝 4자리를 붙이는 분기는 `api_key_saved_suffix`(“API 키를 저장함 · 끝 4자리 NNNN. 첫 요청에서 키를 확인함.”)로 같은 안내를 유지한다. Scanner 키 화면의 “저장함 · 끝 4자리” 형식과 맞췄다. 계정 조회로 복원한 키도 확인 전 안내를 표시한다.
- `CODEX_AUTH_FAILED_NOTICE`를 같은 문구 모듈에 정의하고 `sessions.py`의 기존 인증 실패 분기에서 참조한다. 문구는 다음과 같다.

> API 키가 틀렸거나 Codex 인증이 만료되거나 갱신되지 않아 이 Task를 정지함. 실행 중인 세션을 모두 끝내고 설정에서 로그아웃한 뒤, API 키 입력란에 올바른 키를 입력해 다시 로그인하세요. 새 세션에서 다시 시작하세요.

- 로그인 상태에서는 키 입력이 비활성이고 실행 세션이 있으면 로그아웃이 거부되므로, 실제 화면 동작에 맞춰 세션 종료·로그아웃·키 입력 순서를 안내했다. 원인을 틀린 키 하나로 단정하지 않는다. 상태는 음슴체, 사용자의 다음 행동은 하세요체다.
- 키 검증 API·새 상태·재시도를 추가하지 않았다. API_KEY 상태 자체는 Codex 계정 유형이며 키 검증 성공을 뜻하지 않는다. 키 가림·전송 직후 비우기·끝 4자리 표시·HALTED 전송 비활성은 유지한다.

# A209 · 결과 · 실행 활동을 선택된 세션 아래 하위 줄로

2026-10-30 · `wip/next` · PR #110. 출처: 사용자 요청("결과 실행 활동이 현재 선택된 세션 밑으로 이동하면 좋을 거 같다 ... ㄴ 형태로").
관련: A206·A208(같은 날 서버 화면), A178(Qt 소유).

## 이유

"승인 대기"는 모든 세션을 모아 보여 주지만 "결과 · 실행 활동"은 선택된 세션 하나의 화면이다. 그래서 결과 항목을 사이드바 위쪽 공통 버튼에서 세션 목록의 하위 줄로 옮겼다.

## 한 일

- 사이드바 위쪽 버튼은 "대화"·"승인 대기" 둘이다. 축소 화면 메뉴에는 "결과 · 실행 활동"이 그대로 있다.
- 세션 목록에서 현재 세션 줄 바로 아래에 하위 줄이 하나 생긴다.
  - ㄴ자 연결선, 패널 아이콘, "결과 · 실행 활동" 글자로 그린다. 높이는 32이고 세션 줄은 52 그대로다.
  - 누르거나 Return을 치면 그 세션의 결과 화면이 열린다.
  - 결과 화면이 열려 있으면 하위 줄이 강조되고 현재 항목이 된다.
- 결과 화면에서 다른 세션을 고르면 결과 화면이 유지된다. 하위 줄은 새 세션 아래로 옮겨 간다(기존 동작).
- 하위 줄에는 세션 키가 없다.
  - F2·Delete·메뉴 키·컨텍스트 메뉴·more 영역은 하위 줄에서 세션 조작을 부르지 않는다.
  - 검색은 세션 줄 글자만 본다. 현재 세션 줄이 검색으로 숨으면 하위 줄도 숨는다.
- 헤더 "활동" 버튼(대화 옆 도킹)은 바뀌지 않았다.
- 구현은 Codex(`gpt-6-astra`, high)가 했다.

## 검토에서 고친 것

- 되돌림 검사에서 하위 줄 세션 조작 차단 5곳(F2·Delete·메뉴 키·컨텍스트 메뉴·more 영역)을 빼도 시험이 통과했다. 하위 줄에 세션 키가 없어 세션 함수가 조용히 무시했기 때문이다.
- 시험에 세션 조작 감시(`rename_session`·`delete_session`·`open_menu` 호출, 델리게이트 `menu_requested`)를 넣었다. 이제 5곳 모두 시험이 잡는다.

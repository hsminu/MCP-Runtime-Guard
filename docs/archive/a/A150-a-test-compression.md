2026-10-29. `docs/a-status.md` A150. 1차는 [#82](https://github.com/hsminu/MCP-Runtime-Guard/pull/82)로 올렸고 2차는 다음 PR에 올린다(PR 미정).

## 한 일

- **1차(`8dcef48`, #82):** 같은 모양 시험을 매개변수 표·반복·subtest로 묶었다. 다른 시험이 같은 단언을 이미 지키는 시험은 지웠다. `test_scan_status.py`·`test_server_add_folders.py`를 `test_server_add.py`에 합쳤다. 정적 규칙 시험은 위반을 모두 모은 뒤 단언한다. 이 단계에서 A 시험 수집은 1,665 → 723개(+subtest 354개), 줄 수는 25,114 → 23,789줄이 됐다.
- **2차(이 기록의 커밋):** A 시험 파일 66개를 8묶음(h1–h8)으로 나눠 줄 수를 줄였다. 1차 뒤에 생긴 A49·A105·A116·A138·A143·A151·A153·A155·A156 시험도 포함한다. 줄 수는 28,370 → 26,781줄(−1,589줄, 5.6%)이다. 고친 파일은 65개다. 제품 코드·B·C 시험·`conftest.py`·`pyproject.toml`은 고치지 않았다.
  - 방법:
    - 반복되는 준비·정리 코드를 도우미로 뺐다.
    - 쓰이지 않는 가짜 메서드·import를 지웠다.
    - 같은 객체의 여러 속성 단언을 튜플·dict 비교 하나로 묶었다.
    - 코드를 되풀이하는 주석을 줄였다.
    - magic trailing comma로 펼쳐진 짧은 호출을 접었다.
    - 일부 subtest와 내부 check 함수를 pytest 매개변수로 바꿨다.
  - 지우거나 합치거나 이름을 바꾼 시험 함수는 없다. 매개변수로 바꾼 시험은 같은 이름에 사례 ID가 붙는다.
  - 수집 수는 925 → 1,056개로 늘었다. h2(129 → 199)와 h5(108 → 167)에서 subtest·check 함수를 매개변수로 바꿔 사례가 따로 수집되기 때문이다. subtest는 줄었다(h5 133 → 47).
  - h7은 A105 저장 실패 시험에 설정 파일 교체 실패 사례를 더했다(`settings_io._MoveFileExW`가 0을 돌려줌 → `POLICY_SAVE_FAILED`, Guard 차단, 재시도 없음). 이 사례로 수집 수가 154 → 156개가 됐다. 압축 전에는 아래 간헐 실패 때만 실행되던 파일 교체 실패 처리 12항목이 이제 항상 덮인다. C 소유 모듈의 내부 이름을 패치하므로, 그 이름이 바뀌면 이 사례도 고쳐야 한다.
- **목표 30%는 미달이다.** 묶음별 감소율은 2.6–8.0%다. 작업자 보고의 이유는 두 가지다.
  - 1차에서 이미 표·도우미로 묶인 파일이 많다.
  - 남은 줄 대부분은 시점·순서가 다른 상태 전이를 시나리오마다 따로 단언하는 본문이다. 승인 경합, 응답 중 종료, epoch 변경, 저장 실패 경로마다 다른 재시작·재시도 의미가 여기에 든다. 이를 큰 조건부 도우미 하나로 합치면 단언의 뜻이 흐려져서 하지 않았다.

- 압축 전 h7 기준선에서 `test_a105_activation.py::test_first_registration_file_can_activate_without_assembled_guard`가 한 번 `POLICY_SAVE_FAILED`로 실패했다. 같은 코드로 단독 3회, 묶음 커버리지 실행 2회를 다시 돌렸고 모두 통과했다. 통과한 재실행을 기준선으로 삼아 다시 비교해도 손실은 0이다. 원인은 미확정이다. 설정 파일 교체가 순간적으로 거절된 것으로 보이며, 제품 코드는 fail-closed로 저장 실패를 냈다.
- 66개 파일을 함께 돌리면 `test_stdio_logging.py::test_malformed_stdio_and_notifications_are_contained`가 로그 가림이 켜진 상태에서 실패한다.
  - 압축 전 코드(같은 파일 66개)에서도 같은 실패가 났으므로 2차 압축이 만든 문제는 아니다.
  - 시험마다 `redact._active`와 log record factory를 비교하는 pytest 플러그인으로 원인을 찾았다. `test_mcp_launcher_pipes.py::test_main_settings_start_uses_launcher_folders`가 실제 `main()`을 부른 뒤 로그 가림을 켠 채 끝난다.
  - 이 원인은 [A157](A157-pr83-c-review-followups.md)이 `feat/a-application`(#83) 커밋 `0e33404`에서 그 시험에 `preserve_logging_state`를 붙여 고쳤다. 이 커밋의 기준(`e587fd8`)에는 아직 그 수정이 없다.
- 압축 전 h6 측정과 압축 전 코드의 66개 묶음 실행은 시험 결과와 별개로 종료 코드 127로 끝났다. 원인은 미확정이다.
- 묶음 검증 스크립트의 Ruff 단계는 worktree에 없는 상대 경로를 써서 실패했다. 그래서 Ruff는 따로 실행했고, 스크립트는 절대 경로로 고쳤다(저장소 밖 작업 도구).
- 제품 동작은 바뀌지 않았으므로 고의 회귀 대조는 새로 하지 않았다. 작업 지침은 회귀 대조에 쓰인 시험의 병합만 허용하고 약화는 금지했다. 단언 약화는 커버리지로 잡히지 않으므로 리뷰로 확인했다.

# A181 · C6.14-2 병합 뒤 A151 L2 두 항목 닫기

2026-10-30 · `wip/next`(main `e0f08b3` 기준). PR: 다음 A PR(아직 없음)
관련: A151, [A161](A161-msix-l2-path-observation.md), [A162](A162-real-run-display-followups.md), [A168](A168-msix-l2-host-check.md), [C6.14-2](../c/C6.14-2-l2-real-runs.md)(#98), T22. A 코드 변경 없음.

## 문제

A151의 L2 미완료 두 줄은 C 수정을 기다렸다.

- 기본 제품 MSIX 경로의 L2 성공 재확인: Codex 데스크톱 안에서는 `%LOCALAPPDATA%`가 앱 패키지 경로로 가상화된다. C `_check_config`가 논리 경로와 Codex가 보고한 물리 경로를 문자열로 비교해 `L2_CONFIG_LAYERS_UNEXPECTED`·`L2_CONFIG_MISMATCH`로 실패했다(A161·A168).
- 실제 L2 간헐 실패: A 제품 시작 경로 8회 중 1회 `L2_PROBE_CALLS_UNEXPECTED`(A162, #21 알림).

## 한 일

- C6.14-2(#98, main `e0f08b3`)를 확인했다.
  - 경로: 같은 파일인지로 비교한다. 정션 별칭은 통과하고 다른 파일은 실패한다.
  - 간헐 실패 원인: Codex가 한 응답의 두 검사 호출을 겹치지 않게 보내지만 가끔 순서를 바꾼다. C 판정이 순서를 요구해 거짓 실패가 났다. 이제 순서는 보지 않고 두 호출이 정확히 한 번씩인지만 본다. 겹침은 `L2_PROBE_CALLS_OVERLAP`으로 나눈다. C는 실제 L2 120회를 통과시켰고, 그중 순서가 바뀐 1회도 통과로 판정됐다.
  - A가 본 `L2_PROBE_CALLS_UNEXPECTED` 1회는 이 순서 바뀜과 같은 코드·같은 경로다. A 쪽 원인은 따로 없어서 C 답으로 닫는다.
- main에서 MSIX 경로 L2를 다시 돌렸다. 아래 검증.
- `docs/a-status.md`의 두 줄을 완료로 바꾸고 이 기록을 연결했다.

## 검증

Codex 데스크톱 패키지 안의 셸, Windows, 로컬 `.venv` Python 3.12, 고정 codex.exe 0.162.1(C `run_l2`의 로컬 가짜 모델). 제품 시작 경로(`CodexProcessPreparation.claim()` → `preparation().prepare_startup()`)를 시험용 앱 폴더 `%LOCALAPPDATA%\MCPRuntimeGuard-a151-probe`로 돌렸다. 실제 앱 폴더는 고정 codex.exe를 읽기만 했다. 실행마다 논리 경로와 resolve한 물리 경로를 한 번씩 썼고, 끝나면 시험용 폴더를 지웠다. 출력은 고정 코드·bool·초만 남겼다.

| 회차 | 시험용 폴더가 패키지 경로로 가상화됨 | 논리 경로 L2 | 물리 경로 L2 | 폴더 정리 |
| --- | --- | --- | --- | --- |
| 1 | 예 | 통과, 실패 코드 없음, 1.281초 | 통과, 1.223초 | 예 |
| 2 | 예 | 통과, 1.218초 | 통과, 1.194초 | 예 |
| 3 | 예 | 통과, 1.215초 | 통과, 1.198초 | 예 |

A161·A168에서는 같은 논리 경로가 두 코드로 실패했다. 이번에는 6회 모두 통과했다.

## 남은 것

- 실제 데스크톱 앱 창에서 Task 시작 버튼이 켜지는지는 이번에 화면으로 확인하지 않았다. 시작 영수증의 L2 통과까지만 봤다.
- 간헐 실패는 C가 순서 바뀜 회차를 포함해 120회 통과로 확인했다. A는 같은 횟수를 다시 돌리지 않았다.
- C6.14-2가 지적한 "같은 응답의 SEND 판정은 호출 순서에 따라 달라질 수 있다"는 Guard 동작 설명이며, 이번 항목 범위 밖이다.

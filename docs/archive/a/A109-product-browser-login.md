# A109 · 제품 브라우저 로그인 활성화

2026-10-29. 관련: I6·I9·I11, T19·T43·S04의 A 단위 보조 검증, 개발문서 10.4·12절, C2.21(#77), A109·A142 기록. PR: 미정.

## 한 일

- 제품 시작 `_run()`에서 `codex.account_access(open_browser=open_login_browser)`를 호출한다. C의 공개 모듈 객체는 `make_login_opener()`가 만든 비동기 callable이며 그대로 전달한다. 시연·직접 조립의 기본 계정 경로는 바꾸지 않았다.
- `BROWSER_OPEN_FAILED` 안내를 “로그인 페이지를 열지 못해 요청을 취소함. 기기 코드 또는 API 키로 로그인하세요.”로 바꿨다. 상태는 음슴체, 안내는 하세요체다.
- 기존 버튼 로직은 실패 뒤 기기 코드·브라우저·API 키 입력을 다시 허용하므로 수정하지 않았다. API 키 버튼은 빈 입력에서는 꺼지고 키 입력 뒤 켜진다.
- 기존 제품 시작 시험에서 전달된 `AccountAccess.open_browser`가 C 공개 callable과 같은 객체인지 확인한다.
- 새 Qt 시험은 가짜 app-server·열기 실패 대역을 실제 bridge와 화면에 연결한다. 제품에 대응하는 브라우저 사용 가능 상태에서 버튼을 눌러 실패를 만들고, 취소 RPC 1회·FAILED 안내·대체 버튼 활성·취소 버튼 비활성을 확인한다. 계정/명령/수명주기 이벤트·화면 라벨·캡처 로그에 로그인 URL이 없음을 확인한다. 기존 A109 비노출·취소·세대 검사 시험도 유지했다.

## 실제 검증

- A146과 같은 변경 묶음이다. 정확한 실행 명령·환경은 [A146 검증 기록](A146-log-redaction-install.md)에 있다.
- 관련 시험 10개 파일: 최종 113 통과, 서브테스트 40 통과, 9.52초.
- 변경 Python 7개 파일 Ruff check·format check 통과. 전체 mypy 114개 소스 통과. import-linter 7개 계약 유지. `git diff --check` 통과.
- 전체 단위·contract·실제 브라우저·실제 로그인·모델 호출·S02 URL 함정 독립 검증은 미실행이다. C URL 검증기를 복제하거나 새로 시험하지 않았다.

각 회귀를 넣고 해당 시험 노드만 실행했다. 매번 원래 파일 바이트를 `finally`에서 복원하고 일치까지 확인했다.

| 고의 회귀 | 시험 결과 |
| --- | --- |
| 제품 `account_access()`의 opener 인자 제거 | 기존 제품 시작 시험의 새 객체 동일성 검사 실패 |
| 실패 안내를 “다시 시도하세요”로 되돌림 | 새 Qt 시험의 대체 로그인 안내 검사 실패 |
| `BROWSER_OPEN_FAILED`에서 기기 코드 버튼 끄기 | 새 Qt 시험의 실패 후 버튼 검사 실패 |
| API 키 버튼을 항상 끄기 | 새 Qt 시험의 키 입력 후 버튼 검사 실패 |

## 남은 한계

- 사용자 실제 PC에서 브라우저 로그인 완료·실패 안내를 확인하는 절차는 미실행이다. Qt offscreen 대역 검증을 실제 로그인 성공으로 간주하지 않는다.
- C2.21의 취소 한계는 유지된다. 이미 시작한 OS 열기는 취소 직후에도 브라우저를 열 수 있다. Codex 로그인 취소·프로세스 정리는 기존 A109·A142 경로가 담당한다.
- #77 A 리뷰 댓글 원문은 GitHub 연결 도구 404, 웹 조회 실패, 로컬 gh 네트워크 거부로 읽지 못했다. 현황 문서·사용자 지시·C2.21·A109·A142 기록과 현재 코드를 읽고 구현했다. 원문 확인은 남는다.
- 공통 문서의 로그인 방식 확대 반영은 기존 A109 기록의 별도 사항이다. B/C API·공통 계약·현황 문서를 수정하지 않았고, 새 B/C 구현 요청은 없다.

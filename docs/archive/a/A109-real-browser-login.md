# A109 · 실제 브라우저 로그인 완료와 재시작 유지

2026-10-29 · A · 관련 I9·I11, 개발문서 10.4·12절, T43 계정 준비 경로 보조 확인. 계약 변경 없음.

## 한 일과 실제 검증

- 실제 Windows 제품 창에서 기존 로그인 요청을 취소하고 `로그인 요청을 취소함`·SIGNED_OUT을 확인한 뒤 새 브라우저 요청을 열었다. 브라우저 인증은 사용자가 직접 완료했다.
- 첫 시도에서 사용자가 `invalid_auth_step`을 보고했다. 원인은 확정하지 않았다. 같은 요청을 반복하지 않고 취소 후 새 요청으로 완료했다. 요청 식별자·인증 URL·인증 원문은 기록하지 않았다.
- 완료 뒤 실제 Codex 0.162.1의 `account/read`가 CHATGPT를 반환했고 제품에 `ChatGPT 계정으로 로그인되어 있음`이 표시됐다.
- 정상 종료 뒤 새 제품 프로세스에서도 CHATGPT를 재확인했다. 정상 종료는 Codex 암호문·primary 자격증명을 유지하고 계정 프로세스·Task 폴더를 정리했다.
- `BROWSER_OPEN_FAILED` 대체 안내는 사용자가 이번 요청 전에 실제 확인했다고 제공한 근거다. 이번 실행에서 다시 재현한 것으로 세지 않았다.

## 근거와 한계

- [완료된 관찰 JSON](../evidence/A109-A151-A52-real-login.json)의 `canonical-invalid-key-fixed`, `canonical-chatgpt-startup-1`, `canonical-chatgpt-logout-2`에서 상태 전환·재시작 유지·이후 로그아웃을 확인할 수 있다.
- C 소유 L2 기본 경로 비교 문제는 [A161](A161-msix-l2-path-observation.md) 그대로 남겼다. 같은 물리 앱 폴더의 정규 경로를 기존 준비 객체 인자로 지정했으며 실제 계정 프로세스와 L2 평가를 대체하지 않았다.
- ChatGPT 계정 로그인 성공을 확인한 것이며 ChatGPT 구독을 이용한 모델 요청은 이번 항목에 포함하지 않는다. 실제 모델 첫 요청은 별도 API 키 시나리오 [A149](A149-live-first-request.md)에서 확인했다.
- T43 전체 인수와 C 소유자 승인은 별도다. 제품 코드 추가 변경 없음.

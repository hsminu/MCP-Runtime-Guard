# A128 · 실제 데스크톱 등록과 EXE-01 표시

2026-10-29 · A · 관련 I1·I6·I7·I10, EXE-01·CFG-01, T18·T29의 등록 화면 확인.

## 한 일과 실제 검증

- 제품 `main()`의 실제 Windows 창에서 설정 붙여넣기 → 경계·등급 선택 → 등록 내용 확인 → 등록을 수행했다. offscreen이나 등록 서비스 대역을 쓰지 않았다.
- 서버 `desktop-verify`는 저장소의 `examples/stdio_spike_server.py`를 `.venv/Scripts/python.exe`로 실행하는 합성 stdio MCP 서버다. 내부 경계·최대 PUBLIC으로 PENDING 등록했고, Profile 선택 서버는 빈 목록으로 유지됐다.
- EXE-01 확인 영역에서 실행 파일 경로, 크기 **262144 bytes**, SHA-256 **00971a1ef67279e9234086dcffa881322478f80d40366bd7d2d16f56a9f08b07**, 인터프리터만 지문에 포함된다는 한계가 실제로 보였다.
- 별도로 계산한 파일 크기·SHA-256과 표시값이 일치했다. 등록 후 설정 파일의 `command_size`·`command_sha256`도 일치했다.
- 화면에 `Registry 등록·설정 저장 완료 · PENDING. 검사·활성화 전에는 실행되지 않음.`이 표시됐다. 후속 재시작에서 저장된 설정을 정상 로드했다.
- 등록 전후 합성 수신 계수 `receiver_calls=0`, `receiver_effect=0`을 확인했다. 실제 launcher·SDK의 목록 조회를 사용했으며 도구 실행을 요청하지 않았다.

## 한계와 남은 것

- 합성 서버를 실제 프로세스로 실행한 등록 검증이다. 외부 제3자 서버 인수나 독립 wire 계수 시험으로 일반화하지 않는다.
- Scanner 검사·활성화, 변경된 exe의 재확인, 설정 저장과 Registry 중 하나만 성공한 복구 UI는 별도 항목이다.
- 검증용 서버는 앱 설정에 PENDING으로 남아 있고 접근 허용·Profile 선택에는 넣지 않았다. 앱 자체는 정상 종료했다.
- 실행 파일 지문은 스크립트·패키지를 보호하지 않는다. 실제 C 담당자의 독립 인수는 별도다.

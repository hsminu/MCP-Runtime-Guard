# A124 · 가짜 조회 데이터로 전 화면을 눌러 보는 시연

2026-10-28. 팀원이 백엔드 조회 계약 없이도 모든 화면을 직접 눌러 볼 수 있도록 `examples/ui_demo.py`를 만들었다. 실행 방법은 저장소 루트에서 `uv run python -m examples.ui_demo`다.

## 한 일

- **실제로 도는 부분.** 대화의 실행·승인 사본 확인·승인·거절·작업 취소·긴급 차단은 기존 합성 백엔드(`examples.synthetic_app`, ASK 시나리오)를 그대로 쓴다.
- **가짜 데이터로 답하는 부분.** 조회 계약이 아직 없는 화면은 창의 기존 입력 함수와 요청 신호에 고정된 가짜 행으로 답한다.

  | 화면 | 가짜 데이터 |
  | --- | --- |
  | 현황 | 합계, 확인 항목 6개, 최근 호출, 12시간 흐름 |
  | MCP 서버 | 서버 5개(등록·세션·경계·등급 조합), 서버별 검사 상태 |
  | 호출 로그 | 16건(판정·상태·사유 조합), 상태별 처리 단계 |
  | 승인 대기 | 대기 3건·이력 11건. 검색·서버 필터·정렬·페이지를 실제 조회처럼 처리 |
  | 정책 · 경계 | Profile, 접근 규칙, Codex 제외 도구 1개. 저장하면 가짜 규칙만 바뀜 |
  | 설정 | Codex 로그인. 기기 코드 → 4초 뒤 로그인됨, API 키 로그인, 로그아웃 |

  - 조회 응답은 0.25초 뒤에 보내서 불러오는 중 상태도 보인다.
  - 합성 백엔드는 정책·계정 정보가 없어 시작할 때 이 화면들을 비운다. 그래서 시연은 bridge의 `policy_changed`·`account_changed` 연결을 끊고 직접 답한다.
- 실제 Registry·Store·Codex에는 아무것도 보내지 않는다. 창 제목에 "화면 시연 / 가짜 조회 데이터"를 표시한다.
- 합성 백엔드의 `agt_mode` 인자는 시그니처에 있을 때만 넘긴다. #47로 인자가 없어져도 그대로 실행된다.

## 검증

- `tests/unit/test_ui_demo.py` 6개:
  - 모든 관리 화면이 채워짐
  - 승인 조회의 lane·검색·서버·정렬·페이지
  - 상태별 처리 단계
  - 호출·서버 상세가 열린 창에만 답함
  - 정책 저장·로그인이 가짜 행만 바꿈
  - 합성 백엔드 시작 인자
- 합성 백엔드로 실제 시작해 `ready`까지 간 뒤, 정책·계정 화면이 시연 값으로 남는 것을 확인했다. 현황·서버·로그·승인·정책·설정·대화 옆 패널·호출 상세·서버 상세를 라이트·다크로 캡처해 확인했다.
- 전체 테스트(`QT_QPA_PLATFORM=offscreen`, `tests` 전체): 4,874 통과, 4 skip, subtest 20. 실패 1개는 C 소유 `test_paths.py::test_app_root_is_under_local_app_data`이고 이 변경 전부터 실패했다.

## 남은 것

- 가짜 데이터는 고정이다. 실제 조회 계약(A28–A35)이 생기면 그 DTO 모양에 맞춰 다시 확인해야 한다.
- 합성 백엔드의 Task는 하나다. 합성 구성에는 새 세션 생성(`create_session`)이 연결되어 있지 않아서, 새 세션을 시작하면 "새 Task 생성 기능이 연결되지 않음" 안내가 나온다.

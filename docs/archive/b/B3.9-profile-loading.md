# B3.9 · 설정·Profile 로딩 1단계와 policy_version

## 한 일

- `services/catalog.py`에 파일을 열지 않는 `load_profile_settings()`를 추가했다. 이미 파싱한 JSON 형태 Mapping을 strict·extra forbid·frozen Pydantic 모델로 검증하고, Profile·Catalog·AccessRules·Guard 설정값과 C 검증용 서버 설정 사본을 반환한다.
- 정책·Profile·목적지·서버·접근 규칙 전체를 기본값까지 포함해 정규화하고 기존 `jcs_canonicalize()`와 `digest()`로 SHA-256 정책 버전을 계산한다. 접근 규칙 입력에는 기존 `normalize_access_rules()` 결과를 사용한다.
- 알 수 없는 필드, 잘못된 타입·등급·연결 조합, 중복 서버/목적지/Profile 참조/서버 내 도구 ID, 없는 서버·도구·목적지 참조를 거부한다. 모든 서버 ID와 접근 규칙의 서버 ID에 `valid_server_id()`를 적용한다. `AccessRules.is_valid=False`도 로딩 실패다.
- 기존 Boundary 검증을 사용해 외부 서버·목적지의 수신 상한은 INTERNAL 이하로 제한한다. 설정 입력 오류는 원문 없는 `CatalogConfigError`로 전달하고, 반환 객체·서버/도구 설정의 repr·str은 가린다. 넓은 예외 처리 경계는 추가하지 않았다.
- 로더가 붙이는 읽기 전용 Registry 래퍼로 Profile 밖 서버와 설정 밖 도구를 숨긴다. 현재 등록의 서버 경계·도구 종류·인자 지정이 설정과 다르면 차단한다. Registry의 현재 ACTIVE 상태·지문 검사는 기존 Catalog에 그대로 맡긴다. 등록이나 활성 상태를 새로 만들지 않는다.
- Profile이 선택한 목적지만 Catalog에 넣는다. 출처 규칙은 기존 SourceRule·SourceClassifier를 사용한다. 자원형 READ는 C 검증 결과를 반환할 기존 ResourceResolver가 연결되지 않으면 계속 차단된다.
- B3.9의 B 구현을 완료하고 파일 형식 결정·C 검증·A 시작 연결은 B3.11로 분리했다. 기존 Catalog 클래스의 AST, domain·ports·Guard·A/C 소유 파일·의존성·공유 문서는 변경하지 않았다. B3.10 정책 변경 명령은 구현하지 않았다.

## 새 공개 API

모두 `guard_app.services.catalog`에 있다. 아래 메모리 입력은 1단계 로더 API이며 최종 파일 형식·경로 계약은 아니다.

| API | 반환·용도 |
| --- | --- |
| `load_profile_settings(document: Mapping[str, object], registry: Registry, *, resource_resolver: ResourceResolver \| None = None) -> LoadedProfile` | 검증·불변 사본 생성·정책 버전 계산. 로딩 중 Registry 조회·파일/URL/프로세스 접근 없음 |
| `LoadedProfile` | `profile`, `catalog`, `access_rules`, `guard_settings`, `servers`와 `policy_version` 속성 |
| `Profile` | `profile_id`, `server_ids`, `destination_ids`, 기존 SourceRule의 `source_rules` |
| `GuardSettings` | GuardService 생성자에 넘길 `profile_id`, `policy_version`, `taint_mode`, `approval_ttl_seconds` |
| `ServerSettings` | C 검증에 넘길 서버 ID·경계·transport·command/args/env_allow/url·tools. `as_boundary()`는 순수 Boundary 변환 |
| `ToolSettings` | 운영자 지정 `name`, `kind`, `resource_arg`, `destination_arg` |

| 입력 위치 | 필드·기본값 |
| --- | --- |
| 최상위 | `profile`, `servers` 필수. `destinations=[]`, `policy={}`, `access_rules={}` 기본 |
| `profile` | `id`, `servers` 필수. `destinations=[]`, `sources=[]` 기본. 서버·목적지 목록은 ID 문자열 배열 |
| `profile.sources[]` | 개발문서 4.2의 `server`, `tool`, `prefix`, `label`. 선택한 서버의 READ 도구만 참조 |
| `servers[]` | 개발문서 10.1의 `id`, `transport`, `tier`, `max_label`, `tools` 필수. stdio는 `command` 필수, `args=[]`, `env_allow=[]` 기본. streamable_http는 `url` 필수. 두 연결 방식의 실행 필드는 혼합 불가 |
| `servers[].tools[]` | `name`, `kind` 필수. READ의 `resource_arg`는 선택, SEND는 `destination_arg` 필수. OTHER에는 두 인자 지정 불가 |
| `destinations[]` | 개발문서 4.3의 `id`, `tier`, `max_label` |
| `policy` | `taint_mode="accumulate"` (`last_read`·`none` 허용), 양의 정수 `approval_ttl_seconds=300` |
| `access_rules` | `allow=[]`, `deny=[]`. 각 항목은 `[server_id, tool_name]`. 등록 설정의 서버·도구만 참조 |

등급은 `PUBLIC`·`INTERNAL`·`CONFIDENTIAL` 문자열, tier·kind는 기존 enum의 문자열 값을 받는다. JSON 배열은 내부 불변 tuple로 옮긴다. 최상위 일반 Mapping은 허용하지만 내부 값은 JSON 객체·배열·스칼라여야 한다. bool·실수·문자열을 정수 TTL로 자동 변환하지 않는다.

정규화는 검증된 전체 설정을 JSON 값으로 내보낸 뒤 접근 규칙을 정렬·중복 제거한 표현으로 바꾼다. 등급은 기존 Label의 정수 값, enum은 값, tuple은 배열, 생략된 선택 항목은 검증된 기본값으로 내보낸다. 키 순서·문서 공백·접근 규칙 순서/중복·기본값 생략은 버전을 바꾸지 않는다. 그 밖의 배열 순서는 보존하며 문자열 공백·대소문자·Unicode는 변환하지 않는다. Profile 밖의 서버·목적지 설정도 전체 해시에 포함한다.

## 실제 검증

Windows·Python 3.12.15에서 `..\.dev-tools\uv-tool\bin\uv.exe`를 사용했다. pytest 전에 `QT_QPA_PLATFORM=offscreen`을 설정했다. 의존성 설치·동기화는 하지 않았다.

| 실행 | 결과 |
| --- | --- |
| `uv run --no-sync ruff check .` | 통과 |
| `uv run --no-sync ruff format --check .` | 통과, 115개 파일 |
| `uv run --no-sync python -m mypy` | 통과, 59개 소스 파일 |
| `uv run --no-sync python -m pytest -q tests/unit/test_profile_loading.py tests/unit/test_catalog.py tests/unit/test_access_rules.py tests/unit/test_fingerprint.py --basetemp=.test-artifacts/profile-loading` | 샌드박스 안에서 363개 통과, 캐시 권한 경고 1건 |
| `uv run --no-sync python -m pytest -q --basetemp=.test-artifacts/codex --deselect tests/unit/test_ui_keyboard.py::test_add_form_keyboard_reaches_fields_and_prepares_only_local_draft` | 샌드박스 밖에서 2,823개 통과·1개 제외·20 subtest 통과·경고 6건 |
| 기존 Catalog 회귀·범위 검사 | 변경 전후 Catalog 클래스 AST 동일. 기존 테스트 변경 없음. 추가 소스는 B 소유 catalog.py만 변경 |
| `git diff --check` | 통과 |

정상 로드, 직접 구성한 Catalog와 도구 노출·요청 해석·출처 분류 결과 일치, Profile 범위 제한, 살아 있는 Registry 상태·지문 검사, 설정과 등록 메타데이터 불일치, 각 거부 조건과 원문 비노출, 불변 사본을 검증했다. 키 순서·공백·기본값·접근 규칙 정규화의 안정성과 전체 설정 각 부분의 변경 민감도, 정규화 전체의 JCS SHA-256 일치를 확인했다. I2·I6·I7·I9와 기존 Catalog의 T04·T06·T32·T38에 관련된 단위 검증이며, 새 로더의 실제 C/A 연결·dispatch/wire 계수 검증은 포함하지 않는다.

초기 검증에서 JCS 직렬화가 `300.0`을 `300`으로 바꾸어 정수 TTL로 받아들이는 문제를 발견했다. JSON 가능 여부는 JCS로 검사하되 Pydantic 타입 검증에는 원래 숫자 타입을 보존하고, 검증 후 정규화 전체를 JCS 해시하도록 수정했다. 최종 검증은 모두 통과했다.

전체 테스트는 첨부 지시와 Windows asyncio socketpair 초기화 제약에 따라 샌드박스 밖에서 실행했다. 경고 6건은 기존 AGT 폐기 경고 4건, Pydantic 필드 설정 경고 1건, pytest 캐시 권한 경고 1건이다. 첨부에서 예고한 AGT 테스트 실패는 재현되지 않았다. 지정된 A UI 테스트 1개는 이번에 재현·수정하지 않았다.

## 남은 한계와 A·C 전달 사항

- **형식 결정 필요(C 경로 검증, A 시작 연결)**. YAML/TOML/JSON 선택, 실제 파일 경로, 파일 파서·신뢰 출처 확인은 구현하지 않았다. 이 메모리 입력 API를 최종 파일 문법으로 확정하지 않았다.
- C 요청: ServerSettings의 command·args·env_allow·url과 출처 경로를 기존 안전 경로·실행 파일·endpoint 검증에 통과시킨 뒤 사용한다. 로더는 문자열의 실제 경로·실행 가능 여부·네트워크 목적지를 검증하지 않는다. Registry의 실제 연결 정보와 설정 결속도 C/A 연결에서 확인해야 한다.
- A 요청: 신뢰 파일 파싱 결과를 로더에 전달하고, Profile.server_ids에 선택된 서버의 C 검증·등록 결과를 시작 단계에 연결한다. 반환한 Catalog·접근 규칙·GuardSettings를 같은 설정 사본으로 연결한다. AccessChecker 동기 포트·Guard AGT 제거는 B2.9 후속이다.
- B3.10 정책 변경 명령·실행 중 Task 정지·승인 무효화 연결은 별도 후속이다. 새 버전 계산만으로 이미 실행 중인 Guard의 정책을 바꾸지 않는다.
- 새 domain·ports 3인 합의 대상은 없다. 메모리 API·정규화 표현은 A/C 연결 검토가 필요하다. GitHub 논의와 다른 브랜치의 실제 검토·연결 상태는 확인 불가다.

## 새 공개 API와 사용

- `domain.contracts.TaskIdentity`: 신뢰 세션과 결속한 Task ID·epoch다. 모델 문자열·dict를 정지 API에 직접 넘기지 않는다.
- `domain.enums.SystemStopReason`: `L3_VIOLATION`, `WATCHDOG_EXCEEDED`, `AUTH_FAILED`, `AUTH_REFRESH_CONFLICT`, `USAGE_LIMIT`, `PROCESS_FAILED`, `PROTOCOL_FAILED`. 각각 같은 의미의 `Reason.SESSION_*`로 기록한다.
- `domain.enums.SessionEvent`: `STOPPED`, `REQUEST_USER_INPUT`.
- `ports.SessionAudit.record_session_event(identity, event, *, at_utc, reason=None) -> None`: 내구성 커밋 ACK 계약이다. STOPPED에는 enum 사유가 필수이고, REQUEST_USER_INPUT에는 사유가 없다. 원문을 받는 필드가 없다.
- `GuardService.system_control(audit) -> SystemControl`: 신뢰 구성 경로가 생성해 A 세션 관리자에만 전달한다. `SQLiteStore`를 audit로 연결할 수 있다. 생성자 key를 임의로 만들어 capability를 구성할 수 없다.
- `SystemControl.stop_task(identity, reason) -> TaskState`: 호출 coroutine이 실행되면 첫 await·Task lock 대기 전에 해당 생애의 정지 신호를 세운다. 실제 상태·감사 커밋이 확인된 뒤 반환한다.
- `SystemControl.record_request_user_input(identity) -> None`: Task·epoch·UTC 시각·발생 사실만 기록한다. 질문·응답·인자·예외 원문을 받지 않으며 정상 기록은 Task 상태를 바꾸지 않는다.
- `SQLiteStore.record_session_event(...)`: SessionAudit 구현. 기존 감사 detail에는 epoch만 추가하고, 기존 HALTED 감사는 기존 상태 변경 트랜잭션에서 기록한다.
- `SystemControlError`: 제어 확정 실패를 알리는 고정 오류다. 원래 예외는 문자열·repr로 전파하지 않는다.

신뢰 구성 코드의 연결 예:

```python
system = guard.system_control(store)
identity = TaskIdentity(task_id=state.task_id, epoch=state.epoch)
stopped_state = await system.stop_task(identity, SystemStopReason.WATCHDOG_EXCEEDED)
```

`HumanControl`은 이 capability의 생성·정지·사실 기록 API를 제공하지 않는다. 반대로 SystemControl에는 승인·사람 취소 API가 없다. Python 객체 전달 범위의 분리이며 같은 프로세스의 임의 코드 실행을 격리하는 인증 수단은 아니다. 모델 도구 목록에 등록하지 않는다.

## 정지·실패·경쟁 의미

- 정지 신호는 `(task_id, epoch)`별로 관리한다. lock을 기다리는 동안 새 판정·예약·dispatch와 접근 검사 대기를 차단한다. 옛 epoch·없는 Task는 실패하고 현재 생애나 다른 Task를 바꾸지 않는다. 기존 승인 관계가 있는데 Task 행이 사라진 경우는 무결성 실패로 전역 정지한다.
- 같은 Task lock 안에서 살아 있는 승인과 원문 사본을 무효화하고, 기존 `_halt_task` 경로로 정지한다. 일반 대기 승인은 상태·감사 ACK 이후 `invalidated`를 한 번 발행한다. 승인 재평가와의 경쟁도 기존 단일 완료 경로를 쓴다.
- 예약 후 transport 중 정지는 READ를 WITHHELD/HALTED, SEND를 UNKNOWN_OUTCOME/UNKNOWN_OUTCOME으로 커밋한다. 이미 UNKNOWN_OUTCOME인 Task를 HALTED로 덮지 않고 재전송하지 않는다. 승인 실행 중이면 최종 알림은 해당 실행의 Withheld/OutcomeUnknown 한 건이다.
- 성공 결과 커밋을 기다리는 사이 정지가 들어와도 본문은 공개하지 않는다. READ 등급 반영·성공 요청 기록은 보존하고 Task를 HALTED로 만든다. 성공 커밋 ACK가 확인된 SEND도 성공 요청 기록을 보존하고 HALTED·Withheld로 반환한다. 이 경우는 전송 성공 여부가 알려져 있으므로 UNKNOWN_OUTCOME으로 다시 쓰지 않는다.
- HALTED·UNKNOWN_OUTCOME·CLOSED에 반복 호출하면 기존 상태를 그대로 반환한다. 상태 전이·승인 최종 알림을 중복하지 않으며, 접수한 정지 사실 감사는 호출마다 추가한다.
- 승인 전이·Task 커밋·조회·UTC·감사·제어 대기 취소 실패는 성공 ACK가 아니다. `SystemControlError`와 Guard 전역 정지로 처리하고, 실행 중이 아닌 미완료 Pending은 `failed` 한 건으로 알린다. 예약 실행의 결과는 자체 after_dispatch 경계가 확정한다.
- SEND 격리 커밋 실패로 DB가 아직 RUNNING/DISPATCHING이어도 뒤따른 시스템 정지가 HALTED 성공으로 덮지 않는다. Guard 전역 정지를 유지하고 제어 실패를 반환한다.
- 기존 HALTED 감사와 별도의 SESSION_STOPPED 감사는 각각의 트랜잭션이다. 뒤 감사가 실패하면 앞의 정지가 일부 적용되었을 수 있지만 성공을 반환하지 않는다. 전체 rollback·재시작 복구를 새로 구현하지 않았다.

## 인수·한계와 전달할 것

- **A 요청**: TaskIdentity·enum 매핑과 capability를 세션 관리자에 주입하고 직접 Store HALTED 처리를 교체한다. 모델·사람 채널에 이 객체를 주지 않는다. stop_task 완료 전에는 "적용됨"으로 표시하지 않는다. `request_user_input`에는 질문 원문을 전달하지 않는다.
- **A 요청**: T42/L3 정지는 별도 제어 경로로 시작하고, `turn/interrupt`·Codex 종료·transport 호출 종결도 진행해야 한다. 정지 ACK는 실행 중인 Task lock의 해제를 기다리므로, stop_task를 먼저 끝까지 기다린 다음에야 전송을 종료하는 순서는 피한다. 끝나지 않는 transport의 강제 종료·시간 상한은 A 책임이다.
- **A 요청**: Pending의 최종 모델 응답은 NOTIFY-01 한 경로만 소비한다. 사람 승인 반환값·stop_task 반환 상태를 같은 도구 응답으로 중복 중계하지 않는다. Withheld/OutcomeUnknown에는 고정 정지 문구와 세션 종료를 연결한다. 새 정지 Reason 7개는 모델 비공개다.
- **C 요청**: SessionAudit의 내구성·부분 실패와 I2/I5/I6/I8, T41/T42의 실제 host/wire/수신 부작용 계수를 독립 검증한다. 이 기록의 신규 검증은 B 단위 대역·B SQLite 테스트이며 A 연결·C wire 인수를 대신하지 않는다.
- **A·B·C 합의 필요**: 새 DTO·enum·Reason·SessionAudit의 이름·필드·반복/부분 실패 의미. B5.14에서 추적한다. 실제 합의·A 연결·C 독립 검증·PR 번호는 미정이다.
- 현재 B 브랜치에 커밋하며 push·PR 생성은 하지 않는다.

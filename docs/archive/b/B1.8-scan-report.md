# B1.8 · SCAN-01 ScanReport·Finding 확장안

완료: 2026-10-18 · 담당: B · PR 번호: 미정

## 범위와 계약 상태

- 첨부 `8-P5-scan01-desc01.md`의 SCAN-01 B 구현이다. 관련 근거는 contracts의 2026-10-15 Scanner 결정과 기술 설계 10.2절, T17·T19, I7·I9다.
- **합의 전 제안**이다. 기존 Finding·ScanReport 필드의 이름·타입·기본값은 유지하고, 기본값이 있는 필드와 새 타입만 추가했다. A·B·C 합의 기록을 대신하지 않는다.
- 시작점은 `feat/b-security-core`의 `978c83d`이고, 이미 병합된 main 기준은 `139e5a0`이다. 첨부의 과거 기준 `a2698b2`로 되돌리지 않았다.
- C의 `adapters/cisco*.py`·Registry와 A UI·runner·bridge, 기존 테스트, ports·Reason·SQLite·의존성·공통 문서는 변경하지 않았다. 같은 커밋의 DESC-01은 [B3.8 기록](B3.8-reviewed-description.md)에 있다.
- GitHub issue #21 원문·PR·다른 브랜치의 최신 구현은 확인 불가다. 첨부 요약과 현재 브랜치의 C 집계 코드에 근거했다. 현재 브랜치에는 `services/registry.py`가 없으며 Registry 영속화는 이 작업에서 구현하지 않았다.

추가 필드:

- 기존 `Finding.severity`와 `ScanReport.max_severity`는 SDK 값 그대로이며 자체 평가로 덮거나 내리지 않는다. 도구 지문·검사 시각·Scanner 버전과 기존 분석기 목록도 유지했다.
- `ScanRisk`는 1–64자 문자열이다. 대소문자·SDK 위험도 enum으로 변환하지 않는다. `overall_risk`는 데이터·표시 필드이고 새 판정·정렬 함수는 만들지 않았다. SAFE/CRITICAL로 바꿔도 기존 Guard의 ALLOW·ASK·DENY 및 dispatch 수가 같음을 B 단위 대역으로 확인했다.
- Finding의 필드는 도구별 정보, ScanReport의 필드는 보고서 수준 정보다. 옛 입력의 None·빈 값은 미제공이며 도구·출처·안전 여부를 추측하는 근거가 아니다. C가 새 경로에서 실제 이름·지문·출처를 채워야 한다.

`AnalyzerDiagnostic`:

- 필수 `analyzer: Identifier`, `code: ScanErrorCode`. 선택 `tool_name`, `tool_fingerprint`는 기본 None이다. 도구 이름은 repr에서 숨긴다. 예외·SDK 원문을 받는 필드는 없다.
- 진단의 분석기는 같은 보고서의 skipped 또는 failed 목록에 있어야 한다. completed·알 수 없는 분석기에 실패 진단을 붙일 수 없다. 지문이 주어졌다면 fingerprint_set 안에 있어야 하며 같은 분석기·도구·지문·코드 진단의 중복을 거부한다.
- `ScanErrorCode`는 현재 C `cisco_aggregation.py`의 고정 코드 28개와 `SCAN_INCOMPLETE`, `SCAN_MALFORMED`다. AST로 28개 포함을 확인했으며 C 모듈을 domain에서 import하지 않는다. Python 입력은 enum 인스턴스가 필요하고 JSON은 해당 고정 문자열만 받는다.
- 하위 호환을 위해 옛 failed/skipped 보고서의 빈 진단 tuple도 허용한다. 이를 completed·안전으로 바꾸지 않는다. 새 C 번역에서는 실패·생략 코드를 명시해야 한다. findings 0개·overall_risk SAFE도 기존 실패 목록을 지우거나 완료를 만들어 내지 않는다.

## 요약 텍스트의 거부 정책

- `ThreatSummary`는 최대 300 Unicode code point다. 글자 묶음·UTF-8 바이트 수로 세지 않는다. 빈 값·일반 텍스트·LF·TAB은 허용한다.
- 길이 초과·허용하지 않는 문자는 **거부**한다. 절단·치환·NFC 정규화로 검사 원문을 조용히 바꾸지 않는다. 300자를 넘는 뒷부분을 잘라 성공 결과로 만드는 대신 C가 미완료 경고로 처리할 수 있게 한다.
- NUL·ESC·DEL·C1, bidi·zero-width 등 Unicode 제어/형식 문자, surrogate, Unicode 줄·문단 구분자는 거부한다. CR도 허용하지 않는다.
- HTML 꺾쇠·엔티티, URL 스킴·www·도메인형 문자열·이메일, Markdown 링크·참조 문법을 거부한다. 검사에만 NFKC와 도메인 구분점 정리를 사용해 전각 표현도 검사하고, 반환값은 입력 그대로 보존한다. ScanRisk에도 같은 표시 문자 검증을 적용한다.
- 보수적인 어휘 검사이므로 `tool.name` 같은 도메인형 일반 설명이나 부등호도 거부될 수 있다. 완전한 자연어·렌더러 해석 검증으로 주장하지 않는다. A는 검증과 별개로 plain text 표시·링크 자동 활성화 금지를 적용해야 한다.
- 새 텍스트는 repr/str에서 숨기고 고정 검증 메시지만 낸다. 명시적 model_dump/model_dump_json에는 원문이 있으므로 로그에 넣어도 된다는 뜻은 아니다. 기존 자유형 `Finding.description`을 새 검증된 summary로 오인하지 않는다.

## 인수·한계

- **C 요청**: 현재 SDK 내부 결과를 새 DTO로 번역하고 도구별 이름·지문·SDK 위험도·출처, 실패/생략 코드를 연결한다. 실제 SDK의 자체 평가·설명 반환 형식과 새 문자열 필드 매핑은 C 확인이 필요하다. 알 수 없는 실패·유효하지 않은 summary를 빈 findings·안전으로 바꾸지 말고 고정 미완료/형식 오류를 남긴다. 가능한 기존 SDK finding은 보존하고 예외 원문은 코드로 복사하지 않는다.
- **A 요청**: 등록 화면·해당 도구 승인 창에 SDK 위험도·출처·미완료와 자체 평가를 구분해 표시한다. `overall_risk`로 정렬·판정·위험도 하향을 하지 않는다. summary는 “검증되지 않은 내용” 표시와 함께 plain text로만 보여 주고 링크·HTML·로그를 활성화하지 않는다. Scanner 경고로 승인을 막거나 ALLOW를 ASK로 올리지 않는다.
- **A 요청**: 제외한 UI 키보드 테스트의 한글 경로 PC 멈춤을 별도로 확인한다.
- **합의 필요**: 선택 필드·문자열 길이·거부 규칙, 진단 구조와 고정 코드 목록, C 번역·A 표시를 A·B·C가 검토한다. B1.9에서 추적한다. 실제 Scanner 호출·Registry 활성화·A 렌더러·C 독립 T17/T19 인수는 이 작업에서 확인하지 않았다.
- 현재 브랜치에 커밋하며 push·PR 생성은 하지 않는다. `Claude outputs/`는 변경하거나 add하지 않았다.

## 요약 텍스트의 거부 정책

이 절은 2026-10-18 최초 규칙의 기록이다. 스킴·도메인 오탐과 C의 명시적 무해화는 아래 2026-10-19 보완 절에서 고쳤다. 검증기의 무변환·거부 원칙과 필드 길이·형식은 유지한다.

- `ThreatSummary`는 최대 300 Unicode code point다. 글자 묶음·UTF-8 바이트 수로 세지 않는다. 빈 값·일반 텍스트·LF·TAB은 허용한다.
- 길이 초과·허용하지 않는 문자는 **거부**한다. 절단·치환·NFC 정규화로 검사 원문을 조용히 바꾸지 않는다. 300자를 넘는 뒷부분을 잘라 성공 결과로 만드는 대신 C가 미완료 경고로 처리할 수 있게 한다.
- NUL·ESC·DEL·C1, bidi·zero-width 등 Unicode 제어/형식 문자, surrogate, Unicode 줄·문단 구분자는 거부한다. CR도 허용하지 않는다.
- HTML 꺾쇠·엔티티, URL 스킴·www·도메인형 문자열·이메일, Markdown 링크·참조 문법을 거부한다. 검사에만 NFKC와 도메인 구분점 정리를 사용해 전각 표현도 검사하고, 반환값은 입력 그대로 보존한다. ScanRisk에도 같은 표시 문자 검증을 적용한다.
- 보수적인 어휘 검사이므로 `tool.name` 같은 도메인형 일반 설명이나 부등호도 거부될 수 있다. 완전한 자연어·렌더러 해석 검증으로 주장하지 않는다. A는 검증과 별개로 plain text 표시·링크 자동 활성화 금지를 적용해야 한다.
- 새 텍스트는 repr/str에서 숨기고 고정 검증 메시지만 낸다. 명시적 model_dump/model_dump_json에는 원문이 있으므로 로그에 넣어도 된다는 뜻은 아니다. 기존 자유형 `Finding.description`을 새 검증된 summary로 오인하지 않는다.

### 변경 파일과 검사 규칙

- `domain/text.py`: 스킴 시작에 단어 경계를 요구하고 콜론 바로 뒤가 공백이면 비계층형 스킴 링크로 보지 않는다. `Profile:`·`Hotel:`·`Data: the tool ...`가 통과한다. `https://`·`javascript:alert`·`data:text/html`은 계속 거부한다.
- 도메인 검사는 ASCII/퓨니코드 접미사와 일부 Unicode TLD 표기를 검사한다. 흔한 로컬 파일/코드 접미사 `json`, `yaml`, `yml`, `toml`, `ini`, `cfg`, `conf`, `txt`, `csv`, `xml`, `log`, `path`는 예외로 두어 `config.json`·`os.path`를 허용한다. 한국어 문장의 마침표 다음 일반 단어는 TLD로 오인하지 않는다.
- `evil.com`, 하위 도메인, `co.uk`, `zip`, `app`, `dev`, `py`, 퓨니코드, 한글 호스트와 `.한국`·`.рф`, 이메일·Markdown·HTML·엔티티·전각 표기 거부를 검사했다. 파일과 TLD가 모호한 `.py`·`.zip` 등은 예외로 풀지 않는다.
- 완벽한 도메인/URL/파일 판별이 아니다. 고정 파일 접미사 예외·일부 Unicode TLD만 다루므로 오탐·미탐의 여지가 있다. 등록 TLD 전체 목록을 조회하거나 렌더러 안전성을 증명하지 않았다. A의 plain text 표시·자동 링크/HTML 금지는 계속 필요하다.
- 검증기는 여전히 입력을 그대로 반환하거나 고정 오류로 거부한다. 길이 300/64, 제어 문자, repr 제외, 기존 DTO 필드는 바꾸지 않았다. DESC-01 문자 검증과 Catalog도 바꾸지 않았다.

### 새 공개 API

`domain.text.defang_scanner_text(value: str, *, max_length: int = 300) -> str`

- C가 번역 단계에서 명시적으로 고르는 별도 변환이다. 검증기·DTO 생성자가 자동으로 부르지 않는다.
- 안전하고 상한 이내인 후보는 그대로 보존한다. 거부되는 후보는 NFKC 형태에서 HTTP(S)를 hxxp(s), 주소의 점·골뱅이·콜론을 `[.]`·`[@]`·`[:]`, `< >`를 NFKC로 `< >`가 되돌아오지 않는 `‹ ›`로 바꾼다. 엔티티의 `&`와 원래 Markdown 대괄호도 무력화한다.
- 제어/형식 문자·surrogate 등 허용하지 않는 문자는 공백으로 바꾼다. 생성한 `[.]` 같은 표식이 인접 괄호와 Markdown 링크처럼 결합하면 대괄호를 `⟦ ⟧`로 바꿔 다시 무력화한다.
- 절단 시 전체 길이를 상한 이하로 맞추고 끝에 `…`를 넣는다. 상한 1이면 긴 결과는 `…` 하나다. 반환 직전 같은 표시 검증을 통과시키며 Hypothesis로 조합·Unicode·절단 성질을 확인했다.
- 상한은 정확한 정수 1–300만 받는다. 입력이 str이 아니거나 상한이 잘못되면 입력·상한·예외 원문을 포함하지 않는 ValueError다. 로그를 생성하지 않는다. 반환 문자열은 표시할 자료이며 로그 권한이 아니다.
- ScanRisk는 별도 함수를 추가하지 않고 `defang_scanner_text(raw_risk, max_length=64) or None`으로 쓸 수 있다. 빈 자체 평가를 임의의 위험 등급으로 바꾸지 않는다.

예: `<IMPORTANT> evil.com` → `‹IMPORTANT› evil[.]com`, `https://evil.com` → `hxxps[:]//evil[.]com`, `a@b.com` → `a[@]b[.]com`. 과거에는 요약 전체가 거부되던 주입 표식·전송 대상 정보를 무해화한 표시 자료로 보존한다. 검사·정렬·SDK 위험도에는 사용하지 않는다.

### C·A 인수와 남은 한계

- **C 요청(C4.9·C4.17)**: 번역 단계에서 이 함수를 명시적으로 호출한다. 그래도 summary 변환·검증이 실패하면 summary만 비우고 finding·SDK severity·실패 사실을 보존한다. 요약 표시 실패 때문에 위험한 finding을 지우거나 빈 findings를 안전으로 표시하지 않는다. 자체 평가는 상한 64와 None 처리를 별도로 적용한다.
- **C 요청**: 전체 시작 실패에는 유효한 신뢰 서버 식별자를 쓰고 필수 분석기 전부의 failed 진단을 채운다. 예외 메시지를 고정 코드·식별자에 복사하지 않는다. C 어댑터·secrets.py 자체는 수정하지 않았다.
- **A 요청**: 무해화 결과도 “검증되지 않은 내용” 표시와 함께 plain text로만 표시하고 자동 링크·HTML·로그를 활성화하지 않는다. 지정 UI 키보드 테스트의 한글 경로 PC 멈춤은 별도 확인한다.
- 새 함수·코드 및 거부 규칙은 합의 전 제안이다. A·B·C 인수·실제 Scanner 번역 연결·PR 상태는 확인 불가이며 B1.9에서 계속 추적한다. `docs/b-status.md`는 B1.8 한 줄 문구와 갱신일을 보완했다.

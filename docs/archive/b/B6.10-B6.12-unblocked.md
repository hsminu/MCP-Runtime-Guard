# B1.6·B6.10–B6.12 합의 뒤 코드와 시험 대조

2026-10-29 · B 단위 대조 · [#76](https://github.com/hsminu/MCP-Runtime-Guard/issues/76)

#76의 B6-02·03·04·06 정리와 B6-05 A·C 합의를 기준으로 아래 요구를 코드와 시험에 대조했다. B6-01은 A 동의 뒤 C의 [#89](https://github.com/hsminu/MCP-Runtime-Guard/pull/89) 확인이 남아 있다. 아래 표는 각 행을 하나의 하위 요구로 센다. `tests/unit/` 경로의 시험 이름을 적었으며, B 단위 결과는 C 독립 검증을 대신하지 않는다.

신규 시험은 요청 결속 변조 4사례, 제어/응답 경쟁 8사례, 잠금 대기 기본값과 쓰기 중 만료 각 1사례로 모두 14개다. 요청 결속 네 사례는 수정 전 모두 `consume_and_reserve=True`여서 실패했고, 기존 충돌 의미에 맞춰 사본 대조를 추가한 뒤 rollback/`False`가 됐다. 별도 프로세스에서 Task lock을 호출마다 새로 만드는 변이를 넣으면 제어/응답 8사례가 모두 실패했다. `_fresh_utc`를 만료 전으로 고정하거나 기본 busy timeout을 0으로 만드는 변이도 해당 신규 시험에서 각각 실패했다. 변이는 제품 파일에 남기지 않았다.

B1.6·B6.10·B6.11·B6.12의 B 단위 증거는 위와 같다. 시간값 확정과 실제 프로세스 중단·wire·외부 효과 계수는 C 측정·독립 검증이 남는다. B6.9는 C의 #89 확인 대기, B6.16은 #76 A·C 합의와 #86 병합 뒤 A 화면 연결 대기다. B1.5는 이번 범위 밖이다.

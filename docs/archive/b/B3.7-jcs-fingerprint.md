# B3.7 · FP-01 JCS 도구 지문

## 한 일

- `security/digest.py`에 승인 해시와 분리된 JCS 정규화·Tool 객체 전체의 SHA-256 지문을 추가했다. 표준 라이브러리만 사용했고 의존성은 추가하지 않았다.
- [RFC 8785](https://www.rfc-editor.org/rfc/rfc8785.html)의 UTF-16 코드 단위 키 정렬, 최소 문자열 이스케이프, UTF-8, ECMAScript 숫자 표기와 배열 순서를 적용했다. NFC 변환과 필드 선택·기본값 삽입은 하지 않는다.
- Python의 최단 round-trip float 숫자열에 ECMAScript의 소수점·지수 배치 규칙을 적용한다. 첨부의 지수 경계 문구는 RFC 부록 B에 맞춰 절댓값 `1e-6` 미만·`1e21` 이상으로 해석했다. `1e-6`은 `0.000001`, `1e-7`은 `1e-7`이다.
- Python int는 ±(2**53-1) 밖이면 거부한다. 유한 binary64 float는 이보다 커도 RFC 표본대로 처리하고, 음의 0은 `0`으로 쓴다.
- 비유한 수·허용하지 않는 타입·비문자열 키·surrogate·순환·인터프리터 재귀 한계 초과를 입력 원문 없는 전용 오류로 거부한다. 같은 자식 객체를 여러 번 참조하는 비순환 입력은 허용한다.
- 기존 승인 직렬화·해시 함수와 기존 테스트는 수정하지 않았다. `docs/b-status.md`의 B3.7에 완료 기록을 연결했다. 관련 기준은 I9·I10, T10·T17이며 실제 Registry 집행은 C 연결 범위다.

## 새 공개 API

모두 `guard_app.security.digest`에 있다.

| API | 계약 |
| --- | --- |
| `jcs_canonicalize(value: object) -> bytes` | 정확한 dict/list/str/int/float/bool/None을 받아 JCS UTF-8 바이트 반환 |
| `tool_fingerprint(tool: object) -> str` | 파싱된 Tool dict 전체를 받아 소문자 hex SHA-256 64자리 반환. 최상위는 정확한 dict만 허용 |
| `JcsCanonicalizationError(ValueError)` | 입력 원문·원래 예외 메시지를 담지 않는 고정 오류 |

| `git diff --check` | 통과 |

새 단위 테스트는 RFC 부록 B의 모든 유한 수 표본·NaN/Infinity 거부, 예제 객체의 공개 UTF-8 바이트, UTF-16 정렬, 제어 문자·surrogate, 안전 정수 범위, 원문 없는 오류, 순환과 공유 자식, 정의 전체·설명·배열 변경을 검증한다. Hypothesis로 중첩 JSON의 재정규화 불변성과 결정성·키 삽입 순서 독립성을 검증했다. 재파싱 성질 테스트는 큰 정수값 float를 임의 정밀도 int로 바꾸지 않도록 `parse_int=float`로 ECMAScript Number 의미를 유지한다.

처음 샌드박스 안의 전체 실행은 첫 C 테스트 `tests/unit/adapters/test_cisco_aggregation.py::test_completed_findings_preserve_both_sources_without_deduplication`에서 멈춰 중단했다. 별도 수집은 2,425개를 정상 수집했고, 진단 스택은 Windows asyncio의 `_make_self_pipe` → `socket._fallback_socketpair` → `accept` 대기를 보였다. 같은 전체 명령을 샌드박스 밖에서 실행해 완료했다. 전체 실행의 경고는 기존 AGT 패키지 폐기 경고 4건, Pydantic 설정 필드 경고 1건, pytest 캐시 권한 경고 1건이다. 첨부에서 예고한 AGT 테스트 실패는 이번 완료 실행에서 재현되지 않았다.

## C 연결 안내

- Registry의 등록·재연결 지문과 Scanner 지문은 같은 `tool_fingerprint`를 사용한다. 입력은 `tools/list`의 Tool 객체를 파싱한 dict 전체다. 추가 필드·annotations·입출력 schema를 삭제하거나 기본값으로 바꾼 사본을 넘기지 않는다.
- Python `json.loads`는 기본으로 NaN·Infinity를 허용한다. C는 파싱 단계의 `parse_constant` 등 거부 설정을 확인해야 한다. 이 함수도 비유한 float와 `1e9999` 같은 오버플로 결과를 거부한다.
- 중복 키는 dict로 바뀐 뒤 알아낼 수 없으므로 C가 파싱 단계에서 거부해야 한다. 원문·토큰·예외 원문을 오류에 넣지 않는다. Python int를 float로 임의 변환해 안전 정수 범위 검사를 우회하지 않는다.
- `JcsCanonicalizationError`는 C의 기존 실패·미완료 처리로 연결한다. Scanner 경고 정책이나 사람 활성화 규칙은 이 함수가 결정하지 않는다.

## 남은 한계와 전달할 것

- `domain/*`·`ports.py`와 공유 문서는 변경하지 않았다. FP-01 사용자 결정 범위의 구현이므로 이번 변경에 새 3인 합의 대상은 없다.
- C 요청: Registry·Scanner 연결과 지문 변경 시 PENDING 전환·승인 무효화의 I10/T10/T17 독립 검증. 다른 브랜치의 실제 연결 상태와 GitHub 논의는 확인 불가다.
- A 요청: 첨부에서 지정한 `test_add_form_keyboard_reaches_fields_and_prepares_only_local_draft` 제외를 유지했다. 이 테스트는 이번 작업에서 재현·수정하지 않았다.
- Node.js는 이번 대조 검증에만 사용했다. 제품 함수와 저장소 단위 테스트에 Node.js·외부 JCS 라이브러리 의존성은 없다.

# B5.11 · 모델에 돌려줄 고정 문구표

## 한 일

- `core/model_messages.py`에 기존 Outcome 또는 신뢰된 결과 분류·Reason을 `(success, 고정 문구)`로 바꾸는 순수 함수를 추가했다. domain·표준 라이브러리만 사용한다.
- 현재 Reason 24개에 문구를 명시하고, 공개 가능한 코드 4개를 허용 목록으로 분리했다. 나머지 20개는 일반 거부 문구로 가린다. 식별자·버전·인자·본문·예외를 문구에 삽입하지 않는다.
- Released만 성공 표시를 반환하며 결과 본문은 읽지 않는다. Withheld·OutcomeUnknown·정지는 동일한 정지 문구를 사용하고, Pending은 최종 응답 생성을 거부한다.
- 거절·만료·취소·승인 무효화·namespace 누락·STOP-01용 정지 분류를 확장 지점으로 제공했다. 새 domain 사유나 알림·정지 API를 확정하지 않았다.
- 복수 사유에 비공개 사유가 하나라도 섞이면 전체를 일반 거부 문구로 가린다. 공개 사유만 있으면 CONFIDENTIAL_TO_EXTERNAL → INTERNAL_TO_EXTERNAL → INVALID_ARGUMENTS → TOOL_UNSUPPORTED 순서로 하나를 고른다. 입력 순서와 중복은 문구를 바꾸지 않는다.
- B5.11의 B 작성·검증을 완료하고, A 검토·세션 관리자 연결은 새 미완료 항목 B5.12로 분리했다. 기존 Runner·Guard·domain·ports·의존성·공유 문서는 바꾸지 않았다.

## 새 공개 API

모두 `guard_app.core.model_messages`에 있다.

| API | 계약 |
| --- | --- |
| `ModelMessageKind` | 기존 결과 5종과 승인 거절·만료·취소·무효화, namespace 누락, 정지를 구분하는 core 전용 enum |
| `fixed_model_message(kind: ModelMessageKind, reason: Reason \| None = None) -> tuple[bool, str]` | 신뢰된 분류·사유로 고정 응답 표시 생성. raw 문자열을 enum으로 자동 변환하지 않음 |
| `outcome_model_message(outcome: object) -> tuple[bool, str]` | 기존 Released·Denied·Withheld·OutcomeUnknown 변환. Pending과 미검증 객체는 고정 오류로 거부 |
| `MODEL_REASON_MESSAGES` | 모든 Reason의 불변 문구표 |
| `MODEL_VISIBLE_REASONS` | 모델에 코드 공개를 허용한 Reason의 frozenset |
| `ModelMessageError(ValueError)` | 대기 중 최종 응답 생성, 잘못된 입력, 누락된 문구를 거부하는 원문 없는 오류 |

## 결과별 문구

| 분류 | success | 고정 문구·처리 |
| --- | --- | --- |
| Released | true | 빈 문자열. 공개 본문은 A가 실제 Released.result에서 별도로 취급 |
| Denied | false | 아래 사유표. 사유가 없거나 비공개 사유면 `이 요청은 정책에 의해 차단되었습니다` |
| Withheld·OutcomeUnknown·STOPPED | false | `작업이 정지되었습니다` |
| 승인 거절 | false | `승인 요청이 거절되었습니다` |
| 승인 만료 | false | `승인 요청이 만료되었습니다` |
| 취소 | false | `요청이 취소되었습니다` |
| 승인 무효화 | false | `승인 요청이 무효화되었습니다` |
| namespace 누락 | false | `이 요청은 정책에 의해 차단되었습니다` |
| Pending | 해당 없음 | ModelMessageError. 최종 응답을 보내지 않고 알림 대기 |

## Reason 공개·비공개 근거

공개 4개는 `이 요청은 정책에 의해 차단되었습니다: <고정 코드>`다. 비공개 20개는 코드·세부 원인 없이 일반 거부 문구만 쓴다.

| 공개 여부 | Reason | 근거 |
| --- | --- | --- |
| 공개 | INTERNAL_TO_EXTERNAL | 개발문서 10.4절의 고정 정책 피드백 예시. 실제 대상·경계 ID·상한·버전은 포함하지 않음 |
| 공개 | CONFIDENTIAL_TO_EXTERNAL | 같은 외부 전송 제한의 고정 분류. 정책·승인을 완화할 권한을 주지 않음 |
| 공개 | INVALID_ARGUMENTS | 공개된 도구 형식에 맞춰 호출을 수정할 때 필요한 분류. 인자값·검증 예외는 숨김 |
| 공개 | TOOL_UNSUPPORTED | 지원하는 호출로 수정할 때 필요한 분류. 서버·도구 이름·내부 등록 정보는 숨김 |
| 비공개 | OK | 성공 여부는 실제 결과 종류로만 정함. Denied의 OK를 성공으로 오해하지 않게 함 |
| 비공개 | LABEL_EXCEEDS_BOUNDARY | 경계별 상한과 판정 내부 구조를 드러내지 않음 |
| 비공개 | UNKNOWN_DESTINATION·UNKNOWN_SERVER·REG_NOT_ACTIVE·TOOL_FINGERPRINT_CHANGED | 목적지·서버 등록, 활성 상태, 지문 상태는 내부 구성 정보 |
| 비공개 | TASK_UNCLASSIFIED·TASK_NOT_RUNNING·POLICY_CHANGED·STATE_MISSING | Task 보안 상태·정책 변경·저장 상태의 세부는 내부 정보 |
| 비공개 | AGT_DENY·AGT_ERROR·INTERNAL_ERROR·UNSUPPORTED_CONTENT·STATE_COMMIT_FAILED·RESULT_UNCLASSIFIED·POST_DISPATCH_ERROR | 판정기·응답 격리·분류·커밋·전송 후 실패의 내부 구조를 숨김 |
| 비공개 | APPROVAL_CONTEXT_LOST·APPROVAL_STALE·APPROVAL_RACE | 승인 결속·경쟁·유효성 검사 세부를 숨김. 확정된 거절·만료 등은 별도 결과 분류로 표시 |

## 실제 검증

Windows·Python 3.12.15에서 작업 공간의 `..\.dev-tools\uv-tool\bin\uv.exe`를 사용했다. pytest 전에 `QT_QPA_PLATFORM=offscreen`을 설정했다.

| 실행 | 결과 |
| --- | --- |
| `uv run --no-sync ruff check .` | 통과 |
| `uv run --no-sync ruff format --check .` | 통과, 114개 파일 |
| `uv run --no-sync python -m mypy` | 통과, 59개 소스 파일 |
| `uv run --no-sync python -m pytest -q tests/unit/test_model_messages.py --basetemp=.test-artifacts/codex-model-messages` | 샌드박스 안에서 202개 통과, 캐시 권한 경고 1건 |
| `uv run --no-sync python -m pytest -q --basetemp=.test-artifacts/codex --deselect tests/unit/test_ui_keyboard.py::test_add_form_keyboard_reaches_fields_and_prepares_only_local_draft` | 샌드박스 밖에서 2,707개 통과·1개 제외·20 subtest 통과·경고 6건 |
| 모듈 경계·변경 범위 검사 | domain·표준 라이브러리만 import. 새 비동기·예외 처리 경계·문자열 보간 없음. 기존 소스·테스트·domain·ports 변경 없음 |
| `git diff --check` | 통과 |

모든 Reason과 최종 분류의 누락 검사를 두었고, 문구표 누락 시 정상 기본값으로 넘어가지 않는 것도 검증했다. 공개/비공개, 복수 사유 순서·중복, Released만 성공, 대기 중 응답 금지, 거절·만료·취소·정지 구분, 본문을 읽지 않는 동작을 단위 검증했다. Hypothesis로 결정성과 식별자·버전·인자·원문 비노출을 확인했다. I5·I9의 반환 부분에 해당하며 실제 모델 왕복 검증은 포함하지 않는다.

전체 테스트는 첨부 지시와 이전에 확인한 Windows asyncio socketpair 초기화 제약에 따라 샌드박스 밖에서 실행했다. 경고 6건은 기존 AGT 패키지 폐기 경고 4건, Pydantic 설정 필드 경고 1건, pytest 캐시 권한 경고 1건이다. 첨부에서 예고한 AGT 테스트 실패는 재현되지 않았다.

## 남은 한계와 A·C 전달 사항

- A 요청(B5.12): 문구·코드 공개 범위·복수 사유 우선순위를 검토하고 세션 관리자에 연결한다. 이번은 B 작성 완료이며 A 검토 완료가 아니다. 현재 A Runner의 기존 문구·제어 흐름은 수정하지 않았다.
- Released의 `(True, "")`는 본문 공개 허가를 새로 만드는 증명이 아니다. A는 Guard가 실제로 반환한 Released의 공개 결과만 별도로 보낸다.
- Pending에는 응답을 보내지 않고 NOTIFY-01 최종 알림을 기다린다. 기존 승인 코드의 정상 거절·만료는 둘 다 Denied(Reason.OK)를 반환하므로 그 사유만으로 구분하지 않는다. 최종 알림에서 확정된 종류를 ModelMessageKind로 전달한다. 알림 DTO·정확히 한 번 전달은 B5.9 후속이다.
- Withheld·OutcomeUnknown·확정된 정지는 고정 문구 반환 뒤 A가 즉시 interrupt·프로세스 종료를 처리한다. 이 모듈은 제어 명령·재시도·정지 API를 실행하지 않는다.
- STOP-01 원인별 Reason·DTO가 아직 없으므로 STOPPED를 확장 지점으로 두었다. 향후 Reason 변경 시 명시적 문구표와 누락 검사를 함께 갱신해야 한다. 새 domain·ports 계약은 이번에 확정하지 않았다.
- C 요청: A 연결 뒤 실제 모델 응답에 내부 정보가 섞이지 않는지, Pending 조기 응답·알림 중복이 없는지, 정지 결과 뒤 모델이 계속 실행되지 않는지 독립 검증한다.
- 이번 변경에 새 domain·ports 3인 합의 대상은 없다. GitHub 논의와 다른 브랜치의 실제 검토·연결 상태는 확인 불가다. 지정된 A UI 테스트 1개는 제외했으며 이번에 재현·수정하지 않았다.

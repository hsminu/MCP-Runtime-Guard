# B6.8 3단계: 병합 뒤 WAL 보존과 Bandit 오탐 수정

2026-10-29 · B 후속 수정 · #69 C 리뷰 2 · #72 대비

B6.8 PR #69는 `b796ff0`으로 main에 병합됐다. 이 기록은 병합 뒤 발견한 수정 두 개를 다룬다. 이미 병합된 B6.8 기록은 고치지 않고 후속 결과를 여기에 남긴다.

## 즉시 모드 거부 시 원본 보존

#69 C 리뷰 2에서 WAL이 남은 v1·v2 DB를 즉시 모드가 거부한 뒤, SQLite 연결 종료가 WAL을 main DB에 체크포인트해 파일 바이트를 바꾸고 WAL을 제거하는 문제가 확인됐다. 수정 `9ee9324`는 즉시 모드도 연결 직후 `SQLITE_DBCONFIG_NO_CKPT_ON_CLOSE`를 켜고 확인하며, DB를 받아들이고 WAL 설정을 마친 뒤에만 끈다. 따라서 거부할 때는 main DB와 WAL을 보존하고, 받아들인 DB는 정상 종료 때 기존처럼 체크포인트한다. 즉시 모드도 명시 모드처럼 SQLite의 해당 설정과 `setconfig`·`getconfig` 지원이 필요하다.

새 시험 4개는 WAL이 남은 v1·v2·지원하지 않는 버전의 거부 뒤 main DB와 WAL의 바이트 보존 세 가지와, 수용된 v3의 정상 종료 체크포인트 대조군 한 가지다. 수정 전에는 거부 시험 세 개 모두 실패했고 수정 후 네 개 모두 통과했다.

## Bandit 오탐 제거

수정 `3fb28da`는 `_validate_recovery_audits`의 매개변수 `requests`와 함수 안 사용을 `stored_requests`로 바꾼다. 지역 딕셔너리 조회를 HTTP `requests.get` 호출로 오인한 Bandit B113을 피하기 위한 이름 변경이며 동작은 그대로다. 호출부와 다른 지역 변수는 유지했다.

## 검증

Windows에서 두 수정 커밋 각각의 전체 pytest는 **5,630 passed, 5 skipped, 실패 0**이었고 Ruff·format·mypy도 통과했다. 첫 전체 실행에서는 UI 브리지 테스트와 SQLite 앱 테스트가 각각 한 번 실패했다. UI 테스트는 독립 실행 5회, SQLite 앱 테스트는 독립 실행 1회 모두 통과했고, 전체 재실행에서도 실패가 없었다.

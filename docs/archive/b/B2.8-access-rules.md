# B2.8 · ACCESS-01 접근 규칙 순수 판정

## 한 일

- `core/access_rules.py`에 정확한 `(server_id, tool_name)` 쌍으로만 판정하는 동기 순수 함수를 추가했다. `domain`·표준 라이브러리만 가져오며 I/O·시간·호출 이력·인자 내용에 의존하지 않는다.
- 허용·거부 목록을 독립된 frozenset 사본으로 보관하는 불변 `AccessRules`를 만들었다. 중복은 제거하고, 두 목록에 모두 있으면 거부가 우선하며, 목록 밖은 기본 거부한다.
- 이름의 대소문자·공백·Unicode 정규화를 바꾸지 않는다. 접두어·와일드카드·조건식처럼 보이는 문자열도 정확 일치 데이터로만 취급한다.
- 목록 중 하나라도 형식이 잘못되면 집합 전체가 무효가 되어 모든 요청에 `allowed=False, error=True`를 반환한다. 정상 부분만 적용하지 않는다. 잘못된 집합의 정규화도 고정 오류로 거부해 빈 정상 설정으로 해시되는 것을 막았다.
- 규칙 객체 repr과 오류에는 입력값을 넣지 않는다. 판정의 reason에는 고정 코드만 쓴다. 예외를 넓게 잡는 경계는 추가하지 않았다.
- `normalize_access_rules`로 policy_version 계산에 사용할 정렬된 JSON 표현의 독립 사본을 제공하고, `docs/b-status.md`의 B2.8에 완료 기록을 연결했다. 관련 기준은 I2·I6이며 원문 비노출은 I9를 따른다.

## 새 공개 API

모두 `guard_app.core.access_rules`에 있다.

| API | 계약 |
| --- | --- |
| `AccessRules(*, allow: object = (), deny: object = ())` | 불변 규칙 집합. 목록은 정확한 list/tuple/set/frozenset, 쌍은 정확한 list/tuple 2개 원소, 이름은 비어 있지 않은 UTF-8 str만 허용 |
| `AccessRules.is_valid` | 집합 전체의 형식 검증 결과를 나타내는 읽기 전용 bool |
| `evaluate_access(rules: object, *, server_id: object, tool_name: object) -> AccessResult` | 기존 domain 모델 반환. 거부 우선·기본 거부이며 형식 불명은 error=True |
| `normalize_access_rules(rules: object) -> dict[str, list[list[str]]]` | `{"allow": [[server_id, tool_name], ...], "deny": [...]}`. 각 목록을 Python 문자열 순서로 정렬하고 중복 제거. 두 목록 간 중복은 보존 |
| `AccessRulesError(ValueError)` | 무효 집합의 정규화를 거부하는 원문 없는 고정 오류 |

판정 reason은 `ACCESS_RULE_ALLOW`, `ACCESS_RULE_DENY`, `ACCESS_RULE_MISSING`, `ACCESS_RULES_INVALID`, `ACCESS_REQUEST_INVALID`다. 마지막 두 결과만 error=True이며 모두 allowed=False다. 기존 `Reason` enum의 이름·의미는 바꾸지 않았다.

## 실제 검증

Windows·Python 3.12.15에서 작업 공간의 `..\.dev-tools\uv-tool\bin\uv.exe`를 사용했다. pytest 전에 `QT_QPA_PLATFORM=offscreen`을 설정했다.

| 실행 | 결과 |
| --- | --- |
| `uv run --no-sync ruff check .` | 통과 |
| `uv run --no-sync ruff format --check .` | 통과, 112개 파일 |
| `uv run --no-sync python -m mypy` | 통과, 58개 소스 파일 |
| `uv run --no-sync python -m pytest -q tests/unit/test_access_rules.py --basetemp=.test-artifacts/codex-access` | 81개 통과, 캐시 권한 경고 1건 |
| `uv run --no-sync python -m pytest -q --basetemp=.test-artifacts/codex --deselect tests/unit/test_ui_keyboard.py::test_add_form_keyboard_reaches_fields_and_prepares_only_local_draft` | 2,505개 통과·1개 제외·20 subtest 통과·경고 6건 |
| 모듈 경계·변경 범위 검사 | domain·표준 라이브러리 import만 존재. 새 비동기·예외 처리 경계 없음. 기존 소스·테스트 변경 없음. 현황은 B2.8만 변경 |
| `git diff --check` | 통과 |

단위 테스트는 허용·명시적 거부·기본 거부·거부 우선, 서버 구분, 대소문자·접두어·공백·Unicode·구분자·와일드카드의 정확 일치, 잘못된 집합·요청 형식, 불변 사본·repr·정규화 사본을 검증한다. Hypothesis로 결정성, 입력 순서·중복 독립성, 기본 거부, 거부 추가 시 차단, 목록 밖 거부, 다른 서버의 동일 도구 이름 구분, 정규화 왕복을 검증했다.

전체 실행은 이전 작업에서 확인한 샌드박스의 Windows asyncio socketpair 초기화 정지를 피하려고 샌드박스 밖에서 실행했다. 경고 6건은 기존 AGT 패키지 폐기 경고 4건, Pydantic 설정 필드 경고 1건, pytest 캐시 권한 경고 1건이다. 첨부에서 예고한 AGT 테스트 실패는 이번 실행에서 재현되지 않았다.

## 남은 한계와 A·C 전달 사항

- 이번은 순수 판정 1단계다. `ports.AccessChecker`·`guard.py`·AGT 어댑터·기존 `Reason`·domain 계약·의존성·공유 문서는 변경하지 않았다. 이번 core 구현에 새 3인 합의 대상은 없다.
- A 요청: B2.9·B2.10의 3인 합의와 병합 순서가 정해지면 신뢰 설정에서 만든 `AccessRules`와 요청의 등록된 server_id·tool_name으로 `evaluate_access`를 연결한다. 예상하지 못한 예외는 기존 fail_closed 경계로 변환한다.
- P7 후속: 설정·Profile 로더가 신뢰 출처를 확인하고 이 집합을 만든 뒤, `normalize_access_rules` 반환값을 정책 버전 입력에 포함한다. 정책 변경 시 버전 갱신·승인 무효화·Task 정지는 후속 범위다.
- C 요청: 연결 뒤 규칙 거절·오류에서 `host_dispatch == 0`인지를 독립 검증한다. 이번 단위 테스트로 실제 dispatch·wire 차단을 확인했다고 주장하지 않는다.
- A 요청: 지정된 `test_add_form_keyboard_reaches_fields_and_prepares_only_local_draft`는 이번 전체 실행에서 제외했다. 해당 테스트의 재현·수정은 하지 않았다.
- GitHub 논의와 다른 브랜치의 실제 연결·합의 상태는 확인 불가다. B2.9·B2.10·B2.11은 기존 미완료 상태를 유지한다.

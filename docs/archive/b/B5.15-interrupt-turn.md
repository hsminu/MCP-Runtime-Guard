# B5.15 턴 단위 중단 — B 기본안

2026-10-30 · 기준 main `4d8c7a6`. [#20 B 설계](https://github.com/hsminu/MCP-Runtime-Guard/issues/20#issuecomment-6508275892)에 [A가 표와 화면 사유 추가에 동의](https://github.com/hsminu/MCP-Runtime-Guard/issues/20#issuecomment-6508316573)했다. `TURN_INTERRUPTED`·`CANCELLED`와 독립 계수는 C 확인을 받는다. 공통 계약을 확정한 것으로 취급하지 않는다.

## 설계와 결과

| 중단 시점 | Guard 동작 | Task |
| --- | --- | --- |
| 호출 없음 | 변경 없이 `NOTHING_IN_FLIGHT` | RUNNING 유지 |
| 승인 대기 | 소비되지 않은 대상 승인을 `CANCELLED`·`TURN_INTERRUPTED`로 원자 종결, `APPROVAL_CANCELLED` | RUNNING 복귀 |
| Task lock 대기 중인 제출 | lock 획득 뒤 판정·요청 기록 전에 `Denied(TURN_INTERRUPTED)`, 실패 감사만 남기고 예약·승인 생성·전송 0 | RUNNING 유지 |
| lock을 잡고 판정·호출 진행 | 끊지 않고 `CALL_COMPLETING`, 평소의 판정·전송·커밋을 계속한다 | 정상 결과에 따라 유지·등급 반영; SEND 결과 불명 등 기존 격리 규칙 유지 |
| lock을 잡고 판정 중이던 제출이 나중에 ASK | 중단 시점 제출의 승인만 생성 직후 취소하고 `cancelled` 최종 알림 1회 | RUNNING 복귀 |

`TurnInterrupt`는 결과·실제 취소 건수·진행 호출 유무만 담는다. `CALL_COMPLETING`은 포착된 제출이 처리 중이라는 뜻이며 lock을 기다리던 제출은 실제로 전송하지 않을 수 있다. `CALL_COMPLETING`을 먼저 반환할 때 미래에 끝날 자동 취소는 아직 취소 건수에 포함되지 않는다. A는 나중의 최종 알림을 확인한다. 중단 뒤 시작한 제출과 그 승인은 대상에 넣지 않는다. epoch가 다르거나 없는 Task·종료된 Task는 변경하지 않는다.

## 구현과 경합

- `domain/reasons.py`, `domain/enums.py`, `domain/contracts.py`에 사유와 결과 타입을 추가했다. SQLite 사유는 TEXT이며 판독 시 enum을 검증하므로 스키마 버전 변경은 없다. 모델에는 고정 거절 문구만 돌린다.
- `GuardService.interrupt_turn`은 첫 대기 전에 이미 시작된 제출 객체와 승인 ID를 포착한다. 각 제출을 원문 없는 토큰으로 구분해 실행 단계·실제 epoch를 확인한다. 중단 뒤 새로 시작한 제출에는 그 표시를 남기지 않는다. 이미 승인 생성 중인 제출은 정지 신호 없이 생성 종결을 기다린다.
- 대기 승인은 같은 Task lock 안에서 `finish_approval`의 revision CAS로 승인·요청·Task와 감사를 함께 바꾼다. `CANCELLED`·`TURN_INTERRUPTED`, Task `RUNNING`이며 사본을 폐기하고 `Denied(TURN_INTERRUPTED)`·`cause="cancelled"` 알림을 한 번만 완료한다. 사람 승인과 경합하면 lock·CAS로 승자 하나만 확정한다. 이미 소비·예약한 호출은 중단하지 않는다.
- 소비 전 `APPROVED`가 남은 승인도 취소할 수 있도록 `finish_approval`에 한해 `APPROVED → CANCELLED`를 `TURN_INTERRUPTED` 사유에만 허용하는 B 기본안을 추가했다. 기존 일반 승인 전이와 스키마는 바꾸지 않는다. 이 제한적 확장도 C 확인 대상이다.
- 승인 종결 감사가 이미 있어 턴 중단 전용 감사 행은 추가하지 않았다. 쓰기 ACK 불명과 무결성 실패는 전역 정지 및 고정 실패 알림 경로를 사용한다. 조회·lock 대기 중 취소는 그대로 전파한다. 예외 원문·호출 인자는 결과와 감사에 넣지 않는다.
- A 파일 1줄 수정(A 확인 필요, #20 A 회신 근거): `src/guard_app/ui/presentation.py`의 `REASONS`에 턴 중단 문구만 추가했다. 다른 A 파일·A 시험은 수정하지 않았다.

## 시험과 범위

`tests/unit/test_turn_interrupt.py`는 실제 SQLite와 가짜 transport로 유휴·반복 중단, 대기 승인과 새 ALLOW/ASK, READ 등급 커밋, SEND 결과 불명, epoch·Task 경계, 생성 중 승인, 종료·입력 오류·원문 비노출·저장 사유 왕복을 검사한다. 판정 중 중단 이후 대상 ASK 자동 취소, 이후 시작한 ASK 보존, 사람 승인 경쟁, 조회·lock·쓰기 취소, 예기치 않은 오류, 대기자 lock 경합과 취소 건수도 확인한다. I3·I4·I5·I8·I9를 B 단위 대역에서 검증하며 실제 wire·수신 부작용 계수는 C 인수를 대신하지 않는다.

사람 승인과 중단을 동시에 보낸 50회에서는 승인 실행 50회, 중단 취소 0회였다. 중단이 먼저 이긴 경우는 별도 결정적 단위 시험으로 확인했으며, 이 50회에서 두 결과가 모두 관찰됐다고 주장하지 않는다.

## #114 A 리뷰 반영

A가 S1 READ의 transport를 붙잡은 상태에서 S2 READ를 같은 Task lock에 대기시킨 뒤 중단하고 S1을 풀었을 때 S2도 전송되는 문제를 확인했다. 사용자 결정으로 중단 시점에 **lock 대기 중이던 기존 제출만** lock 획득 후 판정과 요청 생성 전 `Denied(request_id=None, TURN_INTERRUPTED)`로 끝낸다. 기존 `FAILURE_BEFORE_DISPATCH` 감사만 남고 해당 제출의 요청 행·승인·예약·전송은 없다. 중단 시 이미 lock을 잡은 제출은 기존 61번 동작을 따르며, 중단 뒤 새로 시작된 제출은 영향을 받지 않는다. 기존 Store 계약·스키마·감사 이벤트는 바꾸지 않았다.

새 시험 `test_queued_submission_is_denied_and_later_submission_is_unchanged`는 READ·SEND·ASK와 중단 뒤 제출을, `test_wrong_epoch_interrupt_does_not_deny_a_queued_submission`과 `test_submit_arriving_during_interrupt_lookup_is_not_in_the_snapshot`은 생애 및 포착 경계를 확인한다. 또한 `test_multiple_interrupts_deny_a_matching_waiter_once`, `test_interrupted_waiter_audit_failure_halts_globally_without_raw_exception`, `test_cancelled_interrupt_validation_releases_queued_submission`으로 복수 중단, 감사 실패, 중단 확인 취소 경계를 검사한다.

## A 인계

Codex `turn/interrupt`를 먼저 보내 새 도구 호출을 막고 `interrupt_turn`을 호출한다. `CALL_COMPLETING`이면 Guard가 끝까지 커밋한 결과를 끊긴 턴의 Codex에 돌려주지 않는다. 승인 카드는 취소됨으로 표시하고 `TURN_INTERRUPTED`를 사유 문구에 연결한다. 판정 중이었다가 ASK가 생긴 대상 제출은 나중에 `cancelled` 최종 알림이 오므로 그 알림도 끊긴 턴에 돌려주지 않는다. 실제 codex.exe에서 응답 처리 방식은 A가 확인한다.

## C 확인 요청

1. `TURN_INTERRUPTED`와 `CANCELLED`, 그리고 소비 전 `APPROVED → CANCELLED`의 제한적 종결을 확인한다.
2. 취소된 승인은 `approval_consumed`·`host_dispatch`·wire가 0인지 독립 계수한다. 중단 시점에 lock 대기 중이던 제출은 `host_dispatch`·wire 0, lock을 잡고 처리 중이던 제출과 예약 뒤 호출은 최대 1인지 확인한다. A가 끊긴 턴의 결과를 Codex에 보낸 수 0도 연결 뒤 확인한다.

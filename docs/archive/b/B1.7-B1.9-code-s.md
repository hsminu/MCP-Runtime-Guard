# B1.7·B1.9 공통 포트와 Scanner 코드 보완

2026-10-30 · B 담당. [결정 요청 #106](https://github.com/hsminu/MCP-Runtime-Guard/issues/106)의 B 제안 기본값을 구현했으며, A·C의 답과 남은 연결 확인을 대신하지 않는다.

## B1.7

2026-10-18 [#20 결정](https://github.com/hsminu/MCP-Runtime-Guard/issues/20#issuecomment-6246812317)에 따라 `ModelClient` Protocol을 공통 `ports.py`에서 제거하고 같은 시그니처를 `examples/legacy_model_client.py`로 옮겼다. 기존 대화 DTO와 legacy 실행 의미는 유지한다. A 소유 예제 `legacy_model_client.py`와 `legacy_runner.py` 두 파일은 Protocol 이동과 import 변경 부분에 대해 A 확인이 필요하다.

## B1.9

[#57 B 리뷰](https://github.com/hsminu/MCP-Runtime-Guard/pull/57#issuecomment-6464199374)와 [C 반영](https://github.com/hsminu/MCP-Runtime-Guard/pull/57#issuecomment-6464509185)에 맞춰 `Finding.code`를 영문·숫자·밑줄·공백 1~64자로 제한했다. C 번역은 같은 범위를 `fullmatch`하고 밖의 값은 `SCAN_CODE_UNRECOGNIZED`로 바꾸므로 현재 번역 출력은 호환된다. 확인한 기존 B·C 시험 보고서에 형식 위반 코드는 없었다.

과거 도메인 `Identifier`는 하이픈·점 등도 허용했고 C 번역이 필터를 적용하기 전에도 원래 코드를 저장할 수 있었다. 따라서 이미 저장된 보고서에 그런 코드가 있다면 등록 조회에서 보고서를 재검증하면서 `StoreError(INTERNAL_ERROR)`가 발생할 수 있다. 실제 SQLite의 합성 과거 행으로 이 실패와 행 불변·원문 비노출을 확인했다. 실제 사용자 DB에 위반 행이 있는지는 확인하지 않았다. 자동 변환·이관은 추가하지 않았다.

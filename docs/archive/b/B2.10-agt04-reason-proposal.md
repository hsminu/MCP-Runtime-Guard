# B2.10 · AGT-04 reason code와 AccessResult 정리 제안

2026-10-27 · **합의 전 제안** · PR 미정 · 기준 main `60cb165`, B 구현 HEAD `36d4d45`. B2.9·B2.11 구현과 검증은 [완료 기록](B2.9-B2.11-agt-removal.md)에 있다. 이 제안에서는 domain enum 값·저장 행·공통 계약을 바꾸지 않았으며 A·B·C 합의가 필요하다.

## 배경과 현재 사용처

## 대안

| 안 | 변경 | 장점과 비용 |
| --- | --- | --- |
| (a) 기존 코드 유지 | `AGT_DENY`·`AGT_ERROR`의 enum·저장값은 그대로 두고 UI 문구만 접근 규칙으로 표시한다. | 이전 기록을 그대로 읽는다. 새 감사·판정 문자열에 제거된 제품 이름이 계속 남는다. B2.11 표시 변경의 범위다. |
| (b) 새 코드 추가, 기존 코드는 읽기 호환용 유지 | `ACCESS_DENY`·`ACCESS_ERROR`를 추가하고 새 판정은 새 코드로 기록한다. `AGT_*`는 기존 행 읽기용으로 유지하고 UI에서는 두 쌍을 같은 뜻으로 표시한다. | 과거 데이터의 enum 해석을 유지하며 새 기록에서 AGT 이름을 없앤다. domain 계약 변경, 정책·고정 문구표·UI·저장/조회·테스트의 동시 검토가 필요하다. |
| (c) 이름 변경과 저장 행 이관 | 코드명을 바꾸면서 제안된 v3 이관 때 과거 AGT 사유 문자열을 새 문자열로 다시 쓴다. | 저장 형식을 하나로 줄일 수 있으나 판정 이유 배열 및 감사 행의 보존 의미와 실패/복구·재시도·검증을 함께 정해야 한다. 기존 감사 증거를 변환하므로 이관 위험이 커진다. SEQ-03/v3는 별도 제안·구현 범위다. |

**B 추천은 (b)**다. 기존 요청 행의 enum 읽기와 과거 감사 문자열을 깨지 않고 새 기록에 현재 개념을 쓰기 때문이다. 신설 코드의 모델 공개 여부를 자동으로 늘리지 않고 기존 고정 거절 정책을 유지해야 한다. (b)도 A·B·C 합의 전에는 구현하지 않는다. 명시적인 요구가 없는 한 기존 행을 덮어쓰거나 새 이름으로 추정해 변환하지 않는다.

## AccessResult 범위와 민감 정보

- `src/guard_app/domain/models.py:159–164`의 `allowed`, `reason`, `error` 필드는 유지했다. `reason`은 기본 repr에서 숨긴다. B2.11에서 AGT 표현을 접근 규칙 설명으로 고치는 docstring만 바꿨다.
- `core/access_rules.py:49–60`의 자체 규칙 reason은 `ACCESS_RULES_INVALID`, `ACCESS_REQUEST_INVALID`, `ACCESS_RULE_DENY`, `ACCESS_RULE_ALLOW`, `ACCESS_RULE_MISSING`이고, `adapters/access_rules_checker.py:27–30`의 신뢰 맥락 불일치는 `ACCESS_CONTEXT_MISMATCH`다. 이 경로는 값 자체를 reason에 이어 붙이지 않으며 모두 고정 코드다.
- 이 확인은 자체 판정기 반환값의 범위다. 임의의 다른 판정기가 반환하는 `reason`이 언제나 고정 값임을 증명하지 않는다. 사용자 입력·인자·문서·예외 원문을 로그·감사·repr로 넘기는 근거로 쓰지 않는다(I9).

## A·B·C 영향과 확인할 것

- **A:** UI reason 매핑에서 과거 `AGT_*`와 새 `ACCESS_*`를 같은 한국어 의미로 구분 없이 표시할지 확인하고, 조회 화면·내보내기에서 미지의 값과 이전 기록을 처리한다. 코드 표시 여부는 UI와 모델 전달을 혼동하지 않는다.
- **B:** 합의 뒤 `domain/reasons.py`, `core/policy.py`, `core/model_messages.py`, 관련 단위 테스트를 묶어 변경한다. 과거 요청·감사 행은 보존하고 신규 판정, 오류·거부 합성, 고정 문구 완전성, 과거 기록 읽기를 검증한다. 스키마 개정 여부는 별도 계약으로 정한다.
- **C:** 새/기존 reason 각각의 차단 dispatch·수신 효과 0 계수, 새 모델 공개 코드 없음, 과거 저장 행 읽기와 잘못된 사유의 fail-closed를 독립 검증한다. 감사 조회 계층이 생기면 그 계층의 타입·미지 코드 처리도 확인한다.

## 공통 계약 문안 제안(사용자 반영)

> AGT-04: B 제안은 `ACCESS_DENY`·`ACCESS_ERROR`를 새 판정용으로 추가하고 `AGT_DENY`·`AGT_ERROR`는 기존 요청·감사 기록 호환을 위해 유지한다. UI는 같은 의미로 표시하고 모델에는 기존 고정 거절 정책을 유지한다. domain·판정·저장/조회·표시 변경은 A·B·C 합의와 C 독립 검증을 거쳐 수행한다. 기존 데이터 이관은 별도 결정한다.

검증: 위 사용처와 테스트 단언을 정적으로 대조했다. B2.9·B2.11 전체 검사 결과는 [완료 기록](B2.9-B2.11-agt-removal.md)에 있다. 이 제안에 따른 새 enum·이관은 구현하거나 검증하지 않았다.

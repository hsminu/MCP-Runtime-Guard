# B3.11 CFG-01 설정 바이트 변환

2026-10-26 · B 담당 순수 변환 구현 완료 · I6/I9 · B3.9/B3.10 후속

main `58afdd4`를 포함하는 병합 커밋 `177e0f5`에서 작업했다. P14에 제공된 CFG-01 사용자 결정 요약(JSON v1 봉투·1MiB·깊이 64·UTF-8 BOM 규칙)을 구현했다. 로컬 공통 계약에는 CFG-01·LIST-01 결정 행이 아직 없으며, PR #34 원문/최신 병합 상태는 **확인 불가**다. 공통 문서는 수정하지 않았다. [이전 제안](B3.11-settings-file-proposal.md)은 당시 제안으로 보존한다.

## 바꾼 파일과 공개 API

| 파일 | 변경 |
| --- | --- |
| `src/guard_app/services/catalog.py` | `SettingsFileError`, `parse_settings_bytes`, `serialize_settings_bytes`와 공개 export, 기존 로더 설명 연결 |
| `tests/unit/test_settings_file.py` | 새 순수 변환 단위 테스트 105개 |
| `docs/b-status.md` | B3.11 B 구현 완료, C2.14·B3.12 대기 분리 |
| 이 기록 | 규칙·검증·A/C 연결 요청 |

```python
def parse_settings_bytes(
    data: bytes, *, max_bytes: int = 1_048_576, max_depth: int = 64
) -> dict[str, object]: ...

def serialize_settings_bytes(
    settings: Mapping[str, object],
    *,
    max_bytes: int = 1_048_576,
    max_depth: int = 64,
) -> bytes: ...
```

두 함수는 파일·경로·프로세스·Registry에 접근하지 않는다. `domain/*`·`ports.py`에 CFG-01 API/DTO를 추가하지 않았다. B3.9 Profile 필드 검증과 전체 설정의 JCS SHA-256 계산은 그대로다. 바이트에서 Profile까지 한 번에 로드하는 편의 함수는 추가하지 않았다. A가 C의 안전 읽기→B 파싱→기존 로더/C 검증을 명시적으로 연결할 수 있고, 바이트 해석과 Profile 검증의 실패 단계도 구분할 수 있기 때문이다.

## 파싱·직렬화 규칙

- 읽기는 받은 bytes의 길이(BOM·공백 포함)를 먼저 제한하고, 맨 앞 UTF-8 BOM 한 개만 제거한 뒤 엄격한 UTF-8로 디코드한다. UTF-16 자동 감지·대체 디코드는 없다. BOM 두 개 또는 공백 뒤 BOM은 JSON으로 거부한다.
- JSON 파서 전에 문자열·따옴표·역슬래시 escape를 구별해 컨테이너 깊이를 검사한다. 봉투 객체가 1, settings 객체가 2다. 루트와 모든 중첩 객체의 디코딩된 키 중복은 hook에서 거부한다.
- NaN·Infinity·-Infinity 토큰과 `1e999` 같은 유한 범위 초과 float를 거부한다. JCS와 동일하게 정수는 ±(2**53−1), float는 유한 binary64다. 큰 정수 토큰은 int 생성 전에 길이로 제한한다. 문자열·키의 unpaired surrogate도 거부한다.
- 봉투 키는 `schema_version`, `settings` 두 개만 받는다. 버전은 bool/float/문자열이 아닌 정확한 정수이며 1만 지원한다. settings는 객체여야 한다. 파싱은 독립된 dict/list 사본을 반환하며 Profile 필드·참조·실행 권한은 검증하지 않는다.
- 쓰기는 최상위 Mapping을 JSON 사본으로 분리하고 내부는 정확한 dict/list/str/int/float/bool/None만 허용한다. 비문자열 키·tuple·bytes·임의 객체·순환을 암묵 변환하지 않는다. 공유 하위 값은 각각 복사하고 입력을 수정하지 않는다.
- 저장 입력은 **`PreparedPolicyChange.document.to_dict()`**다. `_Configuration.model_dump(mode="json")`은 정책 해시용 정규화 사본이며 등급 이름이 숫자가 되므로 외부 파일 저장용으로 사용하지 않는다. 파싱·직렬화는 기본값/등급/TTL을 보정하지 않는다.
- 쓰기는 키 정렬, 들여쓰기 2칸, `ensure_ascii=False`, BOM 없는 UTF-8, LF, 마지막 LF 한 개를 사용한다. 배열 순서는 유지하며 출력 bytes 전체가 상한 이하여야 한다. pretty bytes는 JCS 바이트가 아니고 policy_version 입력도 아니다.
- max 인자는 신뢰된 호출자의 정확한 양수 int만 허용한다. 파일 안의 max 값으로 완화되지 않는다. 사용자 지정 깊이를 높여도 Python 파서/직렬화/사본 생성의 재귀 한계를 넘으면 고정 깊이 오류로 거부한다.

표준 JSON의 기본값은 중복 키·비유한 수를 허용하고 키/tuple을 변환할 수 있어 hook·명시적 값 검사·`allow_nan=False`를 사용했다. 표준 함수와 hook 의미는 [Python 3.12 JSON 공식 문서](https://docs.python.org/3.12/library/json.html)로 대조했다. 이 설명은 C 파일 연산의 원자성·내구성 검증이 아니다.

## 고정 오류

`SettingsFileError`는 `ValueError`의 하위 타입이며 `.code`, `args`, str/repr에 고정 코드만 담는다. 생성자에 정의 밖 코드가 들어와도 원문 대신 `SETTINGS_JSON_INVALID`가 된다. 알려진 디코드·JSON 파서·재귀 오류는 `from None`으로 번역한다. 예외 원문·입력 bytes·경로 필드는 추가하지 않았다.

| 코드 | 의미 |
| --- | --- |
| SETTINGS_LIMIT_INVALID | 상한이 정확한 양수 int가 아님 |
| SETTINGS_TOO_LARGE | 읽기/쓰기 bytes가 상한 초과 |
| SETTINGS_ENCODING_INVALID | bytes 타입/UTF-8 또는 Unicode scalar 위반 |
| SETTINGS_JSON_INVALID | JSON 구문·값 타입·문자열 키·순환 위반 |
| SETTINGS_DUPLICATE_KEY | 디코딩된 객체 키 중복 |
| SETTINGS_NONFINITE_NUMBER | 비표준 상수·overflow·비유한 float |
| SETTINGS_NUMBER_RANGE | JCS 안전 정수 범위 초과 |
| SETTINGS_TOO_DEEP | 봉투 포함 컨테이너 깊이/재귀 한계 초과 |
| SETTINGS_ENVELOPE_INVALID | 키·버전 타입·settings 객체 형식 위반 |
| SETTINGS_VERSION_UNSUPPORTED | 형식이 맞는 정수 버전이 1이 아님 |

Profile 필드 오류는 기존 `CatalogConfigError`가 맡는다. parse 성공을 설정 적용 성공이나 Task 시작 권한으로 보지 않는다. 오류를 기록할 때 호출자가 원래 파일 내용·파서 context를 별도로 로그에 넣어서는 안 된다.

## 실제 검증

기존 Windows 로컬 환경과 `..\.dev-tools\uv-tool\bin\uv.exe run --no-sync`를 사용했다. 설치·uv sync·의존성 변경은 하지 않았다. pytest는 `QT_QPA_PLATFORM=offscreen`과 저장소 아래 basetemp를 사용했다.

- 샌드박스 안: 새 `test_settings_file.py` **105개 통과**, pytest cache 쓰기 권한 경고 1건.
- 샌드박스 밖 승인 실행: 새 변환·기존 Profile/정책 변경·failclosed·C 리뷰 후속·RegistryStore 6개 파일 **431개 통과**, pytest cache 쓰기 권한 경고 1건. 비동기 Windows socketpair 정지를 피하기 위해 밖에서 실행했다.
- 샌드박스 안: `ruff check .` 통과, `ruff format --check .` 203개 파일 통과, `python -m mypy` 82개 소스 파일 통과.

왕복한 PreparedPolicyChange의 policy_version, 키 배치·공백·들여쓰기·BOM과 해시 독립, 사본 불변성, 한글 출력 크기·마지막 LF 포함 상한, 깊이 64/65, 파서 호출 전 예산, escape된 중복 키, BOM 두 개/잘못된 인코딩, 비유한/큰 수·순환·비 JSON 값, 잘못된 봉투·버전·상한, 로그/오류 원문 비노출을 검사했다. 기존 Profile/정책 변경 테스트는 수정하지 않았다.

- 샌드박스 밖 승인 실행: `uv run --no-sync python -m pytest -q --basetemp=.test-artifacts/codex --tb=short -o faulthandler_timeout=25` **4,304개 통과·1개 skip·20 subtest 통과**, 158.64초. 제외한 테스트는 없다. main의 UI keyboard 수정이 포함된 상태에서 정상 종료했고, 첨부의 A HTTP 타이밍 단언 실패도 재현되지 않았다.
- 전체 실행의 경고 6건은 기존 AGT 관련 폐기 4건, Pydantic forward 필드 1건, pytest cache 쓰기 권한 1건이다. 실패로 바꾸거나 원문 로그를 추가하지 않았다.
- 최종 `git diff --check`, 변경 파일 소유 범위와 완료 기록 링크 검사를 통과했다. 전체 검증 뒤에는 문서만 갱신했다.

## A·C에 전달할 것과 남은 한계

- **A 요청:** 시작 때 C가 안전하게 읽은 bytes를 `parse_settings_bytes`로 해석하고 settings만 `load_profile_settings`에 넘긴다. 파일 없음은 설정 화면으로 안내하고 Task 시작을 막는다. 파싱 오류를 빈 설정/첫 실행 성공으로 바꾸지 않는다.
- **A 요청:** 저장 때 B3.10 준비 결과를 `serialize_settings_bytes(change.document.to_dict())`로 변환해 C의 원자적 교체에 전달한다. 저장 성공 뒤 Guard 적용, 새 Task 생성과 직렬화 순서를 유지한다. 실행 중 자동 재로딩·백업 fallback은 추가하지 않는다.
- **C 요청:** C2.14에서 결정된 LocalAppData 경로·권한·크기 제한 읽기·단일 writer/세대 충돌·임시 파일/원자적 교체·불명 ACK를 구현·독립 검증한다. 파일 바이트 읽기 상한은 BOM과 공백까지 포함하며 B도 재검사한다. 자동 백업은 없음이다.
- 이번 작업은 바이트 변환만 완료했다. C의 파일 연산/경로·실행 파일 검증, A의 제품 시작·설정 화면·실제 저장/정책 적용, wire/부작용 계수와 Windows 파일 내구성은 미검증이다. B3.12는 대기 상태다.
- PR #34 원문과 A/C 최신 구현/인수는 확인하지 않았다. 첨부 결정 요약을 기준으로 구현했고 공통 문서는 사용자 소유로 유지했다. 현재 브랜치에 커밋하며 push·PR 생성은 하지 않는다. Claude outputs/는 읽기만 했다.

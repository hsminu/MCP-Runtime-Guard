# B6.13-2 SQLite writer의 늦은 결과 전달

2026-10-30 · B 담당 후속

SQLite writer가 비동기 작업 결과를 전달할 때 Future가 이미 끝났거나 대상 이벤트 루프가 이미 닫혔으면 `call_soon_threadsafe`를 호출하지 않는다. 검사와 호출 사이에 루프가 닫히는 경합은 남으므로 기존 `RuntimeError` 처리도 유지한다. 동기 작업의 이벤트 전달과 쓰기 결과 판정은 그대로다.

## 재현과 한계

- 최신 A 브랜치 `ae3c6a3`에서는 5회 실행 중 abort가 없었다. 과거 C 제보 커밋 `2950f79`에서는 별도 5회 중 1회 abort를 관찰했다. 그때 스택은 writer의 `Condition.wait`와 메인 스레드의 `Event.wait`였으며, C가 보고한 `call_soon_threadsafe` 스택과 달랐다. 같은 원인이라고 단정할 수 없다.
- 원인에 대한 C의 가설은 이벤트 루프가 닫히는 동안 writer가 `call_soon_threadsafe`로 결과를 보내 Windows proactor의 self-pipe 쓰기와 경합한다는 것이다. 이번에 관찰한 스택은 이 가설을 확인하지 못했으며, 중단의 원인은 미확정이다.
- A의 `tests/unit/test_store_query_link.py`는 실제 `SQLiteStore`를 생성하거나 `wait_closed`를 호출하지 않는다. 이 파일에서 특정 테스트의 실제 Store 정리 누락을 단정할 수 없다.
- 시작된 읽기는 호출자가 취소되더라도 `asyncio.shield` 때문에 내부 Future가 대기 상태로 남는다. 이때 루프가 열려 있으면 이번 가드는 결과 전달을 막지 않는다. 즉 이번 변경만으로 취소된 모든 읽기의 늦은 전달이 방지되는 것은 아니다.
- 이미 시작한 쓰기는 완료까지 기다린 뒤 취소를 전파한다. COMMIT 결과 판정과 결과 불명 시 실행 권한 차단·연결 폐기는 결과 전달 전에 writer에서 처리한다.
- Store 소유자는 `close()`를 요청한 뒤 `wait_closed()`의 성공을 확인하고 이벤트 루프를 닫아야 한다. 시간 안에 종료가 확인되지 않은 경우는 종료 미확인으로 처리해야 한다.

## 검증

추가한 회귀 테스트 6개는 수정 전 실패했고 수정 후 통과했다. Ruff·format·mypy와 B writer·저장소 집중 시험 291개가 통과했다.

수정 커밋 `7a92450`에 A 브랜치 `ae3c6a3`을 임시 병합한 합본을 10회 실행한 결과, 1회 abort가 발생했고 나머지 9회는 각각 47개 시험이 통과했다. abort 스택은 writer의 `Condition.wait`와 메인 스레드의 `Event.wait`로, 별도 과거 커밋 재현과 같은 위치였으나 C가 보고한 전달 스택은 아니었다. 이번 가드로 프로세스 중단이 해결됐다고 결론 내릴 수 없다.

## 원인 조사

가설은 A의 `test_store_query_link.py`에서 남은 순환 참조의 QObject가 이후 B 시험의 메인이 아닌 스레드에서 가비지 컬렉션될 때 Qt가 abort한다는 것이다. `mrg-check`의 임시 합본에서 `QT_QPA_PLATFORM=offscreen`, `QT_LOGGING_RULES=*.debug=true`, `python -X faulthandler`, `-p no:cacheprovider`, `-s`로 두 시험 파일을 각 조건에서 독립 프로세스로 20회 실행했다. `-s`는 Qt stderr가 pytest 캡처에 가려지지 않게 한다.

| 조건 | abort | 결과 |
| --- | --- | --- |
| writer 수정 적용, GC 추가 없음 | 0/20 | 매회 47개 통과 |
| writer 수정 적용, 각 A 시험 종료 뒤 메인 스레드에서 `gc.collect()` | 0/20 | 매회 47개 통과 |
| writer 수정 제거, 같은 메인 스레드 GC | 0/20 | 매회 47개 통과 |

60회 stderr는 모두 비어 있어 Qt fatal 메시지를 관찰하지 못했다. GC 대조의 중단 0회는 가설의 예상과 일치하지만 GC가 없는 기준 조건도 0회였고, QObject가 어느 스레드에서 소멸했는지는 직접 관찰하지 않았으므로 중단 원인을 확정할 수 없다. writer 수정은 늦은 결과 전달을 줄이는 별도 보강이다. 임시 시험 fixture와 writer 변경은 실험 후 원래 바이트로 복원했다.

# B3.14 EXE-01 실행 파일 고정 설정 필드

2026-10-28 · B 설정 구현 · EXE-01 · I6/I9

## 한 일

- `ServerSettings`에 `command_sha256`과 `command_size`를 추가했다. 등록 화면에서 C `pin_executable`이 계산하고 사용자가 확인한 지문·크기를 저장하는 값이다. 설정 로더는 파일을 열거나 프로세스를 실행하지 않는다.
- stdio는 두 필드가 모두 있거나 모두 없어야 한다. 필드가 없는 stdio는 미고정 상태로 로딩하며, 실제 실행 허용 판단은 C launcher의 책임이다. HTTP는 두 필드를 모두 생략해야 한다. 명시적인 `null`, 부분 쌍, 형식 불일치는 전체 설정을 `CatalogConfigError`로 거부한다.
- 지문은 정확한 소문자 16진수 64자이며, 크기는 bool이 아닌 정수 1 이상 `2**53 - 1` 이하로 제한한다. 오류와 repr에 경로·지문 원문을 내보내지 않는다. 새 의존성과 Reason은 없다.
- `schema_version`은 1이다. 두 필드가 없는 서버는 해당 키를 정책 해시의 정규화 표현에서도 생략해 기존 설정의 `policy_version`을 보존한다. 유효한 두 값은 전체 설정의 해시에 포함된다. 파일 직렬화는 원본 문서를 보존한다.
- 근거는 #48 B 답변·C 동의, #54의 `ExecutablePin` 변환 위치 합의, #58 A 리뷰 질문이다. C launcher 구현은 현재 이 역할 브랜치에서 확인되지 않았고 별도 통합이 필요하다.

## 실제 검증

- 수정 전 HEAD `c47191e`에서 기존 `tests/unit/test_profile_loading.py::_document()`의 `policy_version`은 `70571a21f71d7ec0493867c597db21d0f6b2e6d12f022b34092026faa319d062`였다. 미고정 필드가 없는 같은 문서의 수정 후 값도 같다.
- stdio의 유효 pin·미고정, 한쪽 누락, 명시적 null, 대문자·길이·16진수·줄바꿈 오류, 크기 범위·bool·float, HTTP 필드 금지와 원문 비노출을 확인했다. 고정 필드 변경에 따른 해시 변경과 pin 유무별 저장·파싱·로딩 왕복도 확인했다. 신규 EXE-01 집중 테스트는 **29 passed**이고 기존 Profile·설정 테스트는 **224 passed**다.
- 시작 전 전체 pytest 첫 실행에는 `test_runtime.py::test_successful_stop_reads_as_success[cancel_button-작업 취소]`와 `test_sqlite_app.py::test_clean_bridge_restart_runs_real_synthetic_send` **2건 실패**가 있었다. Qt/백엔드 조건이 충족되지 않았고 원인은 미확정이다. 두 테스트를 각각 5회 독립 재실행해 모두 통과했고, 이어진 전체 재검사는 Windows 샌드박스 밖 **4956 passed, 4 skipped, 2 warnings, 20 subtests passed**였다. 당시 실패를 없던 일로 처리하지 않고 관찰 결과를 남긴다.
- 구현 커밋 `9668b1f` 전체 pytest: Windows 샌드박스 밖 **4985 passed, 4 skipped, 2 warnings, 20 subtests passed**, 실패 0. Ruff·format·mypy 통과.

## A 연결과 남은 검증

A는 서버 등록 화면에 경로·크기·지문을 보여 주고 사용자 확인 뒤 `command_sha256`·`command_size`를 설정에 저장한다. 시작 연결에서 값이 있으면 `ExecutablePin(command_size, command_sha256)`으로 변환하고 둘 다 없으면 None을 C launcher에 전달한다. C의 실제 파일 핀 검사·미고정 실행 거부·A 화면 및 연결 검증은 이 B 설정 필드 작업의 완료에 포함하지 않는다.

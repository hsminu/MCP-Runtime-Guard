# B3.15·B3.16 서버 설정 검사와 Registry 저장

2026-10-29 · B 단위 구현 · URL-01·[#50](https://github.com/hsminu/MCP-Runtime-Guard/issues/50)·[#46](https://github.com/hsminu/MCP-Runtime-Guard/issues/46)·[#52](https://github.com/hsminu/MCP-Runtime-Guard/issues/52)·[#59](https://github.com/hsminu/MCP-Runtime-Guard/issues/59)·[#74](https://github.com/hsminu/MCP-Runtime-Guard/issues/74)

URL과 Registry 설정의 불일치는 해당 서버만 숨기는 합의에 따라 B Catalog와 저장소를 변경했다. 이 기록의 B 단위 구현은 A 제품 연결이나 C 리뷰·독립 인수 완료를 뜻하지 않는다.

## 서버별 설정 검사

`load_profile_settings`는 HTTP 서버마다 C `canonical_endpoint`를 호출하고 `EndpointError`의 고정 코드만 기록한다. 문제가 있는 서버는 Registry가 제공하는 등록과 무관하게 Catalog 해석 및 `tool_views`에서 제외되며 다른 서버는 계속 사용할 수 있다. transport별 필드와 문자열 형식 오류는 기존처럼 전체 설정 오류다. 검사는 원래 설정의 `policy_version` 계산을 바꾸지 않는다.

`LoadedProfile.server_issue(server_id)`는 실행 허가가 아닌 읽기 전용 진단이다. 등록의 `tier`·`max_label` 또는 설정 도구의 `kind`·`resource_arg`·`destination_arg`가 다르면 등록 상태와 무관하게 `REG_SETTINGS_MISMATCH`를 반환하고 해당 서버를 숨긴다. 조회 ID와 등록 ID가 다르거나 등록 모델이 잘못된 내부 오류는 계속 `CatalogConfigError`다. 선택하지 않은 서버, 등록이 없고 URL 이슈도 없는 서버, 문제가 없는 서버는 `None`이다. URL 이슈는 Registry 불일치보다 우선한다.

URL 고정 코드는 `URL_INVALID`, `URL_SCHEME`, `URL_USERINFO`, `URL_QUERY`, `URL_FRAGMENT`, `URL_HOST`, `URL_IDNA`, `URL_PORT`, `URL_PATH`, `URL_ADDRESS_FORBIDDEN`, `URL_HTTP_NOT_LOOPBACK`, `URL_NOT_CANONICAL`이다. 서버 URL·예외 원문은 진단 코드나 repr에 넣지 않는다.

## Registry 변경과 검사 보고서

`RegistryStore.record_settings_change`는 사용자 입력의 도구 이름과 정의·지문이 현재 등록과 일치하는지 확인한다. revision CAS 뒤 `kind`·`destination_arg`·`resource_arg` 변경만 반영하며 입력의 검토 설명은 사용하지 않는다. 실제 변경 시 해당 도구의 기존 검토 설명을 비우고 ACTIVE는 PENDING으로 내린다. BLOCKED와 PENDING은 유지하고 기존 검사 ID는 보존한다. `REGISTRY_SETTINGS_CHANGED`, `REG_NOT_ACTIVE`, 변경 수를 감사하며 RECOVERED 단계에서도 허용한다. 변경 없음은 CAS 확인 후 쓰기와 감사 없이 현재 사본을 반환한다.

도구 이름·정의·지문 불일치는 `TOOL_FINGERPRINT_CHANGED`다. 저장소의 기존 경로에는 SEND의 목적지 인자 필수 같은 종류·인자 조합 검사가 없으므로 이번에는 추가하지 않았다. 설정의 `ToolSettings` 검증과 구분한다. 경계의 `tier`·`max_label` 변경 저장 경로는 이번 합의 범위에 없고 불일치 서버는 숨겨진다.

`record_scan_report`는 같은 쓰기 트랜잭션에서 보고서와 현재 등록 도구의 지문 **집합**을 대조한다. 다른 목록이면 `TOOL_FINGERPRINT_CHANGED`로 저장과 감사를 하지 않는다(#59). 사용자 승인에 따라 C 테스트 한 곳을 새 저장 단계 거부에 맞게 변경했다(C 리뷰 대상, #59 합의). 변경된 테스트는 저장 전후 DB revision과 last_scan을 비교하고, 저장되지 않은 scan의 활성화도 거부되는지 확인한다. C `ScanService`에는 이 저장소 오류를 `SCAN_LISTING_NOT_REGISTERED`로 변환하는 경로가 이미 있다.

요청 실패 저장의 예외 형식 이름 상한을 실패 감사와 같은 64자로 맞췄다. 64자는 저장하고 65자는 고정 오류로 거부한다. 기존 Guard·worker의 정상 경로는 64자 초과 형식 이름을 `Exception`으로 축약한다.

검사 보고서 단계의 첫 전체 실행에서는 기존 C 테스트가 다른 목록의 보고서 저장 성공을 기대해 한 개가 실패했다. #59 합의와 사용자 승인에 따라 지문 대조 커밋 뒤 C 테스트 한 곳을 별도 커밋 `aa761e1`로 바꾸고 전체 검사를 통과했다. 그 밖의 C 테스트·코드는 고치지 않았다. A 테스트도 #52에서 동의한 한 곳만 별도 변경했다.

`test_access_rules.py`는 변경 전에 독립 실행 10회 모두 **81 passed**로 시간 제한 실패가 재현되지 않았다. 순수 함수의 `@given` 시험에 `deadline=None`을 설정했고, 원래 간헐 실패의 원인은 확인되지 않았다. Semgrep·Bandit은 이 Windows 환경에서 실행하지 않았다.

## A·C 요청과 남은 범위

- A: `server_issue`로 연결 대상과 `REG_SETTINGS_MISMATCH`·`URL_*` 화면 문구를 처리하고, 저장 값과 파일 값을 나란히 보여 준다. 재확인 순서는 `record_settings_change` → 설정 저장 → 정책 적용 → 다시 활성화다.
- C: `ServerRegistry.apply_settings`를 `record_settings_change`에 연결하고 변경된 C 테스트를 리뷰한다. 기존 `ScanService`의 오류 변환을 포함해 경쟁 경로를 독립 검증한다.
- 경계 변경을 저장하는 경로와 저장소 수준의 종류·인자 조합 검사는 이번 범위 밖이다. A·C 제품 연결 및 독립 인수는 남아 있다.

`B2.9-B2.11-agt-removal.md`의 `ports.py` 불일치 설명은 `21b68da`에서 정정됐다. 병합된 기록은 고치지 않는다.

## C 리뷰 후속(#86)

`LoadedProfile.selected_servers`는 설정에서 선택한 서버를 그대로 유지하고, 실행 시작용 `startable_servers`를 추가했다. 설정 순서는 유지하며 현재는 `URL_*` 이슈가 있는 서버만 제외한다. `REG_SETTINGS_MISMATCH` 서버는 포함하고 `server_issue`는 URL 이슈와 설정 불일치를 각각 계속 알린다. `policy_version` 계산은 바꾸지 않았다.

A 리뷰에 따라 설정 불일치 서버를 남긴다. A155에서 도구 종류를 고쳐 저장하면 설정이 Registry보다 앞설 수 있는데, 서버를 시작해야 목록 기록의 observe → `record_fingerprint_change`가 Registry를 따라오게 할 수 있다. 이때도 Catalog는 불일치 서버를 숨기고 Guard는 거부하므로 실행 권한이 생기지 않는다. A155가 `record_settings_change` 순서로 옮겨지고 C `apply_settings`가 연결되면 `REG_SETTINGS_MISMATCH`도 시작 대상에서 제외한다.

A 요청: `_server_streams`, `_record_listings`, `collect_registration_listing`에서 `startable_servers`를 사용한다. A 동의에 따라 `test_settings_that_differ_from_the_registration_stop_the_assembly`의 이름을 실제 검증 뜻에 맞게 `test_settings_that_differ_from_the_registration_hide_only_that_server`로 바꿨고 내용은 바꾸지 않았다.

### 의존성과 lock

`pyproject.toml`에서 직접 의존 `agent-governance-toolkit-core==5.0.0`와 삭제된 모듈의 mypy override, AGT 테스트 전용 Ruff 예외를 제거했다. `uv.lock`에서 없어지는 패키지 8개는 다음이다.

`agent-governance-toolkit-core` 5.0.0, `agentrust-trace` 0.2.0, `dnspython` 2.9.0, `email-validator` 2.3.0, `pynacl` 1.6.2, `python-dateutil` 2.9.0.post0, `six` 1.17.0, `structlog` 26.1.0. `cryptography` 등 다른 의존 경로가 남은 패키지는 그대로다. 의존성 추가는 없다.

지정 uv 캐시에 Scanner 패키지 인덱스 메타데이터가 없어 `uv lock --offline`은 실패했다. 사용자가 로컬 PowerShell에서 `uv lock`을 직접 실행해 **127개 패키지 해석, 8개 삭제**를 확인했다. 이후 Codex가 `uv export --locked --all-groups --no-emit-project -o requirements.lock`으로 CI 파생 lock을 갱신했고, 같은 명령 재실행 전후 SHA-256이 같았다. CI가 파생 lock의 추적 diff를 검사하므로 `requirements.lock`도 함께 갱신했다. `uv sync`나 의존성 설치는 실행하지 않았다. 새 환경 설치 재현은 A02·A06에서 별도 확인이 필요하다.

## B2.9 · 동기 AccessChecker 제안

`ports.AccessChecker.check_access(req, ctx) -> AccessResult`를 **동기**로 정의했다. 신뢰 `TaskState`와 운영자 ID를 담은 `TrustedContext`로 사전 판정 후 평가마다 한 번 호출한다. 사전 DENY는 접근 판정기를 호출하지 않는다. 접근 규칙은 거부권만 가지며 사람 승인이나 Guard의 ASK/DENY를 완화하지 않는다. 판정기 안의 I/O·대기·스레드·하위 프로세스는 포트 계약에서 금지한다.

- Guard 생성과 `apply_policy_change`는 호출할 수 없는 `check_access` 또는 coroutine 함수 구현을 고정 오류로 거부한다. 정확한 `AccessResult`만 받고 다른 반환값은 `error=True` DENY로 처리한다. 실수로 반환된 coroutine 객체는 실행하지 않고 닫는다.
- `_wait_for_access`, `_discard_access_result`, `_access_checks`, `_unfinished_access_checks`, `_access_task_ids`, `access_timeout_seconds`, `max_access_checks`, `access_cleanup_timeout_seconds`와 이들의 검사·정리 코드를 제거한다. `examples/synthetic_app.py`에서도 삭제된 시간 제한 인자를 넘기지 않는다.
- 사전 판정 → 접근 판정 → 최종 판정, Task lock, 정지 확인 및 승인 재판정 경로를 보존한다. 동기 호출 사이 같은 이벤트 루프에 await 지점은 없지만, 주입된 Registry의 현재 상태·지문 재조회는 방어적 대조로 유지한다. 정지 신호는 실제 정지 요청에서 만들고 lock·승인 관계가 남거나 종료 ACK가 미확정이면 보존한다.
- 일반 판정기 예외는 기존 `fail_closed`에서 고정 거부와 예외 **형식만** 담은 실패 감사로 처리한다. 예외 원문을 결과·감사에 넣지 않는다.
- **취소 특례:** 판정기 또는 잘못 반환된 coroutine의 `close()`에서 직접 발생한 `CancelledError`는 내부 `_AccessCheckCancelled` 표식으로 구분한다. 예약 전 경계에서 Task 정지·감사와 필요한 승인 최종 알림을 먼저 처리하고, 원문의 취소 메시지 없이 취소를 다시 전파한다. 격리/알림 실패는 전역 정지 경계를 사용한다. 이미 격리한 표식은 중첩 경계에서 다시 격리하지 않는다. `KeyboardInterrupt` 등 나머지 `BaseException`은 삼키지 않는다. 일반 asyncio Task 취소의 기존 단계별 Denied·격리 의미는 별도로 유지한다.
- `security.failclosed.fail_closed`에 내부 취소 알림용 선택 키워드 `on_access_cancelled`가 추가된다. 이는 내부 경계의 선택 인자이며 외부 API 합의나 사용자 조작을 뜻하지 않는다. 그 밖에 새 domain 필드·enum은 없다.

공개 계약 변화: `AccessChecker.check_access` 호출자는 더 이상 `await`하지 않는다. `GuardService` 생성자에서 위 접근 대기 관련 3개 인자가 사라진다. A 테스트의 직접 호출도 동기 호출로 바꾼다. 별개인 `ModelClient` 포트와 legacy 시연은 B1.7/A66 합의 전까지 유지한다.

## B6.15·AGT-04와 공통 계약 문안

`services/catalog.py:805–812`는 정규화 접근 규칙을 전체 설정의 JCS SHA-256 `policy_version`에 포함한다. `tests/unit/test_profile_loading.py:368–379,396–404`는 순서·중복 정규화와 규칙 내용 변경 시 버전 변경을 검증한다. `PolicyDecision`은 버전을 갖고 SQLite 판정 저장 시 Task 버전과 대조한다(`domain/models.py:193–201`, `storage/sqlite_store.py:1199–1205`). `tasks.policy_version`은 영속화되며 Task 갱신에서 변경을 거부한다(`storage/sqlite_store.py:111–115,1992–2007`).

`requests`·`audit_events` 행에는 버전 자체가 없다(`storage/sqlite_store.py:139–156,175–185`). `DECIDED` 감사는 Task와 요청 ID를 쓰지만 Registry 감사는 둘 다 NULL로 기록한다(`storage/sqlite_store.py:1229–1236,843–845`). 정상 Task와 연결된 요청은 Task를 통해 버전을 추적할 수 있으나, 모든 판정·감사 행의 직접 저장 조건은 확인되지 않아 **B6.15는 미완료**다. Task 없는 이벤트에 버전이 필요한지, 간접 조회를 허용할지, 직접 저장 시 스키마·기존 행 이관을 어떻게 할지는 별도 합의가 필요하다. 감사 범위와 이관을 결정하고 원자 기록·실패·누락을 C가 독립 검증해야 한다.

AGT-04는 새 `ACCESS_DENY`·`ACCESS_ERROR`를 추가해 신규 판정에 쓰되, 기존 `AGT_*`를 과거 행 읽기용으로 유지하는 (b)를 B가 추천한다. `requests.reasons`는 읽을 때 `Reason(...)`으로 검증한다. `audit_events.reason_code`는 별도 TEXT이며 그 감사 조회의 enum 검증은 확인되지 않았다. 코드 변경은 3인 합의 대기다. 세부: [B2.10 제안](B2.10-agt04-reason-proposal.md).

# B2.10 AGT-04: 접근 규칙 사유 코드와 저장 호환

2026-10-29 · B 단위 구현 · AGT-04

공통 계약의 [2026-10-28 사용자 결정과 AGT-04 행](../../contracts.md), [#20](https://github.com/hsminu/MCP-Runtime-Guard/issues/20)·[#47](https://github.com/hsminu/MCP-Runtime-Guard/issues/47)의 A·B·C 동의에 따라 새 접근 규칙 판정의 `AGT_DENY`·`AGT_ERROR`를 `ACCESS_DENY`·`ACCESS_ERROR`로 바꿨다. B 단위 구현 완료와 A 리뷰·C 독립 contract 테스트 완료는 구별한다. 병합된 [이전 제안](B2.10-agt04-reason-proposal.md)은 당시 기록으로 보존한다.

## 변경 위치

| 위치 | 전 | 후 |
| --- | --- | --- |
| `domain/reasons.py` | `AGT_DENY`, `AGT_ERROR` | 같은 순서의 `ACCESS_DENY`, `ACCESS_ERROR` |
| `core/policy.py` `evaluate` | 접근 거절·오류에 `AGT_*` | 각각 `ACCESS_DENY`·`ACCESS_ERROR`; 판정 순서는 그대로 |
| `core/model_messages.py` | `AGT_*` 키 | `ACCESS_*` 키. 두 문구와 공개 사유 집합은 그대로 |
| A `ui/presentation.py` `REASONS` | `AGT_*` 키 | `ACCESS_*` 키. 접근 규칙 거절·확인 실패 문구는 그대로 |
| A `examples/ui_demo.py` | 시연 사유 `AGT_DENY` | `ACCESS_DENY` |
| checker 예외 | `INTERNAL_ERROR` | B2.9의 `INTERNAL_ERROR`·예약 전 실패 감사·요청 행 없음 유지 |

접근 판정기가 `AccessResult(error=True)`를 돌려주는 경우의 `ACCESS_ERROR`와 판정기가 실제 예외를 던지는 경우는 구분한다. 사용자는 후자를 기존 B2.9 동작으로 유지하도록 결정했다. 새 사유나 스키마·DDL·`user_version` 변경은 없다.

## 저장된 사유 판독

`storage/sqlite_store.py`의 `_LEGACY_REASONS`와 `_stored_reason` 한 곳에서 옛 `AGT_DENY`·`AGT_ERROR`를 각각 새 enum으로 해석한다. 현재 `Reason` 값도 검증하며, 그 밖의 값과 문자열이 아닌 값은 입력 원문을 내보내지 않는 `StoreError`로 거부한다.

| 경로 | 처리 |
| --- | --- |
| 요청 행 읽기 | `_decode_stored_request`가 저장 사유를 `_stored_reason`으로 검증한다. 현재 내부 조회 DTO는 이유를 외부에 반환하지 않는다. |
| 시작 복구 | 동일 판독으로 사유를 검증하고, 모르는 값은 `STORE_INTEGRITY_FAILED`로 전체 롤백한다. 복구 상태 판정에 사유의 의미를 쓰지는 않는다. |
| 감사 읽기 | 현재 사유를 읽는 `OBSERVED` 감사 비교가 `_stored_reason`을 쓴다. 별도 감사 조회 API가 생기면 같은 함수를 사용해야 한다. |
| v3 이관 | 사유 TEXT는 읽거나 바꾸지 않고 원문 그대로 복사한다. 명시 시작에서는 이관 뒤 복구가 판독·검증한다. |

27b에서 복구가 이유를 해석하지 않던 조건은 이 판독 함수 도입 전의 임시 조건이었다. 이번에는 C 조건 1·2에 맞춰 저장 사유를 검증하되 복구의 상태 표는 바꾸지 않는다. 과거 요청의 `reasons`와 감사의 `reason_code`는 다시 쓰지 않으며, 옛 문자열을 새 문자열로 DB에 이관하지 않는다.

## 검증

Windows에서 각 코드 커밋 전 Ruff·format·mypy가 통과했다. 전체 pytest 결과는 아래와 같다. 각 전체 실행에는 **5 skipped, 2 warnings, 20 subtests passed**가 포함됐다.

| 단계 | 전체 pytest |
| --- | --- |
| 코드 교체 | 5626 passed, 실패 0 |
| 저장소 판독 | 5674 passed, 실패 0 |

새 판독 테스트 48개와 기존 복구 테스트 37개는 집중 실행에서 85개 통과했다. 새 테스트는 두 옛 문자열과 전체 현행 사유, 알 수 없는 값의 거부, 실제 Guard·SQLite의 새 거절/오류 판정, v2 이관 및 원문 보존, 복구의 잘못된 사유 거부와 감사 판독을 확인한다. 잘못된 `FOO` 사유 복구 테스트는 변경 전 코드에서 `DID NOT RAISE`로 실패했고 구현 후 통과했다. 기존 `test_checker_exception_is_denied_and_audit_keeps_only_exception_type`도 두 전체 실행에 포함되어 통과했다.

## 남은 요청

- A: 표시 사유 키를 바꾼 `ui/presentation.py`와 시연 값 `examples/ui_demo.py`를 리뷰한다.
- C: 새 판정·감사에 `AGT_*`가 없고 옛 행이 `ACCESS_*`로 해석되는 contract 테스트를 독립 수행한다. `tests/unit/c_counting.py`의 양쪽 이름 허용은 병합 뒤 단순화할 수 있다.
- 별도 감사 조회 API가 생기면 `_stored_reason`을 적용한다.

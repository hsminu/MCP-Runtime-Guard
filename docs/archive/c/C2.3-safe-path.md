# C2.3 · 파일 서버 경로 검사 `safe_path`와 Guard 기대 ID

관련: 2026-10-15 사용자 결정(로컬 파일은 우리가 만든 읽기 전용 파일 MCP 서버로만, `safe_path`로 정규화, 결과 `structuredContent.resource_id`를 Guard가 대조), 개발문서 4.2·13.2절, T33, B `services/catalog.py`(`ResourceResolver`, `classify_read`)·`catalog_sources.canonical_resource_parts`, C2.11(파일 서버), C2.4(검사-열기 경쟁).

## 배경

- B Catalog의 `ResourceResolver = Callable[[ToolSpec, str], str]`는 요청 인자를 "C `safe_path`로 검증한 root 기준 POSIX ID"로 바꾼다. 제품에는 이 해석기가 없어서, 문서 읽기 같은 자원형 READ의 기대 ID를 계산할 수 없었다(테스트에는 인자를 그대로 쓰는 대역만 있었다).
- Catalog는 서버가 보고한 ID가 기대 ID와 정확히 같을 때만 출처 규칙을 적용하고, 그 비교는 대소문자를 가린다(`classify_read`, 세그먼트 접두어). 그래서 표기가 다른 같은 파일이 다른 ID가 되면 안 된다.
- 개발문서 13.2절 참고 코드는 Windows의 대소문자·짧은 이름·`:`(드라이브·ADS)·장치 이름·끝 점과 하드링크를 다루지 않는다.

## 한 일

- **`security/paths.py`**
  - **`safe_path(root, user_path) -> Path`:** 루트 아래의 파일·폴더 하나를 실제 경로로 돌려준다. 오류는 고정 코드(`SafePathError`)이고 경로를 싣지 않는다.

    | 코드 | 경우 |
    | --- | --- |
    | `PATH_INVALID` | 빈 값, 4,096자 초과, 문자열 아님, 짝 없는 서로게이트, 제어 문자(DEL 포함), 역슬래시·`:`·`<>"\|?*`, 절대 경로, `.`·`..`·빈 조각(끝 `/` 포함), 끝 점·공백, 장치 이름(`CON`·`CON.txt`·`NUL.md`·`COM1` 등). 디스크를 보기 전에 거부한다 |
    | `PATH_LINK` | 루트 아래 조각 중 심볼릭 링크나 junction이 있음. 루트 밖을 가리키든 안을 가리키든 거부한다 |
    | `PATH_NOT_FOUND` | 없는 파일·폴더 |
    | `PATH_OUTSIDE_ROOT` | 풀린 경로가 루트 밖이거나 루트 자신 |
    | `PATH_HARDLINK` | 하드링크가 둘 이상인 파일. 루트 밖 파일 내용을 루트 안 이름으로 읽는 길이 된다 |
    | `PATH_NOT_REGULAR` | 일반 파일·폴더가 아님 |
    | `PATH_ROOT_INVALID` | 루트가 `Path`가 아니거나, 상대 경로이거나, 없거나, 폴더가 아님 |

    - 루트 자신은 junction을 거쳐도 된다. 루트를 먼저 실제 경로로 풀고, 그 아래 조각만 검사한다.
  - **`resource_id(root, user_path) -> str`:** 위 실제 경로를 루트 기준 POSIX ID로 만든다. 조각은 디스크의 실제 이름이라 `public/report.txt`·`PUBLIC/REPORT.txt`·8.3 짧은 이름이 모두 `Public/Report.TXT`가 된다(사용자 선택: 실제 이름). 결과는 B `canonical_resource_parts`를 통과한다.
  - **`file_resource_resolver(roots) -> ResourceResolver`:** 서버 ID별 루트로 B Catalog의 해석기를 만든다.
    - 경로 거부는 원문 없이 `ResolutionError(INVALID_ARGUMENTS)`다.
    - 루트가 없는 서버는 `ResolutionError(INTERNAL_ERROR)`로, Catalog의 해석기 미연결과 같다.
    - 루트는 부를 때마다 다시 확인한다.
  - 장치 이름 목록은 C2.6에서 공개한 `RESERVED_DEVICE_NAMES`를 같이 쓴다.
- **NTFS 동작(테스트로 확인)**
  - `Path.resolve`(최종 경로)는 디스크의 실제 대소문자와 긴 이름을 돌려준다.
  - junction은 `is_junction()`, 심볼릭 링크는 `lstat`의 링크 비트로 잡힌다.
  - 하드링크는 원본과 새 이름 모두 `st_nlink` 2다.
- **테스트** `tests/unit/test_safe_path.py` 48개(1개는 심볼릭 링크 권한이 없으면 건너뜀)
  - 파일·폴더 해석, 대소문자 표기 2가지, 8.3 짧은 이름(볼륨이 만들면)이 모두 실제 이름 ID
  - 형식 거부 31가지. 오류 repr에 경로가 없음
  - 없는 파일, 루트 밖·안을 가리키는 junction, 심볼릭 링크(권한 있을 때)
  - 루트 밖 파일의 하드링크, 루트 안 하드링크 쌍
  - junction을 거친 루트, 잘못된 루트 3가지, 잘못된 해석기 설정 4가지
  - **B Catalog와 맞물림(실제 SQLiteStore·ServerRegistry)**
    - 소문자로 요청해도 기대 ID는 실제 이름이고, 출처 규칙(`Public`→PUBLIC, `personal`→INTERNAL)이 적용된다.
    - 서버가 다른 파일이나 다른 표기를 보고하면 분류하지 않는다(T33).
    - 상위 경로·없는 파일·역슬래시는 호출 전에 `INVALID_ARGUMENTS`이고, 오류에 경로가 없다.
    - 루트가 없는 서버는 `INTERNAL_ERROR`다.

## A·B 연결

- **A 조립:** `ProductInputs.resource_resolver`에 `file_resource_resolver({파일 서버 ID: 루트})`를 넣는다. 루트를 설정 어디에 둘지는 C2.11에서 A·B와 정한다.
- **B:** Catalog는 그대로다. 해석기 오류 번역은 Catalog 설명(알려진 거부는 원문 없는 `ResolutionError`)을 따른다.

## 남는 것

- **C2.4 검사-열기 경쟁:** 이 함수가 검사한 뒤 서버가 여는 사이에 경로가 바뀔 수 있다. Windows에는 `O_NOFOLLOW`가 없다. C2.11 서버가 다음 두 가지로 막는다.
  - 쓰기 금지 핸들로 연 뒤 핸들의 실제 경로·파일 ID가 이 결과와 같은지 다시 대조한다(C2.18 방식).
  - 결과 `resource_id`를 Guard가 대조한다.
- **심볼릭 링크 실측:** 이 PC는 심볼릭 링크를 만들 권한이 없어 그 테스트는 건너뛰었다. 검사는 `lstat` 링크 비트이고 junction 쪽은 실측했다.
- **루트가 사용자 폴더 전체일 때:** 하드링크 거부로 일부 시스템 파일(하드링크 2개 이상)은 읽을 수 없다. 문서 폴더에서는 드물다.

리뷰: B(테스트·Catalog 연결), A(조립).

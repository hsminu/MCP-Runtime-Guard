# C2.21 · B3.14 지문 필드에서 실행 입구까지 (EXE-01)

관련: EXE-01, [C2.6](C2.6-mcp-server-launch.md)(`pin_executable`·`launch_mcp_server`), B3.14(`ServerSettings.command_sha256`·`command_size`, #58), [C2.11](C2.11-file-server.md), #48.

## 배경

- B3.14가 설정 레코드에 등록 지문 필드를 더했다.
- A 연결 규칙: 두 값이 있으면 `ExecutablePin(command_size, command_sha256)`, 없으면 None을 C 실행 입구에 넘긴다.
- B 기록은 "C의 실제 파일 지문 검사·미고정 실행 거부·연결 검증은 B 작업에 포함하지 않는다"고 적었다.
- C2.6 시험은 지문을 직접 만들어 넘겼고, 설정 레코드를 거친 경로는 없었다.

## 한 일

- **`tests/unit/test_mcp_server_launch.py`에 3개 추가**
  - 실행 입구는 설정 파일과 같이 JSON 문서에서 엄격 모드로 읽은 `ServerSettings`를 받는다. 그 레코드에서 B3.14 변환(시험 안 `_launch_pin`)을 거친 지문을 넘긴다.
  - **등록 지문을 담은 레코드:** `pin_executable` 결과를 두 필드에 저장한 레코드로 띄운다.
    - 꺼낸 지문은 등록 지문과 같다.
    - A transport로 `tools/list`까지 된다.
  - **두 필드가 없는 레코드:** 지문이 None이고 `LAUNCH_EXECUTABLE_UNPINNED`다. 서버 폴더에 아무것도 생기지 않는다.
  - **등록 뒤 같은 크기로 내용이 바뀐 실행 파일:** `LAUNCH_EXECUTABLE_MISMATCH`다.
    - 오류에 지문이 없다.
    - stderr 파일이 생기지 않는다(실행 전 거부).
- **`tests/unit/test_file_server.py`:** 파일 서버 끝에서 끝까지 시험의 레코드가 두 필드를 담고, 실행 지문을 레코드에서 꺼낸다(A 등록 화면이 저장할 모양).
- 제품 코드는 바꾸지 않았다.

## 검증

- `test_mcp_server_launch.py` 62개 통과(3회 같음)
- `test_file_server.py` 통과
- 단위 + contract pytest는 [C2.8](C2.8-log-redaction.md)과 같은 실행

## A 연결

- **등록 화면:** `pin_executable(command)` 결과의 `sha256`·`size`를 `command_sha256`·`command_size`에 저장한다.
- **시작 연결:** 레코드에서 위 변환으로 지문을 만들어 `launch_mcp_server`에 넘긴다.
- **오류 문구:** #48 C 회신의 코드표를 따른다.

리뷰: B(시험), A(등록 화면·시작 연결).

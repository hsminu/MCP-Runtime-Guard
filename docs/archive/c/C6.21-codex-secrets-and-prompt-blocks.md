# C6.21 · CODEX_HOME `secrets/` 허용과 L1 Codex 안내 끄기

관련: I9·I11, T22·T43, C-CODEX-06·C-CODEX-08. 결정: contracts.md 2026-10-27 두 행(#38), #21 A107·A108.

## 한 일

- **`secrets/` 허용(`security/codex_home.py`)**
  - Codex 0.162.1은 `cli_auth_credentials_store = "keyring"`이어도 토큰을 `CODEX_HOME/secrets/codex_auth.age`(age 암호문)에 두고, 그 암호만 자격증명 관리자에 둔다(`codex-rs/secrets/src/local.rs`·`lib.rs`, `rust-v0.162.1`). C6.19 허용 목록이 이 폴더를 거부해서, 로그인한 뒤에는 Task를 시작할 수 없었다(A108 재현).
  - 최상위에 `secrets` 폴더를 허용한다. 안쪽은 `codex_auth.age`·`local.age`·`mcp_oauth.age`·`gateway_oauth.age`의 일반 파일만 받는다.
  - 결정 문구보다 하나를 더 받는다. Codex가 암호문을 바꿀 때 먼저 쓰는 임시 파일 `.<이름>.tmp-<pid>-<nonce>`(같은 `local.rs`)다. 동시 실행 중 다른 Task가 토큰을 갱신하거나 쓰다가 끊기면 보인다. 받지 않으면 그 순간 새 Task가 거부되거나, 끊긴 뒤로는 계속 거부된다.
  - 링크·junction·하위 폴더·다른 이름은 거부한다. 내용은 읽지 않고 해시 대조에서도 뺀다. `write_codex_home`은 이 폴더를 지우거나 덮어쓰지 않는다(앱 시작 때 로그아웃되지 않음).
- **L1 안내 끄기(`config/codex/config.toml`)**: `include_permissions_instructions = false`, `include_environment_context = false`. 두 키는 0.162.1 `ConfigToml`의 최상위 필드다(`codex-rs/config/src/config_toml.rs:257·266`). `codex.lock.json`의 `config.toml` SHA-256을 `b314c116…ca75c6`로 갱신했다. 주석의 자격증명 설명도 실제 저장 방식으로 고쳤다.

## 검증

- `test_codex_home.py`: 암호문·임시 파일 허용과 내용 변경 뒤 확인 통과, 재시작 때 암호문 유지, `secrets` 안 다른 이름·폴더·잘못된 임시 이름 거부, `secrets`가 파일이면 거부, L1 두 키 확인.
- 실제 codex.exe로 이 설정을 다시 띄워 보지는 않았다. A107의 같은 두 플래그 실행 결과(첫 요청 10,060→5,674바이트, 동작 동일)를 근거로 하고, C6.14 L2의 요청 프롬프트 대조에서 확인한다.

## 남은 것

- C6.14: 요청 프롬프트 대조 기준에서 `<permissions instructions>`와 `<environment_context>`가 빠진 것을 확인한다.
- 디스크에 남는 암호문은 C-CODEX-08로 기록했다(받아들임).

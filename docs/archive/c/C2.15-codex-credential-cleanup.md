# C2.15 · Codex 로그아웃 정리 함수

관련: I9, T43, C-CODEX-08. 결정: contracts.md 2026-10-27(#38) "로그아웃 정리는 C가 함수로 만들고 A가 `account/logout` 성공 뒤 부른다".

## 한 일

- `security/codex_home.py`에 두 함수를 더했다.
  - `clear_codex_credentials(codex_home)`
    - `secrets/` 안의 암호문과 임시 파일을 지운다.
    - 자격증명 관리자의 대상 `secrets|<h16>.codex`와 `secrets|<h16>|gateway-oauth.codex`를 지운다.
    - `secrets/` 안에 모르는 항목이 있으면 아무것도 지우지 않고 `CODEX_HOME_UNEXPECTED_ENTRY`를 낸다.
    - 자격증명 항목이 이미 없으면(`ERROR_NOT_FOUND`) 성공으로 본다. 그래서 여러 번 불러도 된다.
    - 그 밖의 실패는 `CODEX_CREDENTIAL_DELETE_FAILED`다. Windows가 아니면 `CODEX_CREDENTIAL_UNSUPPORTED`다.
  - `keyring_account(codex_home)`: Codex `compute_keyring_account`와 같은 규칙이다. `secrets|` 뒤에 정규 경로 UTF-8의 SHA-256 앞 16자를 붙인다.
    - Rust `canonicalize`는 Windows에서 `\\?\C:\…` 형태를 돌려준다. 같은 값을 얻으려고 `GetFinalPathNameByHandleW`(정규화 이름·DOS 볼륨)를 쓴다.
    - 대상 이름 `<계정>.<서비스>`와 서비스 `codex`는 A108이 실제 자격증명 항목에서 관찰한 형식과 같다.
- **A 연결**: `account/logout` 성공 뒤, Codex 프로세스가 끝난 다음 `clear_codex_credentials(app_paths.codex_home)`를 부른다. 실패하면 고정 문구로 알린다(경로 없음).

## 검증

- 단위 테스트
  - 암호문 삭제와 두 대상 이름(`_delete_credential` 대역)
  - 다시 불러도 성공
  - 모르는 항목이 있으면 아무것도 지우지 않음
  - `\\?\` 정규 경로와 계정 해시 계산
  - 없는 자격증명 항목 삭제는 성공(실제 `CredDeleteW` 호출, 없는 이름)
- 실제 로그인 계정의 항목을 지우는 실행은 하지 않았다. A가 연결한 뒤 로그인 → 로그아웃 → 정리 → 자격증명 관리자에서 항목이 사라졌는지를 T43으로 확인한다.

## 남은 것

- CODEX_HOME 경로가 바뀌면 `h16`이 바뀌어 옛 항목이 고아로 남는다. 앱 폴더는 고정 위치(C2.13)라 평소에는 생기지 않는다.

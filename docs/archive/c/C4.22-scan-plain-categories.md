# C4.22 · Scanner 경고를 사용자가 읽을 분류로 보이기

2026-10-30 · 관련: C4.9(번역)·C4.13(경고 제공)·C4.15·C4.17, A201(경고 화면), 2026-10-13·2026-10-15 Scanner 결정, I7·I9, T17·T18.

## 배경

- A201의 Scanner 경고 화면은 검사 결과를 그대로 나열했다. 발견 한 줄이 `LLM · 위험도 높음 · HIGH · 코드 PROMPT INJECTION` 식이었다.
- 그 밖에도 위험도가 둘(SDK 위험도, LLM 자체 평가)이었고, 분석기 이름(LLM·YARA)과 진단 코드가 앞에 보였다.
- 그래서 사용자는 무엇이 문제이고 무엇을 해야 하는지 알기 어려웠다. "직접 판단하세요"라고 하면서 판단 근거가 없었다.
- 사용자 지시로 화면을 "한 줄 결론 → 도구별 쉬운 분류 → 접힌 자세히" 순서로 바꿨다. 분류표는 Scanner 결과를 번역하는 C가 맡고, 화면은 A 파일이라 A 리뷰를 받는다.

## 한 일

### C: 분류표 `services/scan_categories.py`(새 모듈)

`scan_category(code) -> ScanCategory(name, meaning, action)`

| 분류 | 코드(설치본 4.8.6 LLM·YARA) |
| --- | --- |
| 모델 조종 | `PROMPT INJECTION` |
| 도구 설명 오염·위장 | `TOOL POISONING`, `TOOL SHADOWING` |
| 정보 유출 | `DATA EXFILTRATION` |
| 인증정보 요구 | `CREDENTIAL HARVESTING` |
| 명령·코드 실행 | `CODE EXECUTION`, `SUSPICIOUS CODE EXECUTION`, `INJECTION ATTACK`, `SYSTEM MANIPULATION` |
| 기타 위험 신호 | 그 밖의 모든 코드(`SECURITY VIOLATION`, `unknown`, `SCAN_CODE_UNRECOGNIZED`, 새 이름) |

- 대소문자와 띄어쓰기·밑줄 차이는 같은 코드로 본다. 설치본 이름에 두 표기가 섞여 있기 때문이다.
- 모르는 코드는 낮은 위험으로 바꾸지 않고 "기타"로 둔다. 분류는 표시용이고 위험도·활성화·승인·판정을 바꾸지 않는다.
- 어떤 문구에도 "안전"이라고 쓰지 않는다.

### A 파일(사용자 지시, A 리뷰 필요)

- `services/bridge.py`: UI는 `services.bridge`만 import할 수 있어서 `scan_category`·`ScanCategory`를 다시 내보낸다(두 줄).
- `tests/unit/test_a_architecture.py`: 새 서비스 모듈을 A 밖 목록(`OTHER_SERVICES`)에 넣었다.
- `ui/scan_report.py`
  - **등록 검사 창:** 맨 위에 "주의할 점 3개 · send_note, login_helper" 같은 한 줄 결론을 둔다. 발견이 없으면 "보고된 위험 없음"이다("안전"이라고 쓰지 않는다). 끝내지 못한 검사가 있으면 그것도 한 줄로 알린다.
  - **도구 카드:** 분류마다 한 줄(같은 분류를 LLM·YARA가 함께 내면 더 높은 위험도 하나), 뜻 한 줄, "권장:" 한 줄을 보인다.
  - **자세히(처음엔 접힘, 기존 `linkButton` 접기 방식):** 검사 시각·버전, 분석기 결과, 원래 코드, LLM 자체 평가, 모델 설명("검증되지 않은 내용" 상자)을 넣었다. 기존 화면에 있던 내용은 모두 여기 그대로 있다.
  - **승인 창:** 분류와 뜻만 보인다. 권장 조치("이 도구를 끄세요")는 승인 창에서 할 수 없는 일이라 뺐다. 나머지는 자세히에 둔다.
- `tests/unit/test_a201_scan_report_ui.py`
  - 모델 설명 표시 시험이 자세히를 펼친 뒤 확인하도록 고쳤다.
  - 시험 3개를 더했다.
    - 분류 한 줄·중복 합치기·접힌 원래 코드·펼침
    - 발견 없음 문구와 "안전" 미사용
    - 승인 창에서 권장 조치 없음

## 남는 것

- Scanner를 올려 위협 이름이 바뀌면 `test_the_installed_names_are_the_ones_the_table_was_written_for`가 실패한다. 그때 분류표를 함께 고친다.
- 실제 Cisco 검사 결과로 실제 앱 창에서 등록 → 검사 → 활성화를 눌러 보지는 않았다. 고정 보고서와 offscreen 렌더링만 썼다.
- C4.13(경고 제공) 인수는 실제 앱에서 등록 화면·승인 창을 확인한 뒤 따로 체크한다.
- 문구는 사용자 확인이 필요하다. 특히 분류 이름과 권장 조치는 시연 화면에 그대로 나온다.

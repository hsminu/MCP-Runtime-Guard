# C2.21 · Codex 브라우저 로그인 URL 검증과 기본 브라우저 열기

관련: A109(#70, 브라우저 로그인 A 연결부), 2026-10-29 사용자 결정(기기 코드 제한 안내와 브라우저 로그인 지원), I9(로그인 URL·비밀값 비노출), I6(실패·미확인), C-CODEX-05(로그인 방식).

## 배경

- A109는 `account/login/start {type: "chatgpt"}`가 돌려준 `authUrl`을 주입 함수 `BrowserLoginOpener`(`Callable[[str], Awaitable[bool]]`)에만 넘긴다. 그 함수가 없어서 제품에서는 브라우저 로그인 버튼이 꺼져 있었다.
- 계약: 실패는 False, 예외는 `CancelledError`만, URL·예외 원문을 남기지 않는다. 일반 예외를 던지면 A는 Codex 로그인을 취소하지 않는다(#70 C 리뷰 2). 그래서 C 쪽에서 계약을 지킨다.

## 고정 Codex가 주는 URL (2026-10-29 확인)

고정 0.162.1 `codex.exe app-server`를 임시 CODEX_HOME으로 띄워 `account/login/start {type: "chatgpt"}`만 보내고 바로 `account/login/cancel`했다(`canceled`). 브라우저는 열지 않았다.

- `https://auth.openai.com/oauth/authorize?` 뒤 쿼리, 길이 470자, fragment 없음
- 쿼리 10개
  - `response_type=code`
  - `client_id=app_EMoamEEZ73f0CkXaXp7hrann`
  - `redirect_uri=http://127.0.0.1:1455/auth/callback`(퍼센트 인코딩)
  - `scope=openid profile email offline_access api.connectors.read api.connectors.invoke`(`+` 구분)
  - `code_challenge`(43자)·`code_challenge_method=S256`
  - `state`(43자)
  - `id_token_add_organizations=true`·`codex_cli_simplified_flow=true`·`originator=mcp_runtime_guard`
- 원문 문자: 영문·숫자와 `% & + - . / : = ? _`

## 한 일

- `security/login_browser.py`
  - `check_login_url(url)`: 위 모양만 받고 그 문자열을 그대로 돌려준다. 다르면 `LoginUrlError("LOGIN_URL_INVALID")`이고 원문을 싣지 않는다.
    - 원문 문자 집합 `[A-Za-z0-9-._~:/?&=+%]`, 퍼센트 이스케이프 형식, 길이 4,096자
    - 접두어 `https://auth.openai.com/oauth/authorize?` 정확 일치. 다른 scheme·호스트(대문자 포함)·포트·사용자 정보·경로·fragment 거부
    - 쿼리 키는 알려진 10개만 한 번씩. 필수 7개(`response_type`·`client_id`·`redirect_uri`·`scope`·`code_challenge`·`code_challenge_method`·`state`)
    - 값: `client_id`는 Codex 값과 같음, `redirect_uri`는 `http://127.0.0.1|localhost:<1–65535>/auth/callback`, `scope`는 위 6개 안에서 `openid` 포함, `S256`만, `code_challenge` 43–128자·`state` 32–256자(base64url 문자)
  - `make_login_opener(shell=None)`·`open_login_browser`: A `BrowserLoginOpener` 구현
    - 검증에 실패하면 셸을 부르지 않고 False다.
    - 셸은 실행기 스레드에서 `ShellExecuteExW`(`open`, `SEE_MASK_NOASYNC`·`SEE_MASK_FLAG_NO_UI`, `SW_SHOWNORMAL`)를 부른다. 스레드는 COM을 단일 스레드 아파트로 열고, 연 경우에만 닫는다.
    - 셸이 정확히 True일 때만 True다. `OSError`·`RuntimeError`(닫히는 실행기)는 원문을 버리고 False다. 취소는 그대로 올린다.
    - `cmd`·`subprocess`·`os.startfile`(Bandit B606)을 쓰지 않는다. 로그를 남기지 않는다.
- `tests/unit/test_ids.py`의 C 모듈 목록에 더했다.

## 왜 이렇게까지 좁혔나

- 호스트만 보면 Codex app-server가 다른 OAuth 앱(`client_id`)이나 외부 콜백(`redirect_uri`), 넓힌 권한(`scope`)으로 동의를 받게 하는 URL도 통과한다. 고정 Codex는 이 값을 바꾸지 않으므로 다르면 거부한다.
- Codex를 올려 모양이 바뀌면 검증이 False를 돌려주고 A가 로그인을 취소한다(실패 쪽). 그때 위 확인 방법으로 다시 본다.

  - Windows 바인딩: 구조체 크기 112(64비트), 인자 형식, 플래그 값. 실제로 열지는 않는다.

## 남은 것

- **A 연결:** 제품 시작부(`__main__`)에서 `codex.account_access(open_browser=open_login_browser)`로 넘긴다. A 파일이라 C는 바꾸지 않았다.
- **실제 열기와 로그인:** 기본 브라우저가 새 탭으로 여는지, 실제 계정으로 로그인한 뒤 Codex가 완료를 알리는지는 A 연결 뒤 사용자 PC에서 확인한다(A109 남은 항목). 시험은 브라우저를 열지 않는다.
- **취소 한계:** 취소는 기다림만 끝낸다. 이미 시작한 `ShellExecuteExW`는 끝까지 실행되어 취소 직후 브라우저가 열릴 수 있다. A가 Codex 로그인을 취소하므로 콜백은 남지 않는다.
- **콜백 포트:** Codex의 로컬 콜백(`127.0.0.1:1455`)은 Codex가 관리한다. 같은 사용자의 다른 프로세스가 그 포트를 먼저 잡는 경우는 이 모듈 범위 밖이다(위협 모델 밖 같은 사용자 프로세스).

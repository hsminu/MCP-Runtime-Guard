- `src/guard_app/security/codex_home.py`: `load_codex_pins`, `write_codex_home`(원본을 고정값과 대조 → 임시 파일 후 교체 → 다시 읽어 확인 → 묶음 해시 반환), `verify_codex_home`(Task 시작 전 확인). 상대 경로·링크·junction인 CODEX_HOME을 거부하고 오류는 고정 코드만 쓴다.

- 단위 테스트 `tests/unit/test_codex_home.py`, `tests/unit/test_install_codex.py`.

## 실제 검증

1. **소스 대조**(`rust-v0.162.1` 소스): `features/src/lib.rs` 기능 표 167개와 대조해 config의 feature 키가 모두 실재함을 확인했다. 0.162.1은 모르는 키를 경고만 하고 무시한다(711행). 최상위 키는 `config/src/config_toml.rs`, `keyring`은 "keyring을 못 쓰면 실패" 모드다(`config/src/types.rs`). 기본값이 켜진 다른 Stable 기능은 데스크톱 앱 요구사항 게이트·전송 옵션·exec 하위 승인이라 모델 도구를 늘리지 않는다.
2. **실행 스모크**([근거](../evidence/c6.13-codex-l1-smoke-2026-10-18.json)): 설치 스크립트로 둔 codex.exe 0.162.1, `write_codex_home`으로 쓴 CODEX_HOME, 환경변수 허용 목록, `-c sqlite_home=<Task 폴더>`, 가짜 모델(스모크 전용 `-c model_provider`)로 실행했다.
   - `configRequirements/read`의 `requirements`는 null이다. `config/read` 값이 설정과 같고, 상대 경로 `model_catalog_json`은 CODEX_HOME 기준으로 풀린다. 켜진 feature는 `mentions_v2`(TUI 팝업)뿐이다.
   - 모델 요청의 도구는 `functions.request_user_input`, `local_docs.read_document` 두 개뿐이다. 이 모델 정보는 `use_responses_lite`라 도구가 최상위 `tools`가 아니라 입력의 `additional_tools` 항목으로 간다.
   - 첫 실행에서 프롬프트에 `skills_instructions`(내장 skill 목록과 CODEX_HOME 경로)가 들어가고 CODEX_HOME에 `skills\.system` 72개 파일이 생겼다. `[skills]` 설정을 더한 뒤 둘 다 없어졌다. CODEX_HOME에는 `config.toml`·`model_catalog.json`·`installation_id`·`.sandbox_migration`만 남고, 로그·상태·goals·memories·queue DB는 모두 Task 폴더에 생겼다.
3. **설치**: tarball sha512 일치, 설치 결과 codex.exe 하나, `codex --version`이 0.162.1, 재실행 시 기존 파일 유지.
4. **코드 검사**: Ruff·포맷·mypy 통과. 새 단위 테스트는 결정된 기능이 모두 꺼졌는지, 저장소 파일이 고정값과 바이트 단위로 같은지, 변조·누락·다른 해시·고정값과 다른 원본·잘못된 CODEX_HOME·형식이 틀린 고정값 파일, 설치의 무결성·해시 불일치·멤버 누락·링크 멤버를 확인한다. 심볼릭 링크 테스트는 이 PC에서 링크 생성 권한이 없어 건너뛰었다.

## 남은 한계와 후속

- 금지 도구 7종 강제 호출 거부·한 응답의 두 호출 순차·요청 프롬프트·`config/read` 대조 자동화는 L2(C6.14)다. 이번 실행은 L1 결과물 확인용이다. L2가 가짜 모델에 붙을 때 쓰는 `-c` 오버라이드와 "Task별 `-c sqlite_home`만 허용" 규칙은 대조 대상 프로세스가 다르다는 점을 C6.14에서 정해야 한다.
- 제품 CODEX_HOME(임시 폴더가 아님)에서는 Codex가 `tmp\arg0\` 아래 `apply_patch.bat` 등 보조 파일을 만든다(`arg0/src/lib.rs`). 이번에는 임시 폴더라 거부됐다. C6.16·C2.13에서 확인한다.
- Windows 기본값 `secret_auth_storage`는 keyring 모드에서 암호화 로컬 저장소를 쓸 수 있다. CODEX_HOME에 인증 파일이 생기는지는 T43(#21 8번)에서 확인한다.
- `CODEX_CONFIG_DIR` 기본값은 소스 checkout 기준이다. 설치 패키지에서의 위치는 A 패키징과 맞춘다. 폴더의 사용자 전용 권한은 C2.13이다.
- 이 PC의 npm 전역 Codex는 0.163.0이다. 고정 버전과 실험 기준은 0.162.1이다.

# C6.12 · 공격 fixture를 제품 스캔에서 제외 (AF-01)

관련: 개발문서 13.5절("`attack_fixtures/`는 스캔 대상에서 제외"), [C2.9](C2.9-ci-static-checks.md)(CI 정적 검사), C5.8(`attack_fixtures/scanner_limits`), 관리대장 AF-01.

## 배경

- `attack_fixtures/`에는 지금 `scanner_limits/server.py` 하나가 있다.
  - 정의 크기·깊이·응답 지연을 바꾼 합성 MCP 서버다.
  - `tests/experiments/scanner_operating_probe.py`가 띄운다.
- C2.9가 CI에 Bandit·Semgrep을 넣을 때 대상을 `src`로 정했다. 그래서 fixture는 이미 빠져 있었다.
- 다만 그 범위와 이유를 관리대장에 적지 않았다. 관리대장 검사 기록 아래 문단은 "`attack_fixtures/`의 제외 범위를 기록한다"고 정해 두었다.

## 한 일

- **검사별 제외 범위를 정리했다.**

| 검사 | 대상 | `attack_fixtures/` |
| --- | --- | --- |
| Bandit `-r src -ll` | `src/` | 제외(대상 밖) |
| Semgrep `--config tools/ci/semgrep.yml src` | `src/` | 제외(대상 밖) |
| pip-audit `-r requirements.lock` | 의존성 | 해당 없음. fixture는 표준 라이브러리만 import |
| mypy | `src/guard_app` | 제외(대상 밖) |
| Ruff check·format | 저장소 전체 | **포함.** 형식·lint 규칙이고 약점 수에 들어가지 않는다. `S`(Bandit 규칙)도 지금 0건이라 끄지 않았다 |
| 배포물(wheel·sdist) | `src/`(setuptools `where = ["src"]`) | 들어가지 않음 |

- **관리대장:** 규칙 예외 기록에 AF-01을, 검사 실행 기록에 이번 측정 한 행을 더했다.
- **Semgrep 경로 제외를 루트 기준으로 고정했다.**
  - `subprocess-only-in-launcher`·`sqlite-only-in-storage`의 제외 경로 앞에 `/`를 붙였다.
  - Semgrep 1.182.1이 CI에서 이렇게 경고했다(#73 CI run 40803475503의 semgrep 작업, 규칙마다 네 번).
    - Semgrepignore v2에 맞춰 이 패턴을 곧 `/src/...`로 해석한다.
    - 루트 기준 동작을 확정하고 경고를 없애려면 `/src/...`로 바꾸라.
  - CI는 저장소 루트에서 `src`를 넘기므로 제외되는 파일은 같다.
  - 규칙 파일 머리 주석에 AF-01과 `/`의 뜻을 적었다.

## 검증

- Bandit 1.9.4 `-r attack_fixtures`(모든 등급·신뢰도): 0건
- Ruff 0.17.0 `check attack_fixtures --select S`: 0건
- Semgrep 1.182.1 규칙 10개를 `attack_fixtures/`에 직접 돌렸다: 0건(B, Linux, #80 B 리뷰)
- uv 0.13.0 `uv build`(setuptools 84.0.0): wheel 119개·sdist 137개 파일 중 `attack_fixtures`·`tests` 경로 0개
- 고친 `semgrep.yml`을 PyYAML로 읽었다: 규칙 10개, 제외 경로 두 개가 `/src/...`
- **Semgrep 경로 변경(B, Linux, #72 해시 고정 설치의 Semgrep 1.182.1, `b8b03c9`, 저장소 루트):**

| 단계 | 결과 |
| --- | --- |
| `semgrep scan --config tools/ci/semgrep.yml --error src` | 0건. main에서 나던 Semgrepignore v2 경고가 없어짐 |
| `semgrep --test --config tools/ci/semgrep.yml tools/ci/semgrep.py` | 10/10 통과 |
| `--disable-nosem` 결과 → `check_semgrep_exceptions.py` | `SEMGREP_EXCEPTIONS_OK 10` |

- **제외 대조(B):** 두 제외 경로를 없는 경로로 바꿔 같은 검사를 돌리면 실패한다.
  - `UNEXPECTED sqlite-only-in-storage storage/sqlite_store.py x3`
  - `UNEXPECTED subprocess-only-in-launcher security/launcher.py x1`
  - 그러니 `/src/...`로 바꾼 뒤에도 제외가 실제로 걸린다.
- 이 PC에는 Semgrep 실행 환경이 없어 C가 직접 돌리지는 못했다. GitHub CI는 결제 문제로 시작되지 않았다.
- Python 파일을 바꾸지 않아 로컬 CI(Ruff·mypy·pytest)는 다시 돌리지 않았다.

## 남은 한계

- 앞으로 fixture에 의도적으로 취약한 코드를 넣으면 Ruff `S`에 걸린다.
  - 그때는 `pyproject.toml`의 `per-file-ignores`에 `"attack_fixtures/**" = ["S"]`를 더하고 AF-01 범위를 넓힌다.
  - `pyproject.toml`은 공통 설정이라 ENV-01 절차를 따른다.
- 다른 공격·결함 서버(C5.6 응답 유실 등)는 `tests/unit/c_counting.py`에 있다. `tests/`도 Bandit·Semgrep 대상 밖이다.
- 스캔 대상을 `src`에서 넓히면 AF-01을 다시 본다.
- **git 저장소가 아닌 폴더에서는 제외가 적용되지 않는다.**
  - Semgrep이 루트를 git으로 잡기 때문에, 압축을 푼 폴더처럼 git이 아닌 곳에서는 `/src/...` 제외가 적용되지 않는다. 그러면 위 대조와 같은 `UNEXPECTED`로 실패한다(#72 B 리뷰 참고 3과 같은 내용).
  - CI는 체크아웃에서 돌기 때문에 괜찮다.
  - 재현: 저장소를 git 없이 복사한 폴더에서 같은 세 명령을 돌린다.

리뷰: B 승인(#80 B 리뷰, AF-01 리뷰어 승인).

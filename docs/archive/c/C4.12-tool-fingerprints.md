# C4.12 · 도구 지문 계산과 SDK 경로 고정

관련: I10, T10, FP-01(2026-10-18 JCS·2026-10-26 계산 입력 결정), 2026-10-15 "지문은 정의 전체" 결정, 개발문서 10.1절, #21 C 회신 3번.

## 배경

- 등록 지문은 Registry(C)가 계산해 B `RegistryStore`에 저장한다. 연결 직후에는 A `product_assembly.live_fingerprints`가 실제 목록으로 다시 계산해 대조한다(I10).
- FP-01 결정
  - 지문 함수는 B `security/digest.tool_fingerprint`(RFC 8785 JCS, SHA-256)다.
  - 계산 입력은 A transport가 SDK로 다시 만든 정의 dict(`model_dump(mode="json", by_alias=True, exclude_unset=True)`)다.
- **문제:** 등록 쪽 계산을 C가 따로 구현하면, 한쪽만 바뀌었을 때 정상 서버가 모두 PENDING이 된다.
- **C의 약속(#21 C 회신 3번):** SDK를 올릴 때 바뀌는 것을 CI가 잡도록 예시 정의의 지문을 테스트로 고정한다.

## 한 일

- **`services/registry.py`**(새 모듈, 개발문서 2.1절의 C Registry 자리)
  - `listing_fingerprints(listing) -> dict[str, str]`: transport 목록 하나의 도구 이름 → 지문이다. 순서는 목록 순서다.
  - 아래 경우는 지문을 하나도 만들지 않고 `RegistryError` 고정 코드를 낸다. 오류에 서버 텍스트를 싣지 않는다.
    - `REG_LISTING_INVALID`: 모양이 다름
    - `REG_LISTING_INCOMPLETE`: 미완료 목록
    - `REG_TOOL_NAME_INVALID`: 이름이 없거나 비었거나 문자열이 아님
    - `REG_TOOL_NAME_DUPLICATE`
    - `REG_FINGERPRINT_FAILED`: JCS로 나타낼 수 없는 값(예: 2^53을 넘는 정수)
  - **목록을 받는 방식:** `services.product_assembly`만 transport 패키지를 가져올 수 있다(I1, A 구조 테스트). 그래서 `ToolListing`을 가져오지 않고 같은 모양의 Protocol(`ToolListingView`)로 받는다. `transport.tool_listing(...)` 결과를 그대로 넘기면 된다.
- **`tests/unit/test_registry.py`**(14개)
  - **SDK 경로 고정**
    - 경로: 응답 JSON → `ListToolsResult.model_validate`(실제 클라이언트와 같은 파싱) → A의 공개 함수 `collect_tool_definitions`(실제 변환 코드) → `listing_fingerprints`
    - 합성 정의 7개의 지문을 고정했다. 기준 SDK는 mcp 1.29.0(uv.lock)이다.
    - 정의 7개가 담은 경우:
      - 기본 정의
      - 모르는 annotations 키와 SDK의 값 변환(`readOnlyHint: 1` → `true`)
      - outputSchema·`_meta`
      - 스키마 안의 실수(0.1·1.0·1e21)
      - 한글과 U+2028
      - 명시적 null·icons·title
      - 모르는 최상위 필드와 배열
  - **독립 대조:** 실수와 값 변환이 든 두 정의는 JCS 정규형을 손으로 쓴 문자열의 SHA-256과도 같다. 지금 코드가 내는 값을 그대로 박은 것이 아니다.
  - **A와 같은 계산:** A `live_fingerprints`의 도구별 계산(`tool_fingerprint(definition.to_dict())`)과 결과가 같다.
  - **바뀌는 것과 안 바뀌는 것:** 키 순서는 지문을 바꾸지 않는다. 배열 순서와 설명 한 글자는 바꾼다.
  - **실패:** 실패 8가지가 각 코드를 내고, 오류에 서버 텍스트가 없다.
- **`tests/unit/test_a_architecture.py`(A 소유)**
  - 새 서비스 모듈은 A 것 또는 B·C 것으로 분류돼 있어야 한다는 A 테스트가 있다.
  - 그래서 `OTHER_SERVICES`에 `registry` 한 단어를 더했다. A 리뷰 대상이다.

## 남은 것

- **C4.10:** Registry 본체를 같은 모듈에 만든다.
  - 동기 조회 캐시(`ports.Registry`)
  - 등록(`register_server`, PENDING)
  - 연결 직후 지문 변경 반영(`record_fingerprint_change` → 캐시 교체 → `GuardService.invalidate_tool`)
  - 재시작 복원
- **A(제안):** `live_fingerprints`가 도구별 계산 대신 `listing_fingerprints`를 쓰면 등록과 대조의 계산이 한 곳이 된다. A 파일이라 바꾸는 것은 A 몫이다.
- **B(요청):** 두 곳의 "원본 dict"를 FP-01 기준인 "transport가 만든 정의 dict(SDK 재구성, `exclude_unset`)"로 고쳐 주기 바란다. #21 C 회신 3번에서 요청했고 아직 남아 있다.
  - `security/digest.tool_fingerprint` docstring
  - `ports.RegistryStore` 설명의 "tools/list 원본으로 계산"
- **SDK를 올릴 때:** 고정 테스트가 깨지면 모든 서버가 재등록 대기가 된다는 뜻이다. 원인을 기록한 뒤에만 기대값을 바꾼다.

리뷰: B(`services/registry.py`), A(`test_a_architecture.py` 분류 한 줄, `live_fingerprints` 공유 제안).

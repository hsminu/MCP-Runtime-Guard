# C2.14 · 설정 파일 읽기와 원자적 교체

관련: I9, CFG-01(2026-10-26 사용자 결정, #33), B3.11(`parse_settings_bytes`·`serialize_settings_bytes`), C2.13 앱 폴더, A의 시작 설정 공급과 저장(B3.12·A104).

## 배경

- CFG-01에서 C 몫은 다섯 가지로 정해졌다(#33 C 확인).
  - 설정 파일 경로
  - 사용자 전용 권한
  - 크기 제한 읽기
  - 원자적 교체(같은 폴더 임시 파일·fsync·교체)
  - 실행 파일·URL 검증
- B3.11이 C에 요청한 것:
  - 공개 상수 `SETTINGS_MAX_BYTES`+1바이트까지만 읽어 넘긴다.
  - 세대 충돌과 결과를 알 수 없는 저장을 다룬다.
- A는 다음 둘을 기다렸다.
  - 시작 때 설정 읽기(A24–A27). 파일 없음은 첫 실행, 읽기 실패는 앱 시작 거부·덮어쓰지 않음으로 처리한다.
  - 정책 저장(`ProfileSaver`, A81)
- **범위:** 이번에는 파일 연산만 한다(2026-10-27 사용자 결정). 서버 값 검증은 해시 출처·HTTP 허용 범위 같은 정책을 먼저 정해야 해서 분리했다.
  - stdio `command`·`args`·`env_allow` → C2.6
  - HTTP `url` → C2.5

## 한 일

- **`security/settings_io.py`**(새 모듈)
  - **`read_settings_file(folders, *, max_bytes) -> SettingsSnapshot | None`**
    - 파일이 없으면 None이다.
    - 있으면 링크를 따라가지 않고(`FILE_FLAG_OPEN_REPARSE_POINT`), 읽기만 공유하는 핸들로 연다. 이 핸들이 쓰기·이름 변경·삭제를 막는다.
    - 열린 핸들로 확인하는 것: 일반 파일인지, 링크·폴더가 아닌지, 하드링크가 하나인지
    - 경로로 확인하는 것: 권한(DACL)이 사용자·SYSTEM뿐인지(`paths.is_private_file`)
    - `max_bytes + 1`바이트까지만 읽는다. 초과 판정은 B가 한다.
    - 돌려주는 세대(`SettingsGeneration`)는 파일 크기와 읽은 바이트의 SHA-256이다. `SettingsSnapshot`의 repr에는 내용을 싣지 않는다.
    - 실패 코드
      - `SETTINGS_FILE_INVALID`: 링크·폴더·하드링크·넓은 권한
      - `SETTINGS_FILE_READ_FAILED`: 다른 핸들이 쓰는 중 등
  - **`replace_settings_file(folders, data, *, expected, max_bytes) -> SettingsGeneration`**
    - 지금 파일의 세대가 `expected`와 다르면 쓰지 않고 `SETTINGS_FILE_CHANGED`다.
      - 첫 저장은 `expected=None`이고, 파일이 없어야 한다.
      - 앱 실행 중 누가 파일을 직접 고쳤으면 그 내용을 덮어쓰지 않는다(CFG-01: 직접 편집은 앱을 닫은 상태에서만).
    - 쓰는 순서
      1. 같은 폴더에 `settings.json.<uuid>.tmp`를 배타 생성해 쓰고 fsync한다.
      2. `MoveFileExW(WRITE_THROUGH)`로 바꾼다. 교체에는 `REPLACE_EXISTING`을 붙이고, 첫 저장에는 붙이지 않아 그 사이에 생긴 파일을 덮지 않는다.
      3. 새 파일은 `config` 폴더의 사용자·SYSTEM 권한을 물려받는다.
    - 실패하면 임시 파일을 지우고 디스크를 다시 읽어 분류한다.

      | 디스크 상태 | 코드 | A 처리 |
      | --- | --- | --- |
      | 그대로 | `SETTINGS_FILE_WRITE_FAILED` | `POLICY_SAVE_FAILED`, 적용하지 않음 |
      | 새 내용이 자리에 있음 | `SETTINGS_FILE_WRITE_UNKNOWN` | 반영을 확인하지 못했으므로 재시작 요구 |
      | 다른 내용 | `SETTINGS_FILE_CHANGED` | 덮어쓰지 않음 |

    - 그 밖의 코드
      - `SETTINGS_FILE_DATA_INVALID`: bytes가 아님, 빈 값, 상한 초과
      - `SETTINGS_FILE_LIMIT_INVALID`: 상한이 정확한 양의 int가 아님
      - 닫힌 앱 폴더는 `APP_FOLDERS_CLOSED`(`AppPathError`)다.
  - **상한을 인자로 받는 이유:** `security`가 `services`를 가져오지 않게 하려는 것이다. A가 B의 `SETTINGS_MAX_BYTES`를 넘기므로 상한은 B 한 곳에만 적힌다.
  - 블로킹 파일 연산이라 이벤트 루프에서는 `asyncio.to_thread`로 부른다.
- **`security/paths.py`**

## 검증([근거](../evidence/c2.14-settings-io-2026-10-27.json))

- **교체 중 강제 종료 60회**
  - 자식(기본 python.exe)이 앱 폴더를 잡고 두 내용(약 600KB·640KB)을 번갈아 교체했다. 0–150ms 뒤 `TerminateProcess`로 끊었다.
  - 매번 다음 시작에서 파일은 둘 중 하나로 온전했다(A 30, B 30, 그 밖 0).
  - 15회는 임시 파일이 남았고, 15개 모두 다음 시작이 지웠다. 시작 뒤 `config`에는 `settings.json`만 남았다.
- **시간**
  - 교체(약 600KB, WRITE_THROUGH): 중앙값 10.74ms, 최대 26.32ms(50회)
  - 읽기: 평균 1.24ms
- **옮겨 넣은 파일(#44 B 리뷰 3번)**
  - 같은 볼륨에서 옮기면 파일은 원래 폴더에서 물려받은 ACE(시험에서는 Everyone 읽기)를 그대로 들고 온다.
  - 앱을 닫은 상태에서 넣었으면, 다음 시작에서 `config` 폴더 DACL을 다시 걸 때 상속 ACE가 새로 계산된다. 그래서 사용자·SYSTEM만 남고 읽기가 통과한다.
  - 앱 실행 중에 넣으면 다시 계산되지 않는다. 읽기와 저장 모두 `SETTINGS_FILE_INVALID`이고, 재시작하면 통과한다.
  - 파일에 직접 붙은(상속이 아닌) 넓은 ACE는 재적용으로 사라지지 않아 계속 `INVALID`다.
- **실행 중 찾은 것:** Windows 파일 이름은 대소문자를 구분하지 않는다. 그래서 테스트에서 `settings.json.AAAA….tmp`와 `settings.json.aaaa….tmp`는 같은 파일이 된다. 우리 임시 파일 이름은 `uuid4().hex`(소문자)라 정리 규칙과 맞다.
- **로컬 전체 검사**(Windows 11, Python 3.12.10, main `a3fc2a1` 병합본)
  - Ruff·포맷·mypy(100개 파일)·`pip check` 통과
  - contract 41개 통과
  - 단위 4,791개 통과, 4개 생략(링크 권한 3개, `GUARD_TEST_CODEX_EXE`가 없을 때의 실제 L2 1개). 경고 5개는 AGT·FastMCP 의존성의 사용 중단 알림이다.
  - `test_settings_io.py`·`test_paths.py` 3회 반복: 매번 105개 통과, 2개 생략
  - #44 B 리뷰 반영 뒤: Ruff·포맷·mypy(100개 파일) 통과, 두 파일 110개 통과·2개 생략, 단위 4,796개 통과·4개 생략

## A 연결

- **시작**
  1. `read_settings_file(folders, max_bytes=SETTINGS_MAX_BYTES)`
  2. None이면 첫 실행이다(설정 화면, Task 시작 차단).
  3. 아니면 `parse_settings_bytes(snapshot.data)` → `load_profile_settings`로 읽고, `snapshot.generation`을 보관한다.
  4. `SettingsIOError`·`SettingsFileError`·`CatalogConfigError`는 모두 손상으로 다룬다. 앱 시작을 거부하고 파일을 덮어쓰지 않는다.
     - `SETTINGS_FILE_INVALID`(권한·종류 이상)는 "내용 손상"과 다른 문구로 보여 주면 사용자가 고칠 수 있다. 예: "앱을 닫고 설정 파일을 복사해서 넣으세요". 복사한 파일은 `config` 폴더 권한을 물려받는다(#44 B 리뷰 3번).
  5. `parse_settings_bytes`에는 `max_bytes`를 따로 넘기지 말고 기본값을 쓴다. 읽기와 해석의 상한이 어긋나면 잘린 앞부분만 해석될 수 있다(#44 B 리뷰).
- **저장(`ProfileSaver`)**
  1. `serialize_settings_bytes(change.document.to_dict())`
  2. `replace_settings_file(folders, data, expected=보관한 세대, max_bytes=SETTINGS_MAX_BYTES)`. 정책 잠금 안에서 한 번에 하나씩 부른다.
  3. 결과에 따라 처리한다.

     | 결과 | A 처리 |
     | --- | --- |
     | 성공 | 새 세대를 보관하고 True |
     | `SETTINGS_FILE_WRITE_FAILED`·`SETTINGS_FILE_DATA_INVALID` | False(적용하지 않음) |
     | `SETTINGS_FILE_CHANGED` | False. 바깥에서 고친 것이므로 재시작해서 다시 읽으라고 안내 |
     | `SETTINGS_FILE_INVALID`·`SETTINGS_FILE_READ_FAILED` | False. 대조하려고 지금 파일을 읽다가 난 것이다. 실행 중에 파일을 옮겨 넣은 경우 등이고, 재시작 안내 |
     | `SETTINGS_FILE_WRITE_UNKNOWN` | 적용 실패 때처럼 재시작 요구(`require_restart`) |
     | `AppPathError("APP_FOLDERS_CLOSED")` | False. 종료 중 저장 등 |
     | `SETTINGS_FILE_UNSUPPORTED`·`SETTINGS_FILE_LIMIT_INVALID` | Windows 밖·호출 오류. 제품 경로에서는 나오지 않음 |

- 두 함수 모두 `asyncio.to_thread`로 부른다.

## 남은 것

- **C2.6·C2.5:** 설정의 stdio `command`·`args`·`env_allow`와 HTTP `url` 검증. 해시 출처와 HTTP 허용 범위를 먼저 정한다.
- **남는 한계**
  - 세대 대조와 교체 사이에 틈이 남는다. 끼어들려면 사용자·SYSTEM 전용인 `config` 폴더에 쓸 수 있어야 한다. 같은 사용자 권한은 위협 모델 밖이다.
  - `WRITE_THROUGH`가 저장 장치 캐시까지 비운다는 것은 OS 문서 수준의 보장이다. 전원 차단 실험은 하지 않았다.

리뷰: B(`security/settings_io.py`·`security/paths.py`, 상한·오류 코드 연결), A(시작·저장 연결).

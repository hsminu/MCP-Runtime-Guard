# C6.26 · L2 실패 코드 상수 (`codex_l2.L2_FAILURE_CODES`)

2026-10-29 · 관련: [#83 C 리뷰](https://github.com/hsminu/MCP-Runtime-Guard/pull/83#issuecomment-6493041009) 참고 4, A151, C6.14·C6.23, T22.

## 배경

- A151은 L2 실패 코드 28개를 `services/session_preparation.L2_FAILURE_CODES`에 사본으로 두었다.
  - A 시작 화면은 이 집합에 있는 코드만 그대로 알린다.
  - 나머지는 `CODEX_L2_FAILED`로 묶는다.
- #83 C 리뷰 때 사본이 C 코드와 같음을 확인했다. 다만 C가 코드를 더하거나 빼면 사본이 어긋날 수 있다. 그래서 C가 상수를 두기로 했다.

## 한 일

- `security/codex_l2.py`에 `L2_FAILURE_CODES`(frozenset, 28개)를 더했다.
  - 이 모듈이 `L2Report.failures`와 `L2Error`에 싣는 `L2_` 코드 전체다.
  - `failures`에는 실행 입구 `LaunchError`·앱 폴더 `AppPathError`의 코드도 들어올 수 있다. 이 코드들은 집합에 넣지 않았다. 지금처럼 A가 묶어서 알린다.
- `tests/unit/test_codex_l2.py`에 시험 2개를 더했다.
  - **상수 = 모듈이 실제로 쓰는 코드:** 모듈 소스를 AST로 읽어 `L2_[A-Z_]+` 문자열을 모으고(상수 정의는 뺌), 상수와 같은지 본다. 코드를 하나 더하거나 빼면 실패한다.
  - **A 사본 = C 상수:** A가 사본을 이 상수로 바꾸기 전까지 어긋남을 잡는다. 바꾼 뒤에는 자명하게 통과한다.
- 돌연변이 확인: 상수에서 `L2_TURN_TIMEOUT`을 빼자 두 시험 모두 실패했다.

## 넘길 것

- **A(A151):** `session_preparation.L2_FAILURE_CODES` 사본을 `from guard_app.security.codex_l2 import L2_FAILURE_CODES`로 바꾼다.

## 검증

- 로컬 Windows 11, Python 3.12.10. `test_codex_l2.py` 65개 통과, 1개 생략(실제 codex.exe 경로 없음)
- 정적 검사와 전체 시험은 [C3.8-1 기록](C3.8-1-query-counts.md)의 검증 절과 같다(같은 작업 트리).

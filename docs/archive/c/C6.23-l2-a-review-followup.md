# C6.23 · #41 A 리뷰 후속(L2 시간 상한과 범위 설명)

관련: T22, C6.14, #41 A 리뷰(2026-10-27, `dde8dfd` 기준 승인).

## 배경

A는 #41을 승인하면서 다섯 가지를 요청했다. 1·2번은 "병합 전에 문구를 고쳐 주면 좋겠다"였다. C가 B 리뷰만 반영하고 A 리뷰 본문은 확인하지 않은 채 #41이 병합됐다. 그래서 따로 처리한다.

| A 요청 | 처리 |
| --- | --- |
| 1 [중] "가짜 모델 밖 통신 없음"이 관찰 범위보다 넓게 적힘 | C6.14 기록과 PR 본문은 #41 안에서 고쳤다(`4f183eb`). 남은 것은 모듈 설명이다. 이번에 판정 범위와 관찰하지 않는 것을 적었다 |
| 2 [중] L2 전체 시간 상한이 없음(최악 약 160초) | 이번에 상한·고정 코드·최악 시간 설명을 넣었다 |
| 3 [하] 읽지 못한 요청이 판정에 안 들어감 | #41 안에서 고쳤다(`4f183eb`, B 리뷰 1번과 같은 내용) |
| 4 [하] L2 허용 항목과 A의 L3 허용 항목을 테스트로 묶기 | 이번에 넣었다 |
| 5 [하] `run_l2`가 예외로 끝나는 경우 설명 | 이번에 적었다 |

## 한 일

- **`security/codex_l2.py`**
  - **시간 상한:** `L2_DEADLINE_S = 30.0`이다. `observe_l2`·`run_l2`에 `deadline_s` 인자를 더했다.
    - 초기화부터 turn 완료까지를 `asyncio.wait_for`로 묶는다. 넘으면 `L2_DEADLINE_EXCEEDED`를 남기고, 평소처럼 Codex 종료 확인·응답 읽기 정리·가짜 모델 닫기·시험 폴더 삭제로 넘어간다.
    - 결과는 예외가 아니라 불통과 보고다.
    - 실측은 1.1–3.1초다(C6.14). 30초는 느린 PC를 위한 여유다.
    - 양수가 아니거나 600초를 넘는 값(무한대·NaN·bool·문자열 포함)은 시작 전에 `L2_DEADLINE_INVALID`로 거부한다.
    - A도 따로 상한을 둔다고 했다. A 상한이 더 짧으면 그쪽 취소가 먼저 온다.
  - **`run_l2` 설명**
    - 최악 시간은 `deadline_s` + 약 15초다. 종료 확인(stdin EOF 뒤 5초, Job 종료 뒤 5초)과 정리(응답 읽기 2초, 가짜 모델 닫기 2초, 폴더 삭제)가 더해진다.
    - 부른 쪽이 취소해도 정리를 거친 뒤 취소가 전달된다. A가 실제로 확인했다.
    - `L2Report` 없이 예외로 끝나는 경우를 나열했다.
      - 고정값·L1 파일을 읽지 못함
      - 가짜 모델 포트를 열지 못함
      - `thread_params`가 예외를 냄
      - 잘못된 상한
  - **모듈 설명**
    - 판정하는 것: 가짜 모델 서버에 정상 요청 두 개 말고 다른 요청이 오지 않는지
    - 관찰하지 않는 것: codex.exe가 다른 호스트로 나가는 연결. C6.14의 연결 표 실측은 근거일 뿐 판정에 쓰지 않는다.
  - **허용 항목:** `ALLOWED_ITEM_TYPES` 주석을 "A의 L3 허용 항목과 같아야 하고 테스트가 대조한다"로 고쳤다. `security`가 `services`를 가져오지 않도록 사본으로 둔다.
- **`tests/unit/test_codex_l2.py`**(9개 추가, 모두 64개)
  - L2 허용 항목 == A `codex_session.L3_ALLOWED_ITEMS`
  - 잘못된 상한 7가지는 아무것도 시작하기 전에 거부
  - 응답하지 않는 대역 Codex(python.exe가 stdin만 읽음)에 0.5초 상한을 건다. `L2_DEADLINE_EXCEEDED` 하나만 남고, 종료 확인과 시험 폴더 삭제가 되고, 전체가 5초 안에 끝나는지 본다.

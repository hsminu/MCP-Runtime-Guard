# C2.19 · DB 경로와 이관 전 백업 입구

관련: I9, REC-01(DB 단일 소유), SEQ-03(이관 전 백업), REC-05(강제 종료 측정), C2.13·C2.17, #37 C 회신 1·2번과 B 수락.

## 배경

- #37에서 A·B·C가 SEQ-01–03과 REC-01–05에 모두 동의했다.
- C 몫은 두 가지 입구다.
  - REC-01: DB 경로를 확인한 뒤 주는 입구(`db_path()`)
  - SEQ-03: 이관 전 백업 자리를 주는 입구(`begin_backup()`)
- B는 이 두 입구가 들어오면 B6.8에서 그것만 쓰겠다고 했다. 스냅샷은 B가 SQLite Backup API로 만든다. C는 위치와 파일 연산만 맡는다.

## 한 일

- **`AppFolders.db_path() -> Path`**
  - 앱 폴더가 열려 있을 때만 `data\guard.sqlite3`를 준다.
  - DB와 옆 파일(`-wal`·`-shm`·`-journal`) 중 이미 있는 것은 아래를 모두 만족해야 한다. 아니면 `APP_DB_INVALID`다.
    - 링크·reparse point·폴더가 아닌 일반 파일
    - 하드링크가 하나
    - 권한이 사용자·SYSTEM뿐
  - **#37 회신보다 더한 것:** 권한 확인이다. 앱 시작 때 폴더 DACL을 다시 걸어도, 파일에 직접 붙은 넓은 권한은 그대로 남기 때문이다.
  - **보지 않는 것:** 파일 소유자다. 관리자 권한으로 실행하면 SQLite가 만든 파일의 소유자가 Administrators가 되기 때문이다(CI 러너).
- **`AppFolders.begin_backup(label) -> BackupTarget`**
  - `label`은 소문자·숫자·`-` 묶음(`v2-to-v3` 형식)이고 32자 이하다. 아니면 `APP_BACKUP_LABEL_INVALID`다.
  - `data\backups\<label>-<UTC 초>.partial`을 빈 파일로 배타 생성해 이름을 선점한다.
    - 같은 이름의 임시 파일이나 완성 백업이 있으면 `-2`…`-9`를 붙인다.
    - 다 차면 `APP_BACKUP_CREATE_FAILED`다.
  - B는 `target.path`로 대상 연결을 열고 `Connection.backup()`을 한 뒤 닫는다. 그다음 `quick_check`·`application_id`·`user_version`을 확인한다.
- **`BackupTarget.publish() -> Path`**
  - 아래 경우에는 `APP_BACKUP_PUBLISH_FAILED`다.
    - 임시 파일 옆에 SQLite 파일(`-journal`·`-wal`·`-shm`)이 남아 있음
    - 임시 파일이 비어 있거나 일반 파일이 아님
  - 통과하면 fsync한 뒤 `MoveFileExW(WRITE_THROUGH)`로 `<이름>.sqlite3`로 바꾼다. 같은 이름이 있으면 덮어쓰지 않고 실패한다.
  - B는 이 실패를 `STORE_BACKUP_FAILED`로 받아 이관하지 않는다(#37 B 수락).
  - 실패해도 대상은 열린 채로 남는다. 연결을 닫고 다시 부를 수 있다.
- **`BackupTarget.discard()`**
  - 임시 파일과 옆 파일을 지운다. 여러 번 불러도 된다. 못 지우면 `APP_BACKUP_DISCARD_FAILED`다.
  - publish가 끝난 뒤에 부르면 아무것도 하지 않는다. B가 `finally`에서 불러도 완성된 백업은 남는다.
  - 끝난 대상에 다시 publish를 부르면 `APP_BACKUP_TARGET_CLOSED`다.
- **앱 시작 정리**
  - `prepare_app_folders`가 `backups`에서 `*.partial`과 그 옆 파일만 지운다. 링크는 대상이 아니라 링크만 지운다.
  - 완성 백업과 그 밖의 파일은 남긴다. 복원은 앱 기능이 아니라 오프라인 절차다(#37).
  - 다 지우지 못하면 `APP_STALE_BACKUP_CLEANUP_FAILED`로 시작을 멈춘다. 남은 Task 폴더 규칙과 같다.
  - 지운 개수는 `AppFolders.stale_backups_removed`다.
  - `_clear_task_folders`와 같은 항목 삭제 코드를 `_remove_entry`로 묶었다.
- **`tests/unit/test_paths.py`**에 더한 테스트(28개, 경우 포함)
  - `db_path`
    - 새 DB와 WAL로 쓰는 중인 DB는 통과한다.
    - 폴더·junction·하드링크·넓은 권한·심볼릭 링크는 거부한다. 심볼릭 링크는 권한이 없으면 생략한다.
  - 백업
    - 실제 SQLite backup → publish → 완성 파일 `quick_check` 통과와 권한, publish 뒤 discard
    - 연결이 열린 동안 publish 실패 → 닫은 뒤 성공
    - 빈 파일·journal 남음·같은 이름 있음은 실패하고 기존 파일은 그대로다.
    - discard: 옆 파일 삭제, 열린 파일, 반복 호출
    - 같은 초 이름 충돌(접미사 `-2`…`-9`, 다 차면 실패), 잘못된 label 12가지
  - 시작 정리: 남은 임시 파일 삭제와 완성 백업 보존, 지울 수 없는 임시 파일
  - 닫힌 앱 폴더에서 두 입구 거부

## 검증([근거](../evidence/c2.19-db-backup-entry-2026-10-27.json))

- **백업 중 강제 종료(REC-05 측정 일부)**
  - 자식 프로세스가 `prepare_app_folders` → `begin_backup` → SQLite backup(8쪽씩, 원본 약 12MB)을 진행하다가 `TerminateProcess`로 끝났다.
  - 자식이 살아 있는 동안 다른 시작은 `APP_ALREADY_RUNNING`이었다.
  - 강제 종료 뒤에는 OS가 핸들을 닫아 잠금이 풀렸다. 바로 다시 시작했다(0.004초).
  - 남은 `.partial`과 `.partial-journal` 두 개를 시작 정리가 지웠다.
  - 원본 DB는 `quick_check` ok, `user_version` 2 그대로였다.
  - #37 C 회신 1번에서 미확인으로 남긴 "강제 종료 때 잠금이 풀리는지"를 이 실행으로 확인했다.
- **로컬 전체 검사**(Windows 11, Python 3.12.10, main `c2da9e0` + C6.14 기준, C2.18 포함)
  - Ruff·포맷·mypy(85개 파일)·`pip check` 통과
  - contract 41개 통과
  - 단위 4,354개 통과, 3개 생략(링크 권한 2개, `GUARD_TEST_CODEX_EXE`가 없을 때의 실제 L2 1개). 경고 5개는 AGT·FastMCP 의존성의 사용 중단 알림이다.
  - `test_paths.py` 74개(1개 생략: 심볼릭 링크 권한), `test_launcher.py` 35개

## 남은 것

- **B(B6.8)**
  - 제품 DB는 `folders.db_path()`로 받는다.
  - 이관 전에는 `begin_backup("v<n>-to-v<m>")` → backup·확인 → `publish()`를 한다. 실패하면 `discard()`하고 `STORE_BACKUP_FAILED`로 닫는다.
  - `security`를 직접 가져오지 않으려면 A 조립에서 두 입구를 함수로 넘겨받으면 된다.
- **A**
  - 제품 모드에서 `--db-path` 대신 `db_path()`를 쓴다.
  - `APP_DB_INVALID`·`APP_STALE_BACKUP_CLEANUP_FAILED`는 다른 `APP_*` 코드처럼 고정 문구로 보이고, 앱을 시작하지 않는다.
- **남는 한계:** `db_path()` 확인과 SQLite가 경로로 다시 여는 사이에 틈이 있다. 끼어들려면 사용자·SYSTEM 전용 `data` 폴더에 쓸 수 있어야 한다(같은 사용자는 위협 모델 밖).
- **REC-05 나머지(C):** 이관·복구 COMMIT 중 강제 종료, 단계별 시간, daemon writer 측정은 B6.8 뒤에 한다.
- **contracts:** 미결 표의 SEQ·REC 행 갱신은 사용자 문서다.

리뷰: B(`security/paths.py`, B6.8 사용 방식), A(시작 연결).

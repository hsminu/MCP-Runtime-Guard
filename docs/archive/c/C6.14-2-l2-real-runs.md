# C6.14-2 · 실제 실행에서 드러난 L2 판정 두 가지(A161 경로, #21 검사 호출 순서)

관련: [C6.14](C6.14-codex-l2.md), A151(제품 시작 L2), A161(Windows 앱 가상 경로), [#21 A 보고](https://github.com/hsminu/MCP-Runtime-Guard/issues/21#issuecomment-6496456303), T22.

## 1. 같은 파일을 다른 경로로 보고하면 실패하던 것(A161)

- **증상:** Codex 데스크톱 앱 안에서 제품을 띄우면 `%LOCALAPPDATA%`가 앱 패키지 경로로 가상화된다. Codex는 user 설정 층의 파일과 `model_catalog_json`을 물리 경로로 보고하고, C는 논리 경로를 쥔다. `_check_config`가 둘을 `Path ==`로 비교해 같은 파일을 다른 것으로 보고 `L2_CONFIG_LAYERS_UNEXPECTED`·`L2_CONFIG_MISMATCH`를 냈다. 그 실행의 세션은 모두 거부됐다(A 실측 2회).
- **수정:** `_same_file`이 경로 문자열이 같으면 바로 받고, 다르면 `os.path.samefile`(파일 ID)로 같은 파일인지 본다. 읽지 못하는 경로는 다른 파일로 본다.
- **시험:** 정션으로 같은 파일을 다른 경로에 보이게 하면 통과, 내용이 같은 다른 파일·없는 경로는 두 코드로 실패. 수정 전 비교로 되돌리면 이 시험이 실패한다.
- 같은 파일의 하드 링크도 같은 파일로 받는다. 같은 파일이므로 맞다.

## 2. 검사 호출 순서가 바뀌면 실패하던 것(#21)

- **증상:** A 제품 시작 경로에서 8회 중 1회 `L2_PROBE_CALLS_UNEXPECTED`.
- **재현:** 실제 codex.exe 0.162.1로 L2를 40회 돌려 1회 재현했다. 겹침은 없고 두 검사 호출이 `l2_probe_2` → `l2_probe_1` 순서로 왔다. 나머지 39회는 통과.
- **원인:** Codex는 한 응답의 도구 호출 두 개를 겹치지 않게 차례로 보내지만, 가끔 순서를 바꾼다. C 판정이 순서까지 요구한 것이 지나쳤다.
- **수정:** 순서는 보지 않는다(두 호출이 정확히 한 번씩). 겹침은 `L2_PROBE_CALLS_OVERLAP`으로 나눈다. A 사본(`session_preparation.L2_FAILURE_CODES`)에는 새 코드가 없어 A는 `CODEX_L2_FAILED`로 닫는다(안전한 쪽).
- **Guard에 주는 뜻:** 한 응답 안의 호출 순서는 Codex가 보장하지 않는다. 같은 응답의 SEND 인자는 같은 응답의 READ 결과를 담을 수 없으니 유출은 없다. 다만 같은 응답의 SEND 판정은 순서에 따라 달라질 수 있다.
- **수정 뒤 실제 실행:** 40회 모두 통과, 이어서 80회 모두 통과. 80회 중 1회(66회차)는 순서가 바뀐 회차였고 통과로 판정됐다.
- **다시 시도:** 거짓 실패를 판정에서 없앴으므로 L2 다시 시도는 두지 않는다. 다시 시도는 진짜 실패를 가릴 수 있다.

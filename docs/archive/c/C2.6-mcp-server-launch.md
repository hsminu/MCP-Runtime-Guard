# C2.6 · stdio MCP 서버 실행 입구

관련: EXE-01(2026-10-27 사용자 결정, #49), #48(B 설정 필드·A 등록 화면), 개발문서 10.1·13.1절, [C2.12](C2.12-codex-launcher.md) `launch_process`, [C2.18](C2.18-image-check-and-lock-order.md) 이미지 대조, I9·I11·T19·T22·T43.

## 배경

- 10-18 결정으로 stdio MCP 서버도 C launcher(`launch_process`)로 띄운다. launcher는 실행마다 실행 파일의 크기·SHA-256을 대조해야 하는데, 설정 파일의 서버 레코드에는 `command`·`args`·`env_allow`만 있고 해시가 없었다.
- EXE-01이 해시의 출처를 정했다.
  - 등록 때 C가 지문을 계산한다.
  - 사용자가 확인하면 레코드의 `command_sha256`·`command_size`로 저장한다(B 필드, #48).
  - 연결마다 그 값으로 대조한다.
- 10.1절은 C가 검증할 실행 값과 실행 환경(서버별 작업 폴더, 격리 stderr, 시스템 기본 변수와 `env_allow`만, Job Object)을 정했다.

## 한 일

- **`security/launcher.py`**: 프로세스 실행의 단일 지점에 stdio MCP 서버 입구 세 개를 더했다. 오류는 고정 코드이고 경로·인자·값을 싣지 않는다.
  - **`check_stdio_values(command, args, env_allow) -> StdioServerValues`:** 레코드 값 검사. 등록 화면과 연결마다 쓴다.

    | 값 | 규칙 | 코드 |
    | --- | --- | --- |
    | `command` | `C:\`처럼 드라이브 문자로 시작하는 절대 경로, 마지막 이름이 `.exe`. UNC·`\\?\`·`\\.\`, 드라이브 상대(`C:x`), `.`·`..`·빈 조각, `<>:"\|?*`(ADS 포함)·제어 문자, 끝 점·공백, 장치 이름(`CON`·`NUL`·`COM1` 등, 확장자 무관), 짝 없는 서로게이트 거부. 파일이 있고 일반 파일이며 링크·junction이 아니어야 함 | `LAUNCH_EXECUTABLE_INVALID` |
    | `args` | tuple·list의 문자열 256개 이하, 하나에 4,096자 이하, NUL·짝 없는 서로게이트 없음. 실행 파일과 합친 명령줄(`subprocess.list2cmdline`, asyncio와 같은 인용)이 32,766자 이하. 빈 문자열·줄바꿈·따옴표는 셸 없이 그대로 가므로 허용 | `LAUNCH_ARGS_INVALID` |
    | `env_allow` | tuple·list의 이름 64개 이하, `[A-Za-z_][A-Za-z0-9_]*`, 대소문자만 다른 중복 거부, Guard가 정하는 이름(아래 기본 환경·TEMP·TMP) 거부 | `LAUNCH_ENV_ALLOW_INVALID` |

  - **`pin_executable(command) -> ExecutablePin(size, sha256)`:** 등록 화면용 지문이다.
    - `command`를 검사한 뒤 쓰기·이름 변경·삭제를 막는 핸들(`FILE_SHARE_READ`, reparse point 미추적)로 열어 센다. 연결 때 대조하는 열기와 같은 함수(`_open_locked`)다.
    - 해시는 스레드에서 계산한다.
    - 빈 파일, 다른 쪽이 쓰기 핸들을 쥔 파일은 `LAUNCH_EXECUTABLE_INVALID`다.
  - **`launch_mcp_server(server_dir, command, args, env_allow, pin) -> LaunchedProcess`**
    - 연결마다 실행 값을 다시 검사한다.
    - `pin`이 None이면 `LAUNCH_EXECUTABLE_UNPINNED`다. 지문 필드가 없는 옛 레코드를 B가 "고정 안 됨"으로 읽는 경우다(#48 B 답변). A 화면은 "실행 파일 확인 필요"로 보인다.
    - 대조가 다르면 `LAUNCH_EXECUTABLE_MISMATCH`다(`launch_process`). 둘 다 그 서버만 띄우지 않는다.
    - 작업 폴더는 `server_dir`다.
    - stderr는 연결마다 새 `stderr-<128비트 난수>.log`를 배타 생성한다. 같은 서버를 다시 연결해도 앞 파일을 덮지 않는다.
    - TEMP·TMP는 `server_dir\tmp`다.
    - 환경은 `MCP_SERVER_ENV_BASE`(`SYSTEMROOT`·`WINDIR`·`LOCALAPPDATA`·`APPDATA`·`USERPROFILE`)와 `env_allow`에 적힌 이름의 부모 값만 넘긴다. 부모에 없는 이름은 넘기지 않는다.
    - Job Object, 멈춘 채 생성, 이미지 대조, 실패 정리는 `launch_process` 그대로다.
    - 돌려받은 `read_bytes`·`write_bytes`·`drain`을 A가 `validated_stdio_stream_factory`에 넘긴다.
  - `_open_verified`의 열기 부분을 `_open_locked`로 떼어 `pin_executable`과 함께 쓴다. 동작은 같다.
- **`security/paths.py`**
  - 관리 폴더에 `servers`를 더했다. 다른 관리 폴더처럼 사용자·SYSTEM 전용 보호 DACL이다.
  - **`AppFolders.server_folder(server_id) -> Path`:** 서버 하나의 작업 폴더를 만들거나 그대로 준다.
    - 서버 ID에는 `/`·`\`·`:`·`..`·장치 이름처럼 경로에 쓸 수 없는 값도 올 수 있다(B `valid_server_id`는 제어 문자·`__`·끝 `_`만 막는다). 그래서 폴더 이름은 ID(UTF-8)의 SHA-256 앞 32자다.
    - 빈 값·문자열 아님·짝 없는 서로게이트는 `SERVER_ID_INVALID`, 그 자리가 링크·junction·파일이면 `SERVER_FOLDER_INVALID`·`SERVER_FOLDER_CREATE_FAILED`다.
  - `prepare_app_folders`가 이전 실행의 서버 폴더를 모두 지운다. stderr에는 서버가 남긴 문서 조각이 있을 수 있다. 개수는 `stale_server_folders_removed`이고, 다 지우지 못하면 `APP_STALE_SERVER_CLEANUP_FAILED`로 시작하지 않는다(Task 폴더와 같은 기준).
  - 장치 이름 목록을 `RESERVED_DEVICE_NAMES`로 공개해 launcher도 쓴다. Task 폴더 정리 함수는 `_clear_all(folder, code)`로 일반화했다.
- **기본 환경 실측(2026-10-28, Windows 11)**
  - 환경을 비우면 Python 3.12.10은 `socket.socket()`에서 `WinError 10106`, Node는 시작 직후 비정상 종료(134)였다.
  - `SYSTEMROOT` 하나면 둘 다 돌지만, 임시 폴더가 `C:\Windows\Temp`가 되고 Python의 홈이 `~`로 남는다.
  - 다섯 개 부모 값과 서버 폴더의 TEMP·TMP로는 둘 다 소켓·난수·임시 폴더·홈이 정상이었다. 그래서 codex와 같은 목록에서 TEMP·TMP만 서버 폴더로 바꿨다.
- **실제 인터프리터로 확인(2026-10-28)**
  - Node 실행 파일(약 90MB)을 긴 경로와 8.3 짧은 경로(`C:\PROGRA~1\…`)로 각각 지문을 만들고 띄웠다. 둘 다 이미지 대조를 통과했고, 줄 하나를 주고받은 뒤 `close`가 True였다.
  - venv의 `python.exe`(274KB 런처)도 같았다. 이 런처는 기본 인터프리터를 자식 프로세스로 띄운다. 자식도 같은 Job이라 `close`는 둘 다 끝난 뒤 True다.
- **테스트** `tests/unit/test_mcp_server_launch.py` 59개. 서버 대신 base `python.exe`를 띄운다.
  - **값 검사**
    - `command` 거부 27가지(위 표의 형식들, 40,000자 경로)
    - 없는 파일·`.bat`·`x.exe` 폴더·junction·심볼릭 링크(권한이 있을 때)
    - `args` 7가지와 경계 통과(256개, 4,096자, 빈 문자열·줄바꿈·따옴표)
    - `env_allow` 11가지
  - **지문:** 파일 바이트의 크기·SHA-256과 같은지. 빈 파일, 쓰기 핸들이 열린 파일, 상대 경로는 거부한다.
  - **실행**
    - 자식이 보는 환경이 기본 다섯 개(부모에 있는 것)·TEMP·TMP·허용한 이름뿐이다. 부모에 심은 `OPENAI_API_KEY`·`HTTPS_PROXY`·`PATH` 표지는 보이지 않는다.
    - 작업 폴더가 서버 폴더다.
    - 두 연결이 서로 다른 stderr 파일을 만들고, 표지가 앱 출력에는 없다.
    - 지문이 없으면 띄우지 않고 파일도 만들지 않는다.
    - 등록 뒤 바뀐 실행 파일은 해시 단계에서 막혀 실행되지 않는다.
    - 연결마다 다시 검사한다(잘못된 값·지문 형식·폴더).
  - **끝에서 끝까지:** C 입구로 띄운 최소 MCP 서버(표준 라이브러리 JSON-RPC)를 A의 `validated_stdio_stream_factory`·`McpTransport`로 연결했다. `tools/list`가 완료되고, C `listing_fingerprints`까지 나온다.
  - **서버 폴더**
    - 이름이 ID 다이제스트다.
    - 경로 문자·장치 이름 ID도 `servers` 바로 아래에 만들어진다.
    - 잘못된 ID, junction 자리, 닫힌 앱 폴더는 거부한다.
    - 다음 시작이 남은 서버 폴더 2개를 지운다.

## A·B 연결

- **B(#48):** `ServerSettings`의 `command_sha256`·`command_size`가 들어오면, 둘 다 있으면 `ExecutablePin(command_size, command_sha256)`이고 없으면 None이다.
- **A 등록·재확인 화면**
  - `check_stdio_values`로 입력을 검사한다.
  - `pin_executable(command)`의 크기·지문을 경로와 함께 보여 준다.
  - 사용자가 확인하면 B 필드로 저장한다(정책 저장 흐름).
- **A 연결**
  - `folders.server_folder(server.id)`로 폴더를 받는다.
  - `launch_mcp_server(folder, server.command, server.args, server.env_allow, pin)`이 돌려준 파이프를 `validated_stdio_stream_factory`에 넘긴다.
  - 끝낼 때는 transport를 닫은 뒤 `close()`를 부른다.
  - `LAUNCH_EXECUTABLE_UNPINNED`·`LAUNCH_EXECUTABLE_MISMATCH`는 "실행 파일 확인 필요"로, 그 밖의 `LAUNCH_*`는 그 서버만 연결 실패로 보인다.

## 남는 한계

- **인터프리터형 서버**(`python.exe -m …`, `node.exe server.js`): 지문은 인터프리터만 덮는다. 스크립트·패키지가 바뀌는 것은 잡지 못한다. 도구 정의가 바뀌는 것은 도구 지문(C4.12)이 잡는다.
- **venv의 `python.exe`:** 기본 인터프리터를 자식으로 띄우는 런처다. 그래서 지문은 런처만 덮고, `pyvenv.cfg`가 가리키는 기본 인터프리터는 덮지 못한다.
- **같은 사용자 권한:** 실행 파일이 같은 사용자가 쓸 수 있는 폴더에 있으면, 그 사용자 권한의 코드는 등록 전에 파일을 바꿔 둘 수 있다. 등록 뒤 변경은 연결 때 대조가 막는다. 같은 사용자 권한은 위협 모델 밖이다.
- **OS 격리 없음:** 서버는 사용자 권한으로 돈다(C-CODEX-04와 같은 판단).
- **stderr 크기:** 연결 동안 상한이 없다. 다음 시작에 지운다.

리뷰: B(테스트·설정 필드 연결), A(등록 화면·연결).

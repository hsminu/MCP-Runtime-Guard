# C2.17 · 제품 DB 위치와 백업 폴더

관련: C2.13, REC-01(DB 단일 소유), B6.17 SEQ-03(이관 전 백업), #35 B 리뷰 1번과 A 회신.

## 배경

- #35 리뷰에서 A가 물었다. `app.lock`은 사용자별 앱 폴더 단위라 다른 Windows 사용자가 같은 DB 파일을 여는 것은 막지 못한다. 이걸 REC-01의 DB 단일 소유로 볼 수 있는지가 질문이었다.
- B의 답은 "제품 DB를 앱 폴더 안 고정 위치에 두면 그렇게 본다"였다. DB 파일 단위 잠금은 따로 두지 않는다.
  - 같은 사용자의 두 번째 실행은 `app.lock`이 막는다.
  - 다른 사용자는 앱 폴더의 사용자·SYSTEM 전용 DACL에 막힌다.
  - DB 경로를 잠금이 지키는 루트에서 계산하고 루트·관리 폴더의 링크·junction을 거부하므로, 같은 DB의 경로 별칭 문제(B6.17 4절)도 생기지 않는다.
- A도 동의했다. 제품 모드는 `--db-path` 대신 이 경로를 쓴다. 2026-10-27에 사용자가 이 PR에 넣기로 정했다.

## 한 일

- `security/paths.py`
  - `MANAGED_DIRS`에 `data`와 `data\backups`를 넣었다. 둘 다 앱 시작 때 보호된 DACL로 만들고, 이미 있으면 소유자를 확인한 뒤 같은 DACL을 다시 건다.
  - `AppPaths.data`, `AppPaths.db_file`(`data\guard.sqlite3`), `AppPaths.backups`(`data\backups`)를 추가했다.
  - SQLite가 옆에 만드는 `-wal`·`-shm`·`-journal`도 같은 폴더에 생겨 같은 권한을 물려받는다.
- `tests/unit/test_paths.py`
  - DB·백업 경로를 확인한다.
  - DB와 `-wal` 파일이 사용자·SYSTEM 권한만 물려받는지 확인한다.
  - 루트·관리 폴더 권한 테스트는 `MANAGED_DIRS`를 돌므로 새 폴더 두 개도 함께 확인된다.

## 검증

- 로컬(Windows 11, Python 3.12.10, `34cc08c` 기준)
  - `test_paths.py` 45개가 3번 반복해서 모두 통과했다.
  - 전체 검사: Ruff·포맷·mypy(84개 파일) 통과, contract 41개 통과, 단위 4,270개 통과·1개 생략(링크 권한).

## 남은 것

- **C(다음 PR, #37 C 회신):** `AppFolders.db_path()`로 DB·`-wal`·`-shm`이 링크가 아닌 일반 파일인지 확인한 뒤 경로를 준다. SEQ-03 백업 입구 `begin_backup()`도 같은 PR이다. 이름 `db_file`은 #37 회신에 맞췄다.
- **A:** 제품 모드에서 `--db-path` 대신 `AppFolders.paths.db_file`를 쓴다. `--demo`가 이 경로를 열지 못하게 한다.
- **B:** #37(B6.17) 4절의 "C 제공 전 같은 DB의 다중 실행 미지원" 표기를 이 결정으로 바꾼다. 이관 전 백업은 `AppPaths.backups`에 둔다.
- contracts 미결 요청 표의 REC-01 행은 사용자 문서다. "DB 단일 소유 = `app.lock` + 앱 폴더 안 고정 DB" 반영 여부는 사용자가 정한다.

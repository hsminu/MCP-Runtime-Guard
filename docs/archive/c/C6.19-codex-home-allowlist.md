# C6.19 · CODEX_HOME 허용 항목 확인

관련: I11·I7, T22 전제, C-CODEX-06. C6.13 리뷰 의견 1번을 반영했다.

## 한 일

- 리뷰 의견: Codex 0.162.1은 CODEX_HOME의 `AGENTS.override.md`, 없으면 `AGENTS.md`를 사용자 지시문으로 프롬프트에 넣는다(`codex-home/src/instructions/mod.rs`). `project_doc_max_bytes=0`은 프로젝트 문서에만 적용된다. C6.13의 `verify_codex_home`은 고정 파일 두 개의 해시만 봐서 이 파일을 막지 못했다.
- `security/codex_home.py`에 최상위 항목 허용 목록을 넣었다. 허용 항목은 고정 파일 `config.toml`·`model_catalog.json`, Codex가 만드는 파일 `installation_id`·`.sandbox_migration`, 폴더 `tmp`(제품 경로의 `tmp\arg0` 보조 파일)다. 이름이 다르거나, 종류(파일·폴더)가 다르거나, 링크·junction이면 `CODEX_HOME_UNEXPECTED_ENTRY`로 거부한다.
- 앱 시작 쓰기(`write_codex_home`)는 원본 확인 뒤, 쓰기 전에 허용 목록을 보고 실패하면 아무것도 쓰지 않는다. Task 시작 확인(`verify_codex_home`)도 같은 검사를 거친다. AGENTS.md 말고도 Codex가 CODEX_HOME에서 읽는 rules·prompts·skills·hooks 등은 개별로 막지 않고 허용 목록 하나로 막는다.
- 단위 테스트: 지시문 파일 5종(대소문자 변형·`.bak` 포함) 거부, 허용 밖 폴더·종류가 다른 항목 거부, Codex가 만드는 항목 허용, 쓰기 전 거부 시 미기록. 링크 파일 테스트의 기대 코드를 새 검사 순서에 맞췄다.

## 실제 검증([근거](../evidence/c6.19-codex-home-allowlist-2026-10-18.json))

- 수정 전: CODEX_HOME에 표지 문자열을 담은 `AGENTS.md`를 두고 실제 codex.exe 0.162.1과 가짜 모델로 실행하자 확인 함수는 통과했고 표지 문자열이 모델 요청에 들어갔다.
- 수정 후: 같은 파일을 두면 Codex 시작 전에 `CODEX_HOME_UNEXPECTED_ENTRY`로 거부했다. 정상 실행은 시작 전 확인을 통과했고, Codex 종료 뒤 `installation_id`·`.sandbox_migration`이 생긴 상태에서 다시 확인해도 통과했다. 모델 요청의 도구는 `request_user_input`과 Guard 도구 하나 그대로였다.
- Ruff·포맷·mypy 통과. 심볼릭 링크 테스트는 이 PC에서 링크 생성 권한이 없어 건너뛰었다.

## 남은 한계

- `tmp` 폴더 안은 검사하지 않는다. Codex는 CODEX_HOME 최상위의 AGENTS.md만 지시문으로 읽는다. 제품 경로에서 `tmp`에 실제로 생기는 파일은 C6.16에서 확인한다.
- 허용 목록은 이번 실행에서 관찰한 항목과 소스로 확인한 `tmp`다. 제품 경로·로그인(T43, keyring 모드의 `secret_auth_storage`)에서 Codex가 다른 항목을 만들면 Task 시작이 거부된다. 실패 쪽으로 닫히며 C6.16·T43에서 목록을 확정한다.
- 같은 사용자 권한의 공격자는 위협 모델 밖이다(개발문서 0.3절). 이 검사는 앱 폴더에 남은 파일·실수로 둔 파일을 막는 용도다.
- 리뷰 의견 3번(모델 정보의 `persistent_instructions`가 없는 도구를 언급)은 C6.13 실행의 모델 요청에 그 텍스트가 들어가지 않았음을 확인했다. 요청에 들어간 모델 정보 텍스트는 기본 프롬프트(`instructions_template`)뿐이고 A의 `baseInstructions`로 교체될 부분이다. C6.14 프롬프트 확인에서 다시 본다.

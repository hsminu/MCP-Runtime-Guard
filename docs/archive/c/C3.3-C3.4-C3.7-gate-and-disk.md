## 한 일

`tests/unit/test_c3_gate_counts.py`(시험 함수 4개 × stdio·HTTP = 8건)를 더했다. 제품 코드는 바꾸지 않았다.

**C3.3 커밋 전 미공개**
- 관측 커밋(`commit_observation`)을 들어간 자리에서 잡아 둔다.
- 서버는 이미 받았는데(wire 1) `submit`은 끝나지 않았고, OBSERVED 감사도 0이다.
- 풀어 주면 그때 Released가 되고 등급이 INTERNAL이 된다.

**C3.3 커밋 실패**
- 관측 커밋이 실패하면 결과는 `Withheld(STATE_COMMIT_FAILED)`이고 요청은 WITHHELD다.
- 서버는 받았다(wire 1).
- 그 요청의 OBSERVED 감사는 0이고, 민감 자료 등급은 반쯤 오르지 않았다(등급·미분류·승격 이력 그대로).
- Task는 HALTED다. 종결 전이라 보안 버전만 1 오른다.

**C3.4**
- ALLOW 전송 뒤 Task 행 전체가 전송 전과 같다.
- 승인 전송은 대기·복귀로 상태와 revision만 움직인다. 등급·미분류·승격 이력·보안 버전은 그대로이고, 끝나면 RUNNING이다.

**C3.7 원문 비기록**
- 전송 다섯 종류의 `body`에 표지(`C37RAW`)를 넣었다: ALLOW, 승인한 ASK, 승인 대기로 남긴 ASK, DENY, 응답 유실.
- Store를 닫은 뒤 앱 폴더 아래 모든 파일을 바이트로 검사했다(DB·`-wal`·`-shm` 포함). 표지는 0건이다.
- 같은 검사에서, 등급을 올린 읽기의 자원 ID(승격 이력 `source_id`, 허용된 메타데이터)는 보인다. 검사가 파일 내용을 실제로 본다는 양성 대조다.

## 남는 것

- **도구 결과 원문 비기록:** 시험 서버의 결과 본문이 고정 문구(`document`·`sent`)라 표지를 실을 수 없다. 이번 검사는 인자 원문까지다. 결과 본문 표지는 C5.2(합성 문서 fixture) 뒤 같은 검사로 넣는다.
- **이번에 보지 않은 경로:** 미분류 결과와 허용하지 않은 형식·크기 결과의 미공개는 응답 게이트 단위 시험(B)이 보고, 이번 실제 서버 계수에는 넣지 않았다.

리뷰: B(응답 게이트·저장 순서·시험).

# C2.20 · 저장한 Scanner 키를 검사에 연결

관련: [C2.10](C2.10-scanner-key-store.md)(#60, 자격증명 관리자 저장·로딩), [C4.14](C4.14-scan-service-budget.md)(#59, `ScanService`·`cisco_connector`), 2026-10-15 결정("제품 경로는 자격증명 관리자만 읽고 `.env`는 개발·실험용"), I9.

## 배경

- C2.10(#60)으로 키를 자격증명 관리자에 저장하고 읽는 입구가 생겼다. C4.14(#59)로 검사 서비스가 생겼다.
- 두 PR이 따로 들어가서, 제품 검사기 연결(`cisco_connector`)은 아직 넘긴 값만 썼다. 기본값은 빈 값이었다.
- 그래서 사용자가 화면에서 키를 저장해도 제품 검사의 LLM 분석기는 늘 키 없음이었다.

## 한 일

- **`services/scanner.cisco_connector(environ=None)`**
  - **기본(None):** 검사를 열 때마다 `security.secrets.scanner_key_environ()`으로 자격증명 관리자에서 키를 읽는다.
    - 화면에서 바꾼 키는 다음 검사부터 쓰인다. 지운 키는 다음 검사부터 쓰이지 않는다.
    - 키가 없거나 읽지 못하면 빈 값이다. 그러면 LLM은 `SCAN_LLM_KEY_MISSING_OR_INVALID`로 준비 실패하고 YARA만 돈다.
  - **mapping:** 그 시점의 사본을 고정 값으로 쓴다(테스트·개발용).
  - **함수:** 검사마다 부른다(테스트용).
  - `.env`·프로세스 환경은 어느 경우에도 읽지 않는다.
- A 조립은 `ScanService(registry, cisco_connector())`면 된다. 화면은 C2.10대로 `ScannerKeyForm(saver=save_scanner_key)`다.
- **테스트**
  - **`tests/unit/test_scan_service.py`: 3개 추가(25개)**
    - 기본 연결은 열 때마다 저장소를 읽는다. 첫 연결은 빈 값, 두 번째는 저장한 키이고, 프로세스 환경의 키는 쓰지 않는다.
    - 고정 mapping은 넘긴 뒤 바꿔도 처음 사본을 쓰고, 함수는 연결마다 불린다.
    - 실제 자격증명 관리자(테스트 전용 대상): 저장한 키가 다음 연결에 들어가고, 지운 뒤에는 빈 값이다. 테스트 뒤 남은 항목은 0이다.
  - **`tests/contract/test_scan_service_sdk.py`:** "제품 연결은 프로세스 환경을 읽지 않는다" 테스트가 이제 기본 연결이 자격증명 관리자를 읽는다. 개발자 PC에 저장된 실제 키에 기대지 않도록 빈 테스트 대상을 읽게 했다.

## 검증

- 로컬(Windows 11, Python 3.12.10, main `1423bd1` 기준)
  - Ruff·포맷·mypy(101개 파일) 통과
  - `test_scan_service.py` 25개 통과, 3회 반복해도 같음
  - `tests/contract/test_scan_service_sdk.py` 3개 통과
  - 전체 pytest 5,095개 통과, 4개 생략, 서브테스트 20개 통과
  - 테스트 뒤 자격증명 관리자의 `MCPRuntimeGuard` 항목 0개

## 남는 것

- **A 연결:** 화면(`ScannerKeyForm(saver=save_scanner_key)`)과 조립(`ScanService(registry, cisco_connector())`)
- **LLM 실제 호출:** 실제 키로 제품 검사를 끝까지 돌리는 측정은 C4.16과 함께 한다.

리뷰: B(테스트), A(조립).

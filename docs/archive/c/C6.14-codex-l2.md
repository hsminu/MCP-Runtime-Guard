# C6.14 · Codex L2 시작 시험

관련: I11, T22·T39·T40, C-CODEX-02·03·07, C6.21. #21 3번 결정에 따라 A가 연 L2 결과 입구에 C 구현을 채운다.

## 한 일

- **`security/launcher.py`**
  - L2 전용 입구 `CodexLauncher.l2_spec`·`launch_l2`를 추가했다.
  - 제품 명세(실행 파일·CODEX_HOME·환경 허용 목록·`sqlite_home`)에 고정된 가짜 모델 덮어쓰기와 토큰 환경변수 하나(`GUARD_L2_TOKEN`)만 더한다.
    - 고정 덮어쓰기는 `model_provider=guard_l2`, `127.0.0.1:<포트>/v1`, `wire_api=responses`, 재시도 0, websocket 끔이다.
    - 바뀌는 값은 포트와 이번 실행의 토큰뿐이다.
  - 제품 세션 입구(`launch`)는 그대로 `sqlite_home` 하나만 넘긴다. 실행 수는 `l2_launches`로 따로 센다.
- **`security/codex_l2.py`**(새 모듈)
  - **`MockModel`:** `127.0.0.1` 임의 포트에 잠깐 여는 asyncio HTTP 서버다.
    - 실행마다 만든 토큰을 보낸 `POST /v1/responses`만 받는다. 다른 요청은 기록하고 거부한다. 토큰이 틀리거나 chunked 본문이면 거부한다.
    - 첫 응답은 강제 호출 묶음이고, 그 뒤로는 최종 답 하나를 스트리밍으로 보낸다.
  - **`observe_l2`:** `create_task_folder` → `launch_l2` → stdio JSON-RPC로 아래 순서를 진행한다.
    - `initialize` → `configRequirements/read` → `config/read`(설정 층 포함) → `remoteControl/status/read` → `thread/start` → `turn/start`
    - 승인 요청에는 거절로, `request_user_input`에는 빈 답으로 응한다.
    - Guard 도구 호출에는 0.3초 붙잡은 뒤 답해서, 두 호출이 겹치는지 본다.
    - 끝나면 `close()`로 종료를 확인한 뒤에만 시험 폴더를 지운다.
  - **`evaluate`:** 관찰을 고정 실패 코드로 판정하는 순수 함수다. 허용 목록 방식이라, 버전이 바뀌어 모양이 달라지면 실패한다.
    - **requirements:** 없어야 한다.
    - **설정 층:** 실행 인자 층(`sqlite_home`·`model_provider`·`model_providers`만), 우리 `config.toml`, 비어 있는 시스템 층 셋뿐이어야 한다.
    - **적용 값:**
      - L1의 모든 키가 그대로 적용돼야 한다. `model_catalog_json`은 CODEX_HOME 기준 절대 경로로 대조한다.
      - L1 밖에서 켜진 기능은 `mentions_v2`(TUI)만 허용한다.
      - `mcp_servers`·지시문 키가 비어 있어야 하고, 제공자가 고정값과 같아야 한다.
    - **원격 제어:** `disabled`여야 한다.
    - **`thread/start`:** `environments=[]`·`ephemeral`·`approvalsReviewer="user"`·시험용 도구·`baseInstructions`가 있어야 한다.
    - **도구:** 모델 요청의 도구가 정확히 `functions.request_user_input`과 `guard_l2.probe`여야 한다(T39).
    - **프롬프트**
      - 개발자 메시지는 우리 `baseInstructions`와 Codex 기본 협업 모드 블록 두 개, 사용자 메시지는 시험 문장 하나여야 한다.
      - 권한·환경·skills·plugins·apps·AGENTS 지시문 등 안내 블록 표지 10종이 없어야 한다(C6.21).
    - **금지 호출(T40)**
      - 함수 이름 28개는 `unsupported call: <이름>`, custom `apply_patch`는 `unsupported custom tool call: apply_patch`, `local_shell_call`은 `aborted`여야 한다.
      - 앞의 6개와 `local_shell_call`이 10-15 실험의 금지 도구 7종이다. 나머지 22개는 0.162.1 소스(`codex-rs/core/src/tools`)에서 찾은 내장 도구다.
    - **항목·요청:** 항목 알림은 허용 종류만, 서버 요청은 Guard 도구 호출만 있어야 한다.
    - **Guard 도구 호출:** 두 개가 순서대로 하나씩 와야 한다.
    - **마무리:** turn 완료, 가짜 모델 밖 통신 없음, 종료 확인, 폴더 삭제.
  - **`run_l2(launcher, folders, *, thread_params)`**
    - `L2Report(passed, failures, home_digest, executable_sha256, model_sha256)`를 돌려준다.
    - `thread_params`는 A의 `thread_start_params`를 감싼 함수다. 제품 세션과 같은 인자로 시험하기 위해서다. security 모듈이 services·adapters를 가져오지 않게 함수로 받는다.
- **`tests/unit/test_codex_l2.py`**(53개, codex.exe 없이 실행)
  - 실제 실행 모양의 통과 관찰
  - 한 군데씩 어긋나게 만든 41가지 경우가 각자 실패 코드를 내는지
  - 가짜 모델 서버(대본·토큰·다른 경로·chunked 거부)
  - L2 실행 명세(고정 덮어쓰기만 더함, 포트·토큰 검사)

## 실제 검증([근거](../evidence/c6.14-codex-l2-2026-10-27.json))

codex.exe 0.162.1을 썼다. 근거 소스는 `rust-v0.162.1`(`092d3ac`)이다.

- **정상 L2(`run_l2`)**
  - 제품 경로와 같은 TEMP 밖 루트에서 통과했다(2.84초, 실패 0).
  - 관찰 결과
    - requirements null
    - 설정 층 세 개
    - L1 기능 전부 적용, 원격 제어 `disabled`
    - 도구 2개, 금지 호출 28/28 거부, `local_shell_call` `aborted`
    - 항목은 사용자·답변·Guard 도구 호출뿐이고 승인 요청 0
    - 프롬프트 안내 블록 0
  - C6.21의 `include_permissions_instructions`·`include_environment_context`가 실제로 먹힌 것을 이 실행으로 확인했다.
- **회귀를 잡는지:** L1의 `multi_agent=true`와 모델 정보의 `multi_agent_version=v1`인 시험 사본으로 돌렸다.
  - Codex가 `tool_search` 도구를 새로 내놓았고, 강제 호출한 `tool_search`가 `unsupported`가 아니라 `aborted`로 처리됐다.
  - 저장소 L1 기준 판정은 `L2_CONFIG_MISMATCH`·`L2_TOOLS_UNEXPECTED`·`L2_FORBIDDEN_NOT_REFUSED`였다.
  - 그 사본 자신의 L1 기준으로도 뒤의 두 코드가 났다. 설정 대조를 피하는 회귀도 도구 시험에서 걸린다.
- **셸 계열은 세 겹으로 막혀 있다:** L1의 `shell_tool`·`unified_exec`과 모델 정보의 `shell_type=unified_exec`을 함께 켜도 셸 도구가 나오지 않았다. `environments=[]`가 환경 의존 도구를 뺀다(`core/src/tools/spec_plan.rs`). 그래서 셸 계열은 L1, 고정 모델 정보, `environments=[]`가 함께 막는다.
- **turn 진행 중 종료 시간(A 요청, #35 A 리뷰):** 두 경우 모두 stdin EOF로 스스로 끝났다(종료 코드 0, `close()` True).
  - Guard 도구 호출에 아직 답하지 않은 상태: 0.11초
  - 모델 응답이 지연되는 상태: 0.05초
  - A의 `confirm_exit` 상한을 정할 때 참고할 실측값이다.
- **전체 검사**(main `c2da9e0` 기준, Windows 11, Python 3.12.10)
  - Ruff·포맷·mypy(85개 파일)·`pip check` 통과
  - contract 41개 통과
  - 단위 4,322개 통과, 2개 생략. 생략한 둘은 링크 권한 테스트와 `GUARD_TEST_CODEX_EXE`가 없을 때의 실제 L2 테스트다.

## 남은 한계와 후속

- **실제 제공자 차이:** L2는 모델 제공자만 가짜로 바꾼 실행이다. 실제 OpenAI·ChatGPT 제공자에서 서버가 다른 모델 정보나 기능을 강제하는 경우(C-CODEX-03)는 고정 모델 정보와 L3(C6.15)가 맡는다.
- **시험용 도구:** L2의 Guard 도구는 시험용 하나다. 실제 등록 도구의 이름 규칙·묶음은 A의 `build_dynamic_tools`와 #31 결정이 맡는다.
- **A 연결:** A의 `_prepare_startup`에서 다음 순서로 연결한다.
  - `write_codex_home` → `CodexLauncher` → `run_l2(launcher, folders, thread_params=...)`
  - `StartupReceipt(configuration, ConfigurationReceipt(report.home_digest, report.executable_sha256, report.model_sha256), report.passed)`로 채운다.
  - 실패 코드는 화면에 고정 문구로만 보인다.
- **CI에서 실제 L2(C6.22, 후속):** 워크플로에서 `tools/install_codex.py`로 codex.exe를 받고 `GUARD_TEST_CODEX_EXE`로 이 테스트를 켠다. 공용 CI 파일을 바꾸는 일이라 따로 제안한다.
- **Codex 버전을 바꿀 때:** 금지 이름·안내 블록 표지·허용 항목은 그 버전 소스로 다시 뽑는다. L2를 통과한 뒤 PR로 올린다(10-18 결정).

리뷰: B(`security/*`), A(`thread_params` 연결·실패 코드 표시).

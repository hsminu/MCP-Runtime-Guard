# C3.9·C3.10 · DB를 직접 고친 뒤 다음 시작이 멈추는지, 멈추지 않으면 실행 권한이 없는지

2026-10-30 · 관련: [사용자 결정](../../contracts.md#사용자-결정) 2026-10-15(DB 변조는 위협 모델 밖, 손상·불일치는 fail-closed, 관계 깨짐·모르는 상태값은 시작 점검에서 멈춤), 개발문서 11.5 REC-02, B6.8(#69), #96 B6.10.

## 한 일

`tests/unit/test_c3_startup_tamper.py`(변조 13가지 × 정상 종료·비정상 종료 = 26건)를 더했다. 제품 코드는 바꾸지 않았다.

**순서**
1. 하니스(`c_counting`, 실제 stdio 서버)로 상태를 만든다: T01 ALLOW 전송, T02 승인 대기, 민감 자료 읽기, 규칙 없는 경로 읽기(미분류).
2. Guard를 닫거나(정상 종료: 대기 승인 취소) 버린다(비정상 종료: 승인이 대기로 남음). 그 뒤 Store를 닫는다.
3. 외래 키·CHECK를 끈 별도 연결로 행을 고친다.
4. B6.8 명시 시작(이관 준비 → 복구 → 회차 활성화)을 다시 한다.

**판정:** 시작이 `StorePrepareError(STORE_INTEGRITY_FAILED)`로 멈추거나, 복구되더라도 다음 셋을 모두 만족해야 한다.
- 옛 승인은 실행되지 않는다(늦은 승인 거부).
- 옛 승인 대기 SEND의 계수(승인 소비·dispatch·wire·효과)가 0이다.
- 새 회차의 새 Task는 정상 전송된다(양성 대조).

- 복구된 경우의 복구 보고: 정상 종료는 승인 변경 0건이다(닫을 때 이미 취소됐기 때문). 비정상 종료는 1건(EXPIRED)이다. 두 경우 모두 미해결 0, 격리 0이다.
- **C3.10은 결정대로다.** 등급·미분류가 감사 기록이나 승격 이력과 맞지 않으면 복구하지 않는다.
- **감사 기록까지 함께 낮춘 변조는 대조할 근거가 남지 않아 복구된다.** 행 서명·HMAC을 두지 않기로 한 2026-10-15 결정의 예상 범위다. 이때도 옛 Task·승인은 재개되지 않는다(REC-02).

## 발견(C-C3-01, 낮음)

- 시작 점검이 요청 행의 결속 세 필드(`epoch`가 Task epoch보다 큼, `kind`, 복구 이력 없는 `row_revision`)를 대조하지 않는다.
- 같은 변조는 실행 중에는 B6.10 소비 결속 검사가 막는다(#96 C 리뷰 실측).
- 결정은 "관계가 깨졌거나 설명할 수 없는 조합은 게이트를 닫는다"인데, 이 셋은 닫지 않고 복구를 마친다.
- 실행 권한은 생기지 않는다(두 종료 모두 실측). 그래서 심각도는 낮음으로 본다.
- 시작 점검에 대조를 더할지, 결정에서 "설명할 수 없는 조합"의 범위를 좁힐지는 B 판단이 필요하다. [관리대장](../../weakness_register.md#발견-항목과-조치)에 올렸다.
- 시험은 지금 동작(복구됨, 실행 0)을 기대값으로 두었다. B가 대조를 더하면 기대값을 "멈춤"으로 바꾼다.

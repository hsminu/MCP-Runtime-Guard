# C6.8-2 · 실제 codex.exe를 거친 T 시나리오(T01–T03·T21·T41–T43·T45·T46, C6.16 일부)

관련: C6.8(C 담당 T/S), C6.14(L2 가짜 모델), C6.15·C6.16, C6.8-1(Guard 입구 계수), A88(A 끝에서 끝까지 시험), #83(A138·A151 제품 시작 경로), I3·I6·I8·I9·I11.

## 배경

- C6.8-1까지의 계수는 Guard 입구를 직접 불렀다. Codex를 거친 시나리오(T21·T41–T46)는 실제 Codex 연결(A19·A20) 뒤로 미뤄져 있었다.
- 화면은 필요 없다. A의 제품 시작 `bootstrap_product`는 앱 폴더·설정 파일·`SessionPreparation`을 받는다. #83부터 B6.8 명시 시작, 같은 Store 위의 Registry, 설정에서 만든 조립 입력(C launcher·HTTP)까지 제품 경로 안에 있다.
- C6.14 L2에는 실제 codex.exe를 루프백 가짜 모델에 붙이는 명세(`CodexLauncher.l2_spec`)와 정해진 도구 호출을 내는 `MockModel`이 이미 있다. 이 둘로 OpenAI 계정 없이 결정적으로 돌릴 수 있다.

## 관찰

1. **Codex가 대화를 디스크에 쓰지 않는다.** 고정 0.162.1에 L1 설정과 ephemeral 스레드면, 실행 중에도 Task 폴더 DB(`threads`·`logs` 행 0)와 CODEX_HOME 어디에도 표지가 없었다. T43은 실행 중에도 성립한다. 그래서 검사기 자체를 대조군으로 확인했다.
2. **허용 밖 항목의 처리:** 웹 검색(`web_search_call`)은 Codex가 A에게 넘기고 A가 멈춘다. 셸 실행(`local_shell_call`)·이미지 생성(`image_generation_call`)은 Codex가 실행하지 않고 넘기지도 않는다. 턴은 정상으로 끝난다.
3. **T42 감사 순서:** `POST_DISPATCH_ERROR` 뒤 `SESSION_PROCESS_FAILED`다. 결과 불명 뒤 relay가 정지 응답(`CODEX_TOOL_STOPPED`)을 돌려주고 A가 그 Task의 Codex 세션을 끝낸다(PR #28 B 리뷰 합의, #84 A 리뷰).
4. **빈 CODEX_HOME과 다르다:** L1 없이 띄운 app-server는 `.tmp/plugins-clone`에서 플러그인 저장소를 받았다(#78 C 리뷰 프로브). L1을 쓴 이 하니스에서는 생기지 않았다.
5. **Guard DB의 표지:** 제품 DB가 앱 폴더 `data` 안으로 들어와 T43 검사 범위에 들어갔다. ALLOW 경로(T43)에서는 Guard DB에도 표지가 없었다. ASK 경로는 T43에 없다.

## 제품과 다른 점

- **Task 세션 준비:** `SessionPreparation`은 하니스 것이다. Task마다 대본 가짜 모델에 붙인다. 앱 시작 L2는 제품과 같은 인자다.
- **조립 입력 두 값:** 설정에서 만든 `ProductInputs`에 `resource_resolver`(경로 그대로)와 호출 상한을 더한다.
  - 제품은 아직 READ 도구의 resource resolver가 없다. 그래서 resource 인자가 있는 READ는 `INTERNAL_ERROR`로 거부된다. 화면 등록 도구는 종류가 OTHER라 지금 제품에서는 닿지 않는다(A49 로컬 파일 서버 규칙에서 연결).
  - 제품 호출 상한은 30초 고정이다. T42만 2초로 줄였다.
- **모델:** 대본 가짜 모델이다. 실제 모델의 공격 문장 추종은 범위 밖이다(개발문서 14.5: 성공 판정은 수신측 계수 0).

# C2.10 · Scanner LLM 키 저장·로딩 (Windows 자격증명 관리자)

관련: 2026-10-15 사용자 결정("Scanner LLM API 키는 사용자가 각자 준비하고 Windows 자격증명 관리자(DPAPI)에 저장한다 … 저장·로딩은 C(`secrets.py`), 입력 화면은 A"), A `ui/scanner_key.py`(`ScannerKeyForm`, `KeySaver = Callable[[str], bool]`), [C4.14](C4.14-scan-service-budget.md) `cisco_connector`, I9.

## 배경

- A의 키 입력 화면(`ScannerKeyForm`)은 이미 있다. 가려진 입력칸이고 저장에 성공하면 끝 4자리를 보여 준다. 하지만 `KeySaver`를 채울 C 입구가 없었다.
- 제품 검사(C4.14 `ScanService`)는 키를 넘긴 값으로만 받는다. 넘길 키가 없으니 LLM 분석기는 늘 준비 실패이고 YARA만 돈다.
- 지금 키를 읽는 경로는 개발·실험용 `.env`와 프로세스 환경(`load_scanner_environment`)뿐이다.

## 한 일

- **`security/secrets.py`:** Windows 자격증명 관리자 입구. `advapi32`의 `CredWriteW`·`CredReadW`·`CredDeleteW`·`CredFree`를 ctypes로 부른다.
  - **저장소:** 일반 자격증명(`CRED_TYPE_GENERIC`), `CRED_PERSIST_LOCAL_MACHINE`. 현재 사용자의 자격증명이라 Windows가 사용자 DPAPI로 암호화하고, 다른 사용자는 읽지 못한다. 대상 이름은 `MCPRuntimeGuard/ScannerLLMKey`이고, 대상은 `MCPRuntimeGuard/` 아래 이름만 받는다.

    | 입구 | 하는 일 |
    | --- | --- |
    | `store_scanner_key(key)` | 형식을 검사하고 저장한다(같은 대상은 덮어씀). `CredWriteW`에 넘기는 ctypes 버퍼는 쓴 뒤 0으로 지운다. 호출자의 문자열과 `bytes` 사본은 지울 수 없다(#60 B 리뷰 정정) |
    | `save_scanner_key(key) -> bool` | A `KeySaver`. 성공일 때만 True |
    | `load_scanner_key() -> str \| None` | 없으면 None. 저장된 값이 형식 밖이면 `SCAN_KEY_STORED_INVALID` |
    | `scanner_key_tail() -> str \| None` | 끝 4자리(재시작 뒤 화면 표시용) |
    | `delete_scanner_key() -> bool` | 지웠거나 원래 없었으면 True |
    | `scanner_key_environ() -> dict` | 검사기 연결에 넘길 `{"OPENAI_API_KEY": 키}`. 키가 없거나 읽지 못하면 빈 dict. 프로세스 환경·`.env`는 보지 않는다 |

  - **키 형식:** `[A-Za-z0-9_-]` 20–512자. 공백·줄바꿈·따옴표·비ASCII는 붙여 넣기 실수로 보고 거부한다(`SCAN_KEY_INVALID`).
  - **오류 코드(`ScannerKeyError`):** 키·Windows 오류 원문을 싣지 않는다.

    | 코드 | 경우 |
    | --- | --- |
    | `SCAN_KEY_INVALID` | 키 형식이 틀림 |
    | `SCAN_KEY_TARGET_INVALID` | 앱 밖의 대상 이름 |
    | `SCAN_KEY_STORED_INVALID` | 저장된 값이 형식 밖 |
    | `SCAN_KEY_STORE_UNAVAILABLE` | `ERROR_NO_SUCH_LOGON_SESSION`(1312). 로그온 세션이 없는 서비스 계정 등 |
    | `SCAN_KEY_STORE_FAILED` | 그 밖의 Windows 오류 |
    | `SCAN_KEY_STORE_UNSUPPORTED` | Windows가 아님 |

  - 모듈 docstring에 제품 키 경로와 한계를 적었다.
- **실측(2026-10-28, Windows 11):** ctypes로 쓰기·읽기·삭제가 됐다. 읽은 값은 쓴 값과 같았고 Type 1, Persist 2였다. 없는 대상을 읽거나 지우면 1168(`ERROR_NOT_FOUND`)이다.
- **테스트** `tests/unit/test_scanner_key_store.py` 23개
  - 테스트마다 새 대상 이름(`MCPRuntimeGuard/test-<난수>`)을 쓰고, 끝나면 지운다. 제품 대상은 건드리지 않는다.
  - 로그온 세션이 없는 환경에서는 건너뛴다.
  - **왕복:** 저장 → 읽기 → 끝 4자리 → 덮어쓰기 → 삭제 → 없음 → 다시 삭제(True). 저장소의 Type 1·Persist 2와 저장 바이트를 직접 읽어 확인했다.
  - **거부:** 형식이 틀린 키 10가지(쓰지 않음), 앱 밖 대상 5가지, 저장소에 직접 넣은 형식 밖 값 2가지(쓰지 않고 검사기 값은 빈 dict)
  - **검사기 값:** 프로세스 환경에 다른 키를 심어도 저장소 값만 쓴다. `load_scanner_environment(environ=…)`로 그 키가 Scanner 설정까지 간다.
  - **누출 없음:** 키가 로그·오류·repr·원인 예외·프로세스 환경에 없다.
  - **오류 코드:** Windows 오류 1312·5가 고정 코드로 바뀐다(대역).
  - **A `KeySaver`:** 성공·실패를 bool로만 알린다(대역).
  - 테스트 뒤 자격증명 관리자에 `MCPRuntimeGuard` 항목이 남지 않은 것을 `cmdkey /list`로 확인했다.

## A 연결

- **조립:** `ScannerKeyForm(saver=save_scanner_key)`. 화면을 열 때 `scanner_key_tail()`로 저장된 키의 끝 4자리를 보여 줄 수 있다.
- **검사:** #59(C4.14) 병합 뒤 C가 `cisco_connector`를 검사마다 `scanner_key_environ()`을 읽게 바꾼다. 화면에서 바꾼 키가 다음 검사부터 반영된다.

## 남는 한계

- 같은 사용자 권한의 프로세스는 이 자격증명을 읽을 수 있다(위협 모델 밖).
- Python 문자열은 메모리에서 지울 수 없다. `CredWriteW`에 넘기는 ctypes 버퍼만 0으로 지우고, 호출자의 `str`과 `key.encode("ascii")`로 만든 `bytes` 사본은 GC 때까지 남는다. 테스트는 이 지우기를 확인하지 않는다.
- **테스트가 강제로 끝나면**(프로세스 종료·디버거 중단 등) `finally`가 돌지 않아 `MCPRuntimeGuard/test-*` 항목이 개발자의 자격증명 관리자에 남을 수 있다(#60 B 리뷰). 찾기: `cmdkey /list | findstr MCPRuntimeGuard/test-`. 지우기: `cmdkey /delete:MCPRuntimeGuard/test-<난수>`. 제품 대상(`MCPRuntimeGuard/ScannerLLMKey`)은 테스트가 쓰지 않는다.
- 키가 유효한지(OpenAI가 받아 주는지)는 저장 때 확인하지 않는다. 첫 검사가 `SCAN_LLM_AUTH_FAILED`로 알려 준다.
- 사용 한도 안내 문구는 A 화면 몫이다.

리뷰: B(테스트), A(화면 연결).

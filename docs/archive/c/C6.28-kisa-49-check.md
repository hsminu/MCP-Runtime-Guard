## 발견 2건

### C-SCHEMA-01: 서버 정규식에 의한 Guard 정지(ReDoS, CWE-1333)

- **KISA 분류:** 시간 및 상태(종료되지 않는 반복문)
- **위치:** `services/catalog.py` `resolve` → `catalog_schema.ArgumentSchema.validate` → `schema_jobs.validate`
- **원인**
  - 도구 인자를 등록 스키마로 검증한다. 이때 MCP 서버가 준 `pattern`·`patternProperties` 정규식을 모델이 정한 인자에 실행한다.
  - 제품 조립은 별도 프로세스 실행기(`schema_runner`)를 넘기지 않는다. 그래서 검증이 Guard 이벤트 루프 안에서 시간 제한 없이 돈다.
- **실측(고치기 전):** `^(a+)+$`에 `"a"*n + "!"`를 넣었다. 길이 21은 0.03초, 25는 0.50초, 27은 2.00초였다. 두 글자마다 4배씩 늘고, 인자 상한(256KB)으로는 막지 못한다.
- **경로**
  - 등록한 서버의 스키마에 이런 정규식이 있고, 모델이 그 도구를 그런 인자로 부르면 된다(프롬프트 삽입으로 유도 가능).
  - 검증은 정책 판정 전에 돌기 때문에, 그 도구가 DENY여도 멈춘다.
- **조치**
  - **`pattern`:** 인자 검증에서 실행하지 않는다(`schema_jobs._ArgumentValidator`, jsonschema 검증기의 `pattern`만 바꿈). 모델에 보이는 스키마에는 남고, 값 형식은 MCP 서버가 검사한다. Guard 판정(목적지 정확 일치, 자원 해석)은 이 값에 기대지 않는다.
  - **`patternProperties`:** 지원하지 않는다(`SchemaJobFailure.PATTERN_PROPERTIES`). 속성 이름 정규식은 `additionalProperties`·`unevaluatedProperties` 판정에서도 실행되기 때문이다. 다른 미지원 키워드(`$ref` 등)처럼 준비 단계에서 거부한다.
  - 스키마 정규식의 컴파일 검사는 그대로다(컴파일은 인자를 받지 않는다).
- **한계**
  - `patternProperties`를 쓰는 도구를 활성화하면 기존 미지원 스키마와 같이 제품 조립이 `PROFILE_TOOL_INVALID`로 실패한다. 그 도구를 끄면(종류 `OTHER`) 다시 동작한다.
  - 근본 해결(시간 상한이 있는 별도 프로세스 실행기, SCHEMA-01 "C 연결 이후")은 남는다.
- **재검사:** 같은 스크립트로 길이 17·27·41·1,001·100,001이 모두 0.00초였다. `test_schema_jobs_semantics`에 두 시험을 더했다.
  - 서버 정규식 미실행: 65자 1초 안, 나머지 검증 유지
  - `patternProperties` 거부: 최상위·중첩

### C-UI-01: 호출 로그 툴팁의 서식 글자 해석

- **KISA 분류:** 입력데이터 검증 및 표현(크로스사이트 스크립트에 해당하는 Qt 서식 글자 삽입)
- **위치:** `ui/call_logs.py` 셀 툴팁 `item.setToolTip(value)`
- **원인:** 셀 문자열에는 MCP 서버가 정한 도구 이름이 들어간다. Qt는 툴팁 문자열의 태그를 서식으로 그린다. 그래서 이름에 `<b>`·`<img>`를 넣으면 화면을 꾸밀 수 있었다. 스크립트 실행은 되지 않는다.
- **조치:** 이미 있는 `widgets.plain_tooltip`으로 감쌌다. 다른 툴팁 50여 곳은 이미 도우미를 쓰거나 고정 문구였다(#110 C 리뷰에서 짚은 줄).
- **재검사:** `test_call_logs`에 태그 이름 시험을 더했다.

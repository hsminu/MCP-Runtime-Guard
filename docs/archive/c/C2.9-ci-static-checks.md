# C2.9 · 단일 구현 지점 정적 강제 (C6.4 포함, C6.3 일부)

관련: 개발문서 2장 의존 규칙 표, 13.4절 Semgrep 규칙, 13.5절 CI 파이프라인, I1, AGENTS.md "위험 연산은 지정된 모듈", [C6.1 CI 1단계](../integration-a-b.md), #58(B6.13 writer 경계 C 동의).

## 사용자 선택(2026-10-29, 계획 보고에서 추천대로)

- **uv:** 로컬에 0.13.0을 설치해 lock을 다시 만든다.
- **Semgrep:** Windows wheel이 없고 의존성 고정이 프로젝트 lock과 맞지 않는다. 그래서 CI Linux 작업에서 해시 고정 요구 파일로 따로 설치한다.
- **걸리는 곳:** 그 줄에 `# nosemgrep: <규칙>`과 사유를 달고 대장에 기록한다. B 파일은 주석만 바꾸고 B 리뷰를 받는다.
- **writer 넓은 예외 경계:** 예외로 등록한다. AGENTS·설계의 "세 경계" 문구 수정은 사용자에게 따로 제안한다.
- **pip-audit:** 이 작업에서 분리한다. 의존성을 정리한 뒤 실패로 막는 단계로 넣는다. litellm은 예외로 등록한다.

## 검증

- **import-linter:** 7개 계약 모두 지켜진다. 위반 확인은 아래처럼 했다.
  - 위반 import를 심은 임시 파일 두 개: `core`에서 `sqlite3`·`subprocess`·`httpx`·`services`·`mcp`, `ui`에서 `storage`
  - 7개 모두 깨졌다. 표준 라이브러리 모듈도 잡힌다.
- **Bandit 1.9.4 `-ll`:** 중간 이상 0건(낮음 2건은 기준 밖)
  - main에 #69(B6.8)가 들어온 뒤 오탐 1건(B113)이 생겼다. 시작 복구 코드가 `requests`라는 이름의 dict를 `.get()`으로 조회하는 줄이다. 그 줄에 사유 주석과 `# nosec B113`을 달았다(B 파일, 주석만, 대장 BA-01). PR CI는 main과 합친 상태로 돌아서 여기서 잡혔다.
- **contract 테스트:** 45개 통과, 13초. 외부 연결은 막힌 상태다.
- **Semgrep:** 이 PC에는 WSL·Docker가 없어 로컬에서 돌리지 못했다. CI Linux 작업(#72) 결과는 다음과 같다.
  - `src` 107개 파일에 규칙 10개, 0건
  - 규칙 시험 10/10 통과
  - 예외 주석을 끈 검사 4건 = SG-01–04(`SEMGREP_EXCEPTIONS_OK 4`)
  - 첫 규칙 시험은 시험 파일 docstring의 표시 문구를 Semgrep이 시험 표시로 읽어 실패했다. 문구를 바꿨다.
- **나머지:** Ruff·포맷·mypy 통과, 전체 단위 pytest 5,448개 통과, 5개 생략, 서브테스트 20개 통과(mypy 106개 파일). lock export를 다시 해도 같다.

## 남는 것

- **C6.3 pip-audit 단계:** 의존성 정리 PR(간접 3개 lock 갱신, mcp 1.30.0은 A·B 합의, litellm 예외) 뒤에 실패로 막는 단계로 넣는다.
- **"세 경계" 문구:** AGENTS·개발문서는 넓은 예외 처리를 `fail_closed`·`after_dispatch`·`ServerWorker._execute` 세 경계로 적는다. B6.13 writer `_execute`는 네 번째다. 문구를 고칠지는 사용자 결정이다.
- **동적 import 규칙:** 개발문서 2장은 동적 import도 Semgrep으로 막는다고 하지만 13.4절 목록에는 없어 넣지 않았다. 넣으면 Cisco 어댑터 두 파일(SDK 지연 import, C-CISCO-05)이 예외가 된다.
- **mypy `--strict`:** 13.5절의 domain·core·security 범위는 이번 범위가 아니다.

리뷰: B(예외 주석 3곳·규칙), A(CI·`ui`·transport 계약).

# C2.16 · 앱 폴더 권한 확인의 SID 약어 비교 수정

관련: C2.13, #35 CI 실패(run 40305952745), B #35 리뷰 5번.

## 원인

- #35의 CI(Windows 러너)에서 `test_paths.py` 7개가 실패하고 20개가 오류였다. 오류 코드는 `APP_FOLDER_PERMISSION_FAILED`·`APP_ROOT_NOT_OWNED`였다.
- CI 로그의 현재 사용자 SID는 `S-1-5-21-…-500`, 즉 내장 Administrator(RID 500)였다. SDDL 변환은 이 SID를 `LA` 약어로 쓴다. `_owner_sid`·`_is_private`가 SDDL 문자열을 그대로 비교해서 같은 계정을 다르게 봤다.
- 테스트가 `mkdir`로 미리 만든 폴더는 관리자 권한 실행에서 기본 소유자가 Administrators다. 그래서 "이전 실행이 남긴 앱 폴더"를 흉내 낸 테스트 4개가 소유자 확인에서 거부됐다.

## 한 일

- `security/paths.py`
  - `_canonical_sid`: SDDL의 SID 표기(`SY`·`LA`·`BA` 같은 약어 포함)를 `ConvertStringSidToSidW` → `ConvertSidToStringSidW`로 `S-1-…` 문자열로 바꾼다.
  - `_owner_sid`·`_dacl_entries`는 항상 이 형태를 돌려준다. `_is_private`는 SYSTEM을 `S-1-5-18`(`SYSTEM_SID`)로 비교한다.
  - B 리뷰 3번: `_dacl_entries`는 정규식으로 읽지 못한 ACE(조건부 ACE 등)나 남은 문자가 있으면 나머지만 보고 판단하지 않고 고정 오류를 낸다.
  - 제품 규칙은 그대로다. 이미 있는 루트·관리 폴더는 소유자가 현재 사용자일 때만 쓴다.
- `tests/unit/test_paths.py`
  - 미리 만든 폴더는 `_own`으로 소유자를 현재 사용자로 적는다. `SetNamedSecurityInfoW`는 소유자만 바꿔도 상속 ACE를 다시 계산해 DACL을 바꾸므로(이 PC에서 확인), DACL을 건드리지 않는 `SetFileSecurityW`를 쓰고 이미 현재 사용자면 아무것도 하지 않는다.
  - 새 테스트: SDDL 약어 → 전체 SID, `LA` 소유자·ACE를 사용자로 인정, 읽지 못한 ACE 거부.

## 검증

- 로컬(Windows 11, Python 3.12.10, 일반 사용자): `test_paths.py` 44개 통과.
- 내장 Administrator 계정의 실제 동작은 로컬에서 재현할 수 없다. `LA` 약어는 `_security_sddl` 대역 테스트로 확인했고, 실제 확인은 CI 러너다.

## 남은 것

- B 리뷰 2번(루트 DACL 재적용을 잠금 뒤로)은 결과 권한이 같아 이번에 바꾸지 않았다. 후속 검토 항목이다.

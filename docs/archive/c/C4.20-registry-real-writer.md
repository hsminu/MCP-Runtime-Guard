# C4.20 · C4.19 실제 writer 재현 (커밋 직후 취소)

관련: [C4.19](C4.19-registry-unknown-write.md)의 남는 것("실제 저장소로 커밋 뒤 취소 재현: B6.13 뒤"), B6.13 SQLite 전용 writer(#58, 병합), I6·I10.

## 배경

- C4.19는 Registry 제어 쓰기의 결과를 모를 때 그 서버를 닫는다.
  - 실패·취소·예상 밖 예외 뒤에는 ACTIVE를 PENDING으로 본다.
  - 다음 제어 연산이나 `refresh`가 DB 행을 다시 읽어 맞춘다.
  - `observe`는 이번 실행 동안 PENDING으로 둔다.
- B6.13 writer의 취소 규칙: 이미 시작한 쓰기는 커밋이나 롤백이 끝난 뒤에 호출자에게 `CancelledError`를 돌려준다. 그래서 "DB에는 커밋됐는데 호출자는 결과를 받지 못한" 경우가 실제로 생긴다.
- 이미 있던 시험은 둘이다.
  - **C4.19 시험:** 모든 쓰기 종류를 실제 SQLiteStore로 커밋한 뒤, 저장 호출을 감싼 곳에서 취소했다. writer 안에서 취소한 것은 아니다.
  - **#58 B 시험(`test_b_registry_writer_integration.py`):** 실제 writer로 세 경우를 봤다.
    - `block`을 COMMIT 직후 취소
    - 시작 전 취소
    - COMMIT 실패(FAULTED)
- 그래서 같은 것을 다시 만들지 않고, 실제 writer로 보지 않은 나머지 쓰기 종류와 `observe`만 더했다.

## 한 일

- **`tests/unit/test_server_registry.py`에 시험 6개 추가.** 제품 코드는 바꾸지 않았다.
  - **`commit_barrier` fixture:** 실제 SQLiteStore와 Registry를 만든다.
    - writer 연결이 무장한 뒤 첫 `COMMIT`을 실행한 직후 멈춘다. B 시험과 같은 방식으로, `sqlite3.connect`에 연결 클래스를 넘긴다.
    - 그 순간 호출자를 취소하고 writer를 풀어 준다. 호출자는 B6.13 규칙대로 `CancelledError`를 받는다.
  - **제어 쓰기 5종:** `register`, `activate`, `record_scan`, `request_review`, `save_reviewed_descriptions`
    - DB 행이 바뀌었다(커밋됨).
    - 결과를 받지 못해 캐시는 그대로다.
    - 상태는 ACTIVE로 보이지 않는다.
    - `refresh`가 돌려준 사본은 DB와 같고, 상태도 DB와 같다.
  - **`observe`:** 지문이 바뀐 목록을 대조하다 COMMIT 직후 취소했다.
    - DB는 PENDING이고 새 지문이 기록됐다.
    - 바뀐 도구를 알려 주는 결과를 받지 못해 승인 무효화(`invalidate_tool`)는 불리지 않는다. 대신 이번 실행 동안 ACTIVE가 아니다.
    - `refresh` 뒤에도 `activate`는 `REG_SERVER_UNRECORDED`로 거부된다.
    - 다시 시작하면(`load`) DB의 새 지문과 PENDING에서 다시 확인한다.
- **돌연변이 확인**

  | 바꾼 것 | 결과 |
  | --- | --- |
  | `_write`가 결과 불명 표시를 하지 않게 함 | ACTIVE에서 시작한 `record_scan`·`request_review` 2개 실패: DB는 바뀌었는데 ACTIVE로 보임 |
  | `observe`가 기록 실패 표시를 지우게 함 | `observe` 시험 실패 |

  - PENDING에서 시작하는 3종(`register`·`activate`·`save_reviewed_descriptions`)은 캐시가 원래 ACTIVE가 아니어서, 표시가 빠져도 상태로는 드러나지 않는다. 이 경우는 캐시와 DB가 갈린 것과 `refresh`가 맞추는 것을 본다.

## 남는 것

- **시작 전 취소:** `block`으로만 봤다(B 시험). 다른 제어 쓰기도 같은 `_write`를 지난다. `observe`가 시작 전에 취소되면 쓴 것이 없어도 이번 실행 동안 PENDING이다. 보수적인 쪽이고, C4.19의 "기록 실패" 시험과 같은 경로다.
- **설정에서 도구 종류·인자를 바꾸는 경로:** B `record_settings_change` 합의 뒤 `ServerRegistry.apply_settings`(C4.19 남는 것 그대로)

리뷰: B(writer 사용 방식·테스트).
